- Сформулируйте каждое требуемое изменение как отдельный пункт. (стр. 103‑104)  
- Упорядочьте пункты так, как их логически «нарисовать» последовательно (сначала группировка комитетов, затем департаментов, затем поддерживающие единицы, затем назначение руководства). (стр. 103‑104)  
- Оформите рекомендации в виде нумерованного списка, начинающегося словами «Council should take the following actions:». (стр. 103‑104)  
- Если все рекомендации «одновременно» (одинаково важны), используйте структурный порядок. (стр. 103)  
- Пример нумерации: 1‑4 пункта. (стр. 104)  
- Не упорядочивайте пункты по «важности», если все они одинаково важны. (стр. 104)  
- Не используйте чисто хронологический порядок, когда изменения должны произойти одновременно. (стр. 104)  

- При свободной ассоциации ищите повторяющиеся паттерны (стоимость, закон, цены, ROI и т.д.). (стр. 106)  
- Если пункт «обобщает» остальные → исключайте его. (стр. 105)  
- Не оставляйте «общие» пункты без конкретики. (стр. 106)  
- Не допускайте, чтобы разные пункты повторяли один и тот же риск. (стр. 106)  

- При классификационном (degree) порядке определите характеристику, объединяющую элементы (например, «проблема»). (стр. 106‑108)  
- Классификация должна быть MECE (каждый элемент попадает в одну подгруппу, все элементы покрыты). (стр. 108)  
- В одной классификационной группе допускается максимум 5‑6 элементов; больше – теряется ясность. (стр. 117)  
- Не смешивайте процессные, структурные и классовые признаки в одной группе. (стр. 108)  
- Не привязывайте к «драматическому» порядку без логической поддержки. (стр. 108)  
- При желании порядок можно инвертировать (от слабее к сильнее) – стиль‑выбор. (стр. 108)  

- Определите тип пункта (например, «плохой тайминг», «плохие данные», «неудобный формат»). (стр. 108‑110)  
- Сгруппируйте одинаковые типы. (стр. 108‑110)  
- Определите, какой процесс задаёт порядок групп (создание отчёта, чтение, исправление). (стр. 108‑110)  
- Не пропускайте шаг идентификации типа – иначе получаете «список без порядка». (стр. 110)  
- Не принуждайте все пункты вписаться в один тип, создавая искусственные группы. (стр. 110)  

- Проверьте, что группа — MECE. (стр. 112)  
- Определите, является ли группа дедуктивной (вывод из утверждений) или индуктивной (вывод из примеров). (стр. 112‑113)  
- Сформулируйте конкретный итоговый пункт, отражающий смысл всех нижележащих, без «интеллектуально пустых» формулировок. (стр. 113)  
- Не используйте «интеллектуально пустые» утверждения (например, «The company should have three objectives.»). (стр. 113)  

- После названия группы сразу приведите конкретный вывод, а не только количество («Three problems are: …»). (стр. 115)  
- Убедитесь, что вывод происходит из перечисленных деталей. (стр. 115)  
- Не оставляйте только число без определения, какие именно вещи считаются. (стр. 115)  
- Не пишите «three reasons» без указания самих причин. (стр. 115)  

- При формулировании действий опишите каждый как конкретный шаг («You should assign…», «We will create…»). (стр. 115‑119)  
- Сгруппируйте действия по общему воздействию и описывайте конечный продукт в виде измеримого результата (число, дата, физический объект). (стр. 117)  
- В одной под‑группе не более 5‑6 действий, чтобы сохранить визуальную читаемость. (стр. 117)  
- Описывайте эффект конкретно (не «improve profits», а «improve profits by 10 % by 15 Jan»). (стр. 117)  
- Не формулируйте без измеримого результата («A world consciousness must be developed…»). (стр. 118)  
- Не смешивайте вопросы и действия без ясного конечного продукта. (стр. 121)  

- Разделите список на уровни: нижний — конкретные действия, верхний — их эффекты (cause‑effect). (стр. 120)  
- Ограничьте количество пунктов в каждой группе ≤5, чтобы ясно видеть иерархию. (стр. 120‑124)  
- Проверьте, что каждый пункт не пересекается с соседним (MECE) и полностью покрывает нужный эффект. (стр. 124)  
- Не классифицируйте действия как «Task», «Objective», «Benefit» без реального различия в эффектах. (стр. 124)
