## Применение оценки и обратной связи в агентных системах (стр. 315–319)

- **Главная мысль:** Оценка (*Evaluation*) и обратная связь (*Feedback*) — ключевые компоненты агентных систем, определяющие качество работы ИИ. На текущий момент они чаще всего реализуются как внешние модули по отношению к основной системе агента.
- **Как делать:**
  1. **Настройка оценки:** Добавить внешний сервис мониторинга, который анализирует ответы агента после завершения сессии (по метрикам RAG, точности ответа и т. д.).
  2. **Оценка автономных агентов:** Для сложных задач сочетать ручную проверку пользователем с внутренними циклами оценки (как в фреймворках CrewAI и AutoGen).
  3. **Сбор обратной связи:** В чат-интерфейсах фиксировать прямую обратную связь от пользователя и сохранять её в долгосрочную память агента (*Agentic Memory*).
  4. **Работа с исследованиями:** В исследовательских агентах изолировать оценку и обратную связь в самом конце процесса, чтобы избежать бесконечных циклов согласования (*feedback looping*).
- **Правила и числа:**
  - Модель OpenAI Strawberry (o1) уже интегрирует рассуждение (*reasoning*) и планирование (*planning*) непосредственно внутрь LLM (стр. 315, 319).
  - Оценка сервисных ботов и автономных агентов обычно происходит *после* взаимодействия (*After the interaction*) на сервере (стр. 316).
  - В совместных рабочих процессах (*Collaborative workflows*) оценка и обратная связь происходят в реальном времени во время взаимодействия (*During the interaction*) (стр. 316, 318).
- **Шаблоны и примеры:**
  - *Персональный ассистент:* ChatGPT с памятью, принимающий явные указания пользователя.
  - *Исследовательские агенты:* Автономные мультиагентные системы для науки и математики.
- **Ошибки и предупреждения:**
  - Применение мультиагентных систем для оценки и обратной связи во время исследования часто приводит к зацикливанию обратной связи (*feedback looping problem*) и падению качества на текущих моделях (стр. 319).
  - Избыточное рассуждение (*heavy reasoning*) замедляет время отклика ИИ, что вредит динамичным системам (например, ИИ в играх или чатам поддержки) (стр. 315).
- **Где нам пригодится:** Для проектирования систем контроля качества, логирования и памяти наших скриптов и ассистентов.

## Упражнения и резюме главы 11 (стр. 320–322)

- **Главная мысль:** Планирование, рассуждение, оценка и обратная связь — фундамент агентных систем; без них ИИ остается лишь простым чат-ботом.
- **Как делать:**
  1. *Упражнение 1 (Beginner):* Создать простейшего агента-планировщика, разбивающего цель на шаги (например, поиск в Wikipedia и сохранение в файл).
  2. *Упражнение 2 (Intermediate):* Добавить цикл обратной связи после каждого шага для корректировки следующего действия.
  3. *Упражнение 3 (Intermediate):* Сравнить параллельное и последовательное выполнение задач в фреймворке Nexus.
  4. *Упражнение 4 (Advanced):* Написать кастомный планировщик через промпт-инжиниринг и интегрировать его в Nexus.
  5. *Упражнение 5 (Advanced):* Реализовать обработку ошибок в последовательном планировании для восстановления при сбоях API.
- **Правила и числа:**
  - Без планирования агенты сводятся к простым чат-ботам (стр. 321).
  - Ограничение доступных действий агента критично: слишком много инструментов путают модель и ведут к ошибкам (стр. 321).
- **Шаблоны и примеры:**
  - Использование встроенных планировщиков в LangChain, Semantic Kernel, OpenAI Assistants, Claude или платформе Nexus.
- **Ошибки и предупреждения:**
  - Использование параллельного выполнения для задач, где шаги строго зависят от результатов предыдущих, неизбежно ведет к сбоям (стр. 320).
- **Где нам пригодится:** Для практики, написания тестов и отработки навыков создания планировщиков.

## Приложение A: Доступ к языковым моделям OpenAI и Azure OpenAI Studio (стр. 323–328)

- **Главная мысль:** Руководство по получению API-ключей и настройке подключения к моделям семейства GPT-4 напрямую через OpenAI или через Azure OpenAI Studio.
- **Как делать:**
  - **Получение ключа OpenAI API (стр. 323–325):**
    1. Перейти на platform.openai.com, войти или зарегистрироваться, привязать платёжный метод (рекомендуется покупать предоплаченные кредиты).
    2. Выбрать раздел **API**.
    3. В левом меню открыть **API Keys**.
    4. Нажать **Create secret key**, ввести имя (например, `GPT-Agents`) и сгенерировать ключ.
    5. Скопировать ключ и сохранить его в локальный конфигурационный файл `.env`.
  - **Настройка Azure OpenAI Studio (стр. 326–327):**
    1. Войти в Azure Portal.
    2. Создать ресурс **Azure OpenAI** в поддерживаемом регионе.
    3. В Azure OpenAI Studio создать развёртывание (**Deployment**), обернув нужную модель (например, GPT-4).
    4. Получить 3 параметра: `api_key`, `base_url` (endpoint) и `deployment_name`.
- **Правила и числа:**
  - Затраты на выполнение всех практических упражнений книги составляют менее **$100** (стр. 323).
  - Модели GPT-4 являются лучшими в своем классе для разработки агентов (стр. 323).
  - Для подключения к Azure OpenAI требуется 3 обязательных параметра: `api_key`, `base_url`, `deployment_name` (стр. 327).
- **Шаблоны и примеры:**
  - Пример имени ключа: `GPT-Agents`.
  - Хранение ключа в файле окружения `.env`.
- **Ошибки и предупреждения:**
  - Никогда не передавайте API-ключи в публичные репозитории; храните их только на локальной рабочей машине (стр. 325).
  - Не все регионы Azure предоставляют доступ ко всем моделям — проверяйте доступность перед созданием ресурса (стр. 326).
- **Где нам пригодится:** Для настройки подключения наших Python-скриптов и агентов к API OpenAI и Azure.

## Приложение B: Окружение разработки Python (стр. 329–334)

- **Главная мысль:** Пошаговая настройка локального окружения Python 3.10, редактора VS Code, виртуальных окружений `venv` и Docker-контейнеров (*Dev Containers*) для безопасной разработки агентов.
- **Как делать:**
  - **Загрузка исходного кода (стр. 329):**
    1. Установить Git (с git-scm.com).
    2. В терминале выполнить: `git clone https://github.com/cxbxmxcx/GPT-Agents.git`.
  - **Установка Python и VS Code (стр. 330–331):**
    1. Скачать и установить Python 3.10 с python.org. Проверить в терминале: `python --version`.
    2. Скачать и установить VS Code с code.visualstudio.com.
    3. В VS Code открыть панель Extensions и установить плагины: *Python, Python Extension Pack, Python Environment Manager, Python Indent, Flake8, Prompt Flow, Semantic Kernel Tools, Docker, Dev Containers*.
  - **Создание виртуального окружения (стр. 332):**
    1. В VS Code нажать `Ctrl+Shift+P` (или `Cmd+Shift+P`), выбрать `Python: Create Environment`.
    2. Выбрать `Venv`.
    3. Указать установленный интерпретатор Python 3.10.
    4. Выбрать файл `requirements.txt` из папки главы для автоматической установки библиотек.
  - **Использование Dev Containers в Docker (стр. 333):**
    1. Скачать и запустить Docker Desktop.
    2. В VS Code кликнуть на иконку удаленного окна в левом нижнем углу.
    3. Выбрать `Open Folder in Container`.
- **Правила и числа:**
  - Весь код книги протестирован на **Python версии 3.10** (стр. 330, 333).
  - Не рекомендуется устанавливать расширения VS Code с рейтингом ниже **4 звёзд** (стр. 330).
- **Шаблоны и примеры:**
  - Команда клонирования: `git clone https://github.com/cxbxmxcx/GPT-Agents.git`.
  - Автоустановка зависимостей через `requirements.txt`.
- **Ошибки и предупреждения:**
  - Агенты, способные генерировать и запускать код, настоятельно рекомендуется запускать в изолированных Docker-контейнерах, чтобы избежать повреждения или заражения основной операционной системы (стр. 333).
- **Где нам пригодится:** Базовая инструкция по быстрой и безопасной настройке нашей среды разработки и контейнеров.

## Дополнительные материалы: Различия между итеративным и спланированным выполнением (стр. 342–346)

*(Примечание: Страницы 342–344 и 346 содержат рекламу книг Manning и обложку; на странице 345 представлена ключевая схема планирования).*

- **Главная мысль:** Разница между дефолтным итеративным поведением обычных LLM (требующих подтверждения каждого шага от пользователя) и спланированным последовательным выполнением задач автономными агентами (GPT Assistants, Claude).
- **Как делать:**
  - **Итеративное выполнение (стандарт для обычных LLM, стр. 345):**
    1. Пользователь отправляет запрос/цель.
    2. Модель делает первый шаг (например, `search_wikipedia`), выводит результат и останавливается, спрашивая разрешение продолжить.
    3. Пользователь отвечает «continue».
    4. Модель делает второй шаг (`get_wikipedia_page`) и снова ждет.
    5. Пользователь отвечает «continue» -> модель выполняет `save_file`.
  - **Спланированное/Последовательное выполнение (стандарт для агентов, стр. 345):**
    1. Пользователь отправляет единый промпт с целью.
    2. Агент внутри себя формирует план задач.
    3. Агент автоматически по очереди вызывает все функции (`search_wikipedia` -> `get_wikipedia_page` -> `save_file`) и собирает данные.
    4. Агент отдаёт пользователю готовый итоговый результат без промежуточных остановок.
- **Правила и числа:**
  - Итеративное выполнение — стандартное поведение по умолчанию для обычной LLM (стр. 345).
  - Последовательное (плановое) выполнение — стандарт для GPT Assistants и Claude (стр. 345).
- **Шаблоны и примеры:**
  - Пример цели: *"search Wikipedia for topic, return the top page, and save to a file"*.
  - Набор внутренних функций агента: `search_wikipedia(topic)`, `get_wikipedia_page(page_id)`, `save_file`.
- **Ошибки и предупреждения:**
  - Использование обычных чат-ботов без слоя планировщика вынуждает пользователя постоянно ручками подтверждать каждый промежуточный шаг скрипта.
- **Где нам пригодится:** Для понимания архитектуры автономных ИИ-ассистентов и написания скриптов, работающих без вмешательства человека.
