## 5.6 Thinking semantically when writing semantic services (стр. 149–151)
- **Главная мысль:** Чтобы языковая модель (LLM) могла самостоятельно фильтровать, сортировать и обрабатывать данные, плагины должны возвращать как можно больше информации (например, в формате JSON), а не просто обрезанные списки заголовков.
- **Как делать (обновление сервиса до версии 2):**
  1. Откройте файл `tmdb_v2.py` и найдите функцию `get_top_movies_by_genre` (стр. 150).
  2. Измените функцию так, чтобы она возвращала отфильтрованные фильмы в виде JSON-строки через `json.dumps(filtered_movies)` (стр. 150).
  3. В файле `SK_service_chat.py` закомментируйте импорт первой версии и раскомментируйте импорт `tmdb_v2` (стр. 150).
- **Правила и числа:** Версия 2 сервиса TMDb возвращает полные JSON-документы в одной строке, что позволяет LLM применять дополнительные текстовые фильтры (например, «только фильмы про космос») уже после вызова функции (стр. 150–151).
- **Шаблоны и примеры:**
  - *Запрос пользователя:* `get a list of currently playing movies for the action genre and only return movies about space` (стр. 150).
  - *Результат:* LLM вызывает сервис, получает полный JSON, самостоятельно анализирует поле `overview` каждого фильма и находит подходящий (например, «Rebel Moon») (стр. 150).
- **Ошибки и предупреждения:** Возврат только названий (строк) сильно ограничивает возможности LLM по самостоятельной обработке результатов (стр. 149).
- **Где нам пригодится:** *Для запросов и проверки структуры данных, возвращаемых нашими скриптами в формате JSON.*

## 6.1 Introducing behavior trees (стр. 153–160)
- **Главная мысль:** Деревья поведения (Behavior Trees, BT) — проверенный паттерн управления роботами и ИИ в играх (предложен Родни Бруксом в 1986 г.), который отлично подходит для контроля агентов на уровне задач и планов.
- **Правила и числа:**
  - Узлы BT возвращают либо **Успех (`SUCCESS`)**, либо **Неуспех (`FAILURE`)**, а не булевы `True/False` (стр. 151).
  - Обход дерева идет **сверху вниз и слева направо** (стр. 154).
  - Основные типы узлов (Таблица 6.1, стр. 154–155):
    - *Selector (Fallback / Выбор)*: выполняет детей по очереди, возвращает `SUCCESS` на первом успешном ребре. Если все упали — возвращает `FAILURE`.
    - *Sequence (Последовательность)*: выполняет детей по порядку. Если хоть один упал — вся последовательность падает (`FAILURE`). Если все успешны — `SUCCESS`.
    - *Condition (Условие)*: возвращает `SUCCESS` или `FAILURE` в зависимости от проверки.
    - *Action (Действие)*: выполняет задачу, возвращает статус выполнения.
    - *Decorator (Декоратор)*: управляет выполнением дочернего узла (может работать как функция барьерного контроля — Control Barrier Function).
    - *Parallel (Параллельный)*: выполняет все узлы параллельно.
- **Шаблоны и примеры:**
  - Пример кода на Python с использованием библиотеки `py_trees` находится в файле `first_btree.py` (стр. 159). Узел запрашивается методом `behavior_tree.tick()` в цикле (стр. 159).
- **Ошибки и предупреждения:** Конечные автоматы (FSM) и простые правила (if-then) громоздки и не масштабируются для сложных систем агентов; деревья поведения решают эту проблему за счет модульности (стр. 157–158).
- **Где нам пригодится:** *Для логики работы наших скриптов и координации нескольких агентов.*

- **Как делать (установка и запуск):**
  1. Клонируйте репозиторий: `git clone https://github.com/cxbxmxcx/GPTAssistantsPlayground` (стр. 160).
  2. Установите зависимости: `pip install -r requirements.txt` (стр. 160).
  3. Задайте ключ: `export OPENAI_API_KEY="your-api-key"` (стр. 160).
  4. Запустите приложение: `python main.py` и откройте `http://127.0.0.1:7860` (стр. 160).
- **Правила и числа:**
  - Кастомные действия добавляются через помещение файлов в папку `playground/assistant_actions/` с использованием декоратора `@agent_action` (стр. 139, 140).
  - Установка базы данных ассистентов (`assistants.db`) делается через специальный `Manager Assistant` с помощью действия `create_manager_assistant` (стр. 144).
- **Ошибки и предупреждения:** В отличие от встроенного Code Interpreter (который стоит $0.03 за запуск и изолирован), локальный запуск кода через `run_code` в песочнице выполняет скрипты на вашей машине (будьте аккуратны с операционной системой) (стр. 138, 141).
- **Где нам пригодится:** *Для тестирования ассистентов, написания кастомных скриптов-действий и отладки через логи.*

## 6.3 Introducing agentic behavior trees (стр. 167–174)
- **Главная мысль:** Деревья поведения агентов (Agentic Behavior Trees, ABT) объединяют классические деревья поведения с LLM-ассистентами, используя промпты для оценки условий и выполнения действий через потоки сообщений (threads).
- **Как делать (Запуск ABT для кодинг-челленджа):**
  1. Установите через Playground необходимых ассистентов: *Python Coding Assistant* («Hacker»), *Coding Challenge Judge* («Judge») (стр. 144, 147).
  2. Запустите скрипт `agentic_btree_coding_challenge.py` (стр. 148–149).
  3. Дерево последовательно выполняет шаги: Hacker пишет решение в `solution.py` -> Judge тестирует и сохраняет в `judged_solution.py` -> Verifier проверяет на отдельном треде и возвращает `SUCCESS` или `FAILURE` (стр. 147–149).
- **Правила и числа:**
  - Ассистенты общаются через *threads* (потоки сообщений, похожие на каналы в Slack). Общий трэд позволяет агентам видеть историю обсуждения, а отдельный трэд изолирует верификатора от «шума» (стр. 147).
  - Задержка (`time.sleep(20)`) в цикле `tick()` используется для троттлинга запросов к LLM (стр. 149).
- **Шаблоны и примеры:**
  - *Пример задачи (Edabit):* Симуляция роста травы в матрице с препятствиями (скалами `x`) и землей (`o`) (стр. 145–146).
  - *Пример ABT для соцсетей (стр. 174):* Поиск видео на YouTube -> скачивание транскриптов -> суммаризация -> выбор видео -> написание поста для X (Twitter) (менее 280 символов) -> постинг в X (каждый шаг на новом треде).
- **Где нам пригодится:** *Для построения автономных многоагентных конвейеров (workflows) с проверкой результатов через код.*
