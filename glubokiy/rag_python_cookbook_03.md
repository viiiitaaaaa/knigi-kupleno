## 3.5 Loading Audio Files via Speech‑to‑Text Models (стр. 73‑74)  
- **Главная мысль** – Чтобы добавить аудио‑контент в RAG‑систему, нужно превратить звук в текст. Самый простой путь – воспользоваться OpenAI Whisper (как API, так и локально).  
- **Как делать**  
  1. Установить OpenAI SDK и импортировать `OpenAI`.  
  2. Открыть аудиофайл в бинарном режиме.  
  3. Вызвать `client.audio.transcriptions.create(model="whisper-1", file=audio_file)`.  
  4. Сохранить полученную транскрипцию.  
- **Правила и числа**  
  - Whisper API – быстрый старт, поддержка 80+ языков, без собственного инфраструктурного управления (стр. 73).  
  - Whisper локально – полный контроль над данными, экономия при больших объёмах (стр. 74).  
  - GPT‑4o – точнее Whisper, лучше пунктуация и работа с техническими терминами, но дороже за минуту (стр. 74).  
- **Шаблоны и примеры**  

```python
from openai import OpenAI
client = OpenAI()
with open("../datasets/audio_files/harvard.wav", "rb") as f:
    transcription = client.audio.transcriptions.create(
        model="whisper-1", file=f
    )
```  

- **Ошибки и предупреждения** – Выбирайте Whisper API только если политика конфиденциальности позволяет отправлять аудио наружу; иначе используйте локальный Whisper.  
- **Где нам пригодится** – загрузка подкастов, интервью или любой голосовой контент для построения векторного хранилища.  



## 3.6 Extracting Text from Images and PDFs via Tesseract OCR (стр. 75‑78)  
- **Главная мысль** – Tesseract (open‑source OCR) позволяет извлекать текст из изображений и сканированных PDF, полностью контролируя процесс на своей инфраструктуре.  
- **Как делать**  
  1. Установить Tesseract (system‑install) и Python‑пакеты `pdf2image`, `pytesseract`, `Pillow`.  
  2. Для отдельного изображения: загрузить через Pillow → `pytesseract.image_to_string(image)`.  
  3. Для сканированного PDF: `convert_from_path(pdf_path)` → список изображений → OCR для каждого изображения, собрать список строк.  
  4. Сохранять метаданные (исходный PDF‑путь, путь к изображению, номер страницы, timestamps).  
- **Правила и числа**  
  - `pdf2image` требует Poppler (устанавливается отдельно).  
  - Точность Tesseract падает на сложных макетах, таблицах, рукописных фрагментах (стр. 77).  
- **Шаблоны и примеры**  

```python
from pdf2image import convert_from_path
import pytesseract, os
images = convert_from_path("../datasets/pdf_files/file.pdf")
texts = [pytesseract.image_to_string(img) for img in images]
```  

- **Ошибки и предупреждения** – Не использовать Tesseract для документов с таблицами/диаграммами, если нужны точные структуры – лучше гибридный подход (OCR + мультимодальные модели).  
- **Где нам пригодится** – быстрый и бесплатный парсинг контрактов, форм, отсканированных книг, когда конфиденциальность важна.  



## 3.7 Extracting Text from Images via Multimodal Models (стр. 79‑81)  
- **Главная мысль** – Мультимодальные LLM (например, GPT‑5.2) могут сразу извлекать текст из изображения, сохраняя оригинальное форматирование (заголовки, списки, таблицы, код).  
- **Как делать**  
  1. Прочитать изображение, закодировать в base64.  
  2. Сформировать промпт «Extract the text…».  
  3. В запросе к `client.chat.completions.create` указать `model="gpt-5.2"` и `content` – текстовый промпт + `image_url` с data‑uri.  
  4. Получить `response.choices[0].message.content` – текст с сохранённой разметкой.  
- **Правила и числа**  
  - Максимальное число токенов – `max_tokens=500` (стр. 80).  
- **Шаблоны и примеры**  

```python
with open(png_path, "rb") as f:
    img_b64 = base64.b64encode(f.read()).decode()
prompt = "Extract the text from the image attached..."
response = client.chat.completions.create(
    model="gpt-5.2",
    messages=[{"role":"user","content":[
        {"type":"text","text":prompt},
        {"type":"image_url","image_url":{"url":f"data:image/jpeg;base64,{img_b64}"}}]}],
    max_tokens=500,
)
content = response.choices[0].message.content
```  

- **Ошибки и предупреждения** – Модели могут «галлюцинировать» цифры в низкокачественных сканах; уточняйте инструкцию, если нужен точный вывод.  
- **Где нам пригодится** – быстрый импорт слайдов, скриншотов UI, графиков, где важна сохранённая структуру.  



## 3.8 Generating Text Description for Images via Multimodal Models (стр. 82‑84)

  2. Промпт : «You are an assistant for visually impaired users. Describe the image in detail.»

  4. Сохранить полученный текст вместе с путём к файлу, номером страницы и ссылкой на окружающий текст.  
- **Правила и числа** – `max_tokens=150` достаточно для короткого описания (стр. 83).

```python
prompt = "You are an assistant for visually impaired users. Describe the image in detail."
response = client.chat.completions.create(

description = response.choices[0].message.content
```  

- **Ошибки и предупреждения** – Описание может упустить детали, если изображение сильно перегружено; при критичных задачах рекомендуется проверять несколько моделей.  
- **Где нам пригодится** – генерация alt‑текста, каталогов изображений, подготовка данных для кросс‑модального поиска.  



## 3.9 Generating Text Summaries for Embedded Tables via Multimodal Models (стр. 84‑87)  
- **Главная мысль** – Вместо сохранения «сырой» таблицы в векторе, лучше получить лаконичное текстовое резюме, которое передаёт смысл (тенденции, рост и т.д.).  
- **Как делать**  
  1. С помощью `unstructured.partition.pdf` разбить PDF на элементы; собрать все таблицы в список.  
  2. Превратить каждую таблицу в строку и поместить в `pandas.DataFrame`.  
  3. Для каждой строки вызвать LLM (OpenAI) с промптом: «Summarize the table…».  
  4. Сохранить полученные резюме вместе с метаданными (путь к PDF, номер страницы).  
- **Правила и числа** – `temperature=0.7`, `max_tokens=150` (стр. 86).  
- **Шаблоны и примеры**  

```python
def summarize_tables(row):
    prompt = f"You are an assistant tasked with summarizing tables. Table chunk: {row.table}"
    resp = client.chat.completions.create(
        model="gpt-5-mini",
        messages=[{"role":"user","content":prompt}],
        temperature=0.7,
        max_tokens=150,
    )
    row["table_summary"] = resp.choices[0].message.content
    return row
tables_df = pd.DataFrame(tables, columns=["table"])
tables_df = tables_df.apply(summarize_tables, axis=1)
```  

- **Ошибки и предупреждения** – Не использовать для чисто справочных таблиц (списки товаров, каталоги), где нужен точный поиск по ячейкам.  
- **Где нам пригодится** – финансовые отчёты, KPI‑таблицы, любые данные, где важнее тренд/инсайт, а не отдельные цифры.

## 4.0 Data Preparation – Общие сведения (стр. 97‑98)  
- **Главная мысль** – При построении RAG‑системы длинный текст разбивается на независимые смысловые куски (chunks), каждому сопоставляется вектор‑эмбеддинг; метаданные помогают фильтрации и ускоряют поиск.  
- **Как делать** – Ключевые этапы: очистка текста → сбор метаданных → разбиение (character, recursive, semantic, agentic) → векторизация.  



## 4.1 Adding Metadata to Enable Metadata Filtering (стр. 99‑103)  
- **Главная мысль** – Хранение метаданных (автор, дата, путь, размер, количество страниц, длина текста) рядом с эмбеддингами позволяет ограничивать поиск по атрибутам, повышая точность.  
- **Как делать**  
  1. Открыть PDF через `PyPDF2.PdfReader`, вытянуть встроенную мета‑информацию (`reader.metadata`).  
  2. Скопировать её в словарь, добавить вычисляемые поля: `page_count`, `file_size`, `file_name`, `file_path`, `text_length`.  
  3. (Опционально) Сформировать Pydantic‑модель для требуемых LLM‑полей (например, контакты авторов).  
  4. Сформировать системный запрос, отправить вместе с полным текстом в OpenAI `beta.chat.completions.parse` с `response_format`.  
  5. Добавить полученные LLM‑полученные поля (например, `author_contacts`) в итоговый словарь метаданных.  
- **Правила и числа** – Ожидается несколько минут и $1‑$5 на 1 000 документов при генерации LLM‑метаданных (стр. 103).  
- **Шаблоны и примеры**  

```python
metadata_ext = dict(metadata)
metadata_ext["page_count"] = len(reader.pages)
metadata_ext["file_size"] = os.path.getsize(file_path)
# LLM‑генерация:
class AuthorContact(BaseModel): ...
response = client.beta.chat.completions.parse(
    model="gpt-5-mini",
    messages=[{"role":"system","content":"Extract the contact information of all authors."},
              {"role":"user","content":text}],
    response_format=Contacts,
)
metadata_ext["author_contacts"] = response.choices[0].message.parsed
```  

- **Ошибки и предупреждения** – Если PDF не содержит нужных полей, LLM‑разбор может вернуть пустой результат; проверяйте наличие данных перед запросом.  
- **Где нам пригодится** – фильтрация по году, автору, отделу (HR / engineering / finance) перед семантическим поиском.  



## 4.2 Enhancing Data Quality by Replacing Abbreviations and Technical Terms (стр. 104‑108)  
- **Главная мысль** – Расширение сокращений и пояснение технических терминов делает каждый кусок текста самодостаточным и улучшает семантические эмбеддинги.  
- **Как делать**  
  1. С помощью `re.sub` заменить известные аббревиатуры (словарь `abbreviations_dict`) на «полная форма (аббр.)».  
  2. При необходимости отправить текст в LLM с инструкцией «заменить все аббревиатуры на полные формы и дать короткое пояснение», получив `enhanced_text`.  
- **Правила и числа** – Примерный словарь: `NLP → Natural Language Processing`, `RNN → Recurrent Neural Network` и т.д. (стр. 104).  
- **Шаблоны и примеры**  

```python
abbreviations_dict = {"NLP":"Natural Language Processing", ...}
for abbr, full in abbreviations_dict.items():
    text = re.sub(rf"\b{abbr}\b", f"{full} ({abbr})", text)
# LLM‑расширение:
prompt = f"""... replace abbreviations ... Text: {text}"""
response = client.chat.completions.create(
    model="gpt-5.2", messages=[{"role":"user","content":prompt}]
)
enhanced_text = response.choices[0].message.content
```  

- **Ошибки и предупреждения** – Не применять, если аббревиатура является общепринятым названием (например, `HTTP`) – может ухудшить читаемость.  
- **Где нам пригодится** – финансовые отчёты, медицинские документы, юридические тексты, где часто встречаются сокращения.  



## 4.3 Improving Search Accuracy by Creating Hypothetical Questions for Text Chunks (стр. 109‑112)  
- **Главная мысль** – Генерируя «гипотетические вопросы» к каждому текстовому куску и индексируя их, мы приближаем запрос пользователя к формулировке, на которую обучена модель, тем самым улучшая реквалидацию.  
- **Как делать**  
  1. Разбить документ на куски (обычное разбиение).  
  2. Для каждого куска вызвать LLM с инструкцией «создай 5 гипотетических вопросов, которые можно ответить из этого куска».  
  3. Сохранить полученные вопросы и их эмбеддинги в базе.  
  4. При запросе сравнивать вектор запроса с векторами вопросов, а затем подгружать оригинальный кусок к LLM‑генерации ответа.  
- **Шаблоны и примеры**  

```python
prompt = f"""Below you can find a chat history... Generate 5 hypothetical questions... {text}"""
result = client.beta.chat.completions.parse(
    model="gpt-5-mini",
    messages=[{"role":"user","content":prompt}],
    response_format=HypotheticalQuestions,
)
questions = result.choices[0].message.parsed.questions
```  

- **Ошибки и предупреждения** – Не использовать, если документы уже в виде вопросов‑ответов (FAQ) или если время индексации критично (добавляются лишние LLM‑вызовы).  
- **Где нам пригодится** – техническая документация, логи, чат‑истории, таблицы, где пользователи задают естественные вопросы.  



## 4.4 Splitting Documents via Character Splitting (стр. 113‑115)  
- **Главная мысль** – Простейший способ разбиения: фиксированный размер окна (символов/токенов) с возможным перекрытием; подходит для «сырого» текста без структуры.  
- **Как делать**  
  1. Задать `chunk_size` (например, 100) и `overlap` (например, 20).  
  2. Итеративно сдвигать окно: `step = max(1, chunk_size - overlap)`.  
  3. Собирать куски в список.  
- **Правила и числа** – Перекрытие = 20 символов улучшает контекст, но увеличивает объём хранилища (стр. 115).  
- **Шаблоны и примеры**  

```python
def split_by_characters(text, chunk_size, overlap):
    chunks = []
    step = max(1, chunk_size - overlap)
    for start in range(0, len(text), step):
        chunks.append(text[start:start+chunk_size])
    return chunks
chunks = split_by_characters(text, 100, 20)
```  

- **Ошибки и предупреждения** – Не использовать для документов с четкой структурой (заголовки, абзацы) – может разорвать смысл.  
- **Где нам пригодится** – быстрый прототип, распознавание речи, лог‑файлы без разметки.

- **Как делать** – (в тексте описано лишь принцип, конкретный код не приведён).  
- **Где нам пригодится** – документы с ярко выраженной иерархией (главы, секции, списки), где важна сохранённость смысловых блоков.
