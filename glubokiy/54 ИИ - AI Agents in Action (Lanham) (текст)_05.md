## Глава 4 (Окончание) / Начало Части 5 (стр. 120–122)
- **Главная мысль:** Раздел завершает обзор многоагентных систем (AutoGen, CrewAI, AgentOps) и открывает главу 5, посвящённую тому, как агенты совершают действия во внешнем мире с помощью функций, плагинов и фреймворка Semantic Kernel.
- **Правила и числа:**
  - На момент написания книги вызов функций (function calling) **не поддерживался** в открытых (open-source) языковых моделях (стр. 126).
- **Шаблоны и примеры:**
  - Введение концепции плагинов как прокси для действий (скрейпинг сайтов, вызов API) (стр. 123).
- **Ошибки и предупреждения:**
  - Терминология в разных фреймворках отличается (например, Semantic Kernel изначально называл модули «skills», а затем переименовал в «plugins», хотя в коде старые названия остались) (стр. 131–132).
- **Где нам пригодится:** для памяти (базовые определения действий и плагинов).

## 5.1 Defining agent actions (Определение действий агента) (стр. 123–124)
- **Главная мысль:** Плагины и инструменты расширяют возможности LLM (больших языковых моделей), позволяя им выполнять внешние задачи через структурированные параметры и вызовы API.
- **Шаблоны и примеры:**
  - Схема работы плагина (рис. 5.1, стр. 123): пользователь запрашивает фильм $\to$ LLM распознает плагин и извлекает параметры $\to$ плагин собирает данные (например, парсит сайт) $\to$ LLM формирует финальный ответ.
- **Ошибки и предупреждения:**
  - Не путайте само действие (функцию) и агента: агент выступает потребителем и координатором инструментов.
- **Где нам пригодится:** для проектирования архитектуры запросов и промптов (стратегия Use External Tools).

## 5.2 Executing OpenAI functions (Выполнение функций OpenAI) (стр. 125–130)
- **Главная мысль:** OpenAI предоставляет спецификацию инструментов (`tools`), с помощью которой LLM анализирует запрос пользователя, выбирает нужную функцию и возвращает её имя вместе с распарсенными параметрами (но сама функция на стороне модели **не исполняется**).
- **Как делать (вызов и обработка функций):**
  1. Сделать API-запрос к LLM, передав описание функций в параметре `tools` (стр. 125, листинг 5.1).
  2. Получить от модели ответ, содержащий имя функции и аргументы в формате JSON (стр. 127).
  3. Проверить программно, вернула ли модель вызовы инструментов (`tool_calls`) (стр. 130).
  4. Найти соответствующую локальную функцию в коде, передать ей аргументы и выполнить её (стр. 130).
  5. Добавить результат выполнения функции обратно в историю сообщений (`messages` с ролью `tool`) и сделать повторный запрос к LLM для перевода результата в естественный язык (стр. 130, рис. 5.4).
- **Правила и числа:**
  - Для задач делегирования функций можно использовать более простые, дешёвые и быстрые модели, например `gpt-3.5-turbo-1106` (стр. 129).
- **Шаблоны и примеры:**
  - Файлы в репозитории: `chapter_4/first_function.py` и `chapter_4/parallel_functions.py` (стр. 126, 127).
- **Ошибки и предупреждения:**
  - **Критически важно:** Сама LLM функцию *не выполняет*. Она лишь возвращает структурированный запрос (название функции и аргументы), который ваш код должен перехватить, запустить и отправить ответ обратно в модель.
- **Где нам пригодится:** для написания своих скриптов интеграции function calling с OpenAI API.

## 5.3 Introducing Semantic Kernel (Введение в Semantic Kernel) (стр. 131–134)
- **Главная мысль:** Semantic Kernel (SK) — это открытый проект от Microsoft для создания ИИ-приложений и агентов, который выступает оркестратором плагинов, навыков (skills), памяти и средств планирования.
- **Как делать (установка и подключение SK):**
  1. Удалить старые версии и клонировать репозиторий SK: `pip uninstall semantic-kernel`, `git clone https://github.com/microsoft/semantic-kernel.git` (стр. 132, листинг 5.8).
  2. Установить в режиме разработки: `cd semantic-kernel/python`, `pip install -e .` (стр. 132).
  3. Инициализировать ядро (`kernel = sk.Kernel()`) и добавить сервис завершения чата (OpenAI или Azure OpenAI) с ключами из `.env` (стр. 132, листинг 5.9).
- **Правила и числа:**
  - Поддерживается в Python, Java и C# (плагины, написанные на одном языке, нельзя напрямую использовать в другом, но сами языки поддерживаются) (стр. 132).
- **Шаблоны и примеры:**
  - Использование переменных контекста в шаблонах промптов (`SK_context_variables.py`): плейсхолдеры вроде `{{$format}}`, `{{$subject}}`, `{{$genre}}` (стр. 134, листинг 5.10).
- **Ошибки и предупреждения:**
  - Функция `kernel.invoke_prompt` может потребовать адекватной настройки асинхронности (`asyncio.run`) (стр. 133).
- **Где нам пригодится:** для создания структуры агентов на базе Python и Semantic Kernel.

## 5.4 Synergizing semantic and native functions (Синергия семантических и нативных функций) (стр. 135–142)
- **Главная мысль:** В Semantic Kernel можно объединять *семантические функции* (промпты к LLM) и *нативные функции* (обычный код на Python, например, для чтения файлов или запросов к БД), регистрируя их как плагины.
- **Как делать (создание и регистрация нативных функций):**
  1. Описать нативный код внутри класса (например, класс `MySeenMoviesDatabase`) (стр. 139, листинг 5.14).
  2. Использовать декоратор `@kernel_function(description="...", name="...")` для каждого метода, чтобы сделать его доступным для ядра (стр. 139).
  3. Импортировать объект в ядро через `kernel.import_plugin_from_object(MySeenMoviesDatabase(), "SeenMoviesPlugin")` (стр. 140, листинг 5.15).
  4. Внедрять нативные функции прямо в текст семантического промпта по имени класса и метода: `{{MySeenMoviesDatabase.LoadSeenMovies}}` (стр. 141, листинг 5.16).
- **Шаблоны и примеры:**
  - Структура файлов плагина: папка плагина $\to$ папка функции $\to$ `config.json` (тип `completion` для семантических функций) и `skprompt.txt` (текст промпта) (стр. 137, рис. 5.7).
- **Ошибки и предупреждения:**
  - Простое создание функции через код не регистрирует её в ядре автоматически; для использования в шаблонах нативная функция должна быть явно импортирована через `import_plugin` (стр. 142).
- **Где нам пригодится:** для написания собственных скриптов-помощников, где код на Python совмещается с вызовами LLM.

## 5.5 Semantic Kernel as an interactive service agent (Semantic Kernel как интерактивный сервисный агент) (стр. 142–148)
- **Главная мысль:** С помощью Semantic Kernel можно обернуть любой внешний API (например, базу данных фильмов TMDB) в набор семантически описанных нативных функций (GPT-интерфейс) и встроить их в интерактивный чат-агент.
- **Как делать (создание сервисного агента и чата):**
  1. Получить API ключ стороннего сервиса (например, TMDB — The Movie Database) (стр. 142).
  2. Создать класс (`TMDbService`), методы которого делают запросы к API, и задекорировать их `@kernel_function` с понятным описанием для LLM (стр. 144, листинг 5.18, 5.19).
  3. Импортировать этот класс в ядро как плагин (стр. 145, листинг 5.20).
  4. Настроить параметры выполнения чата (`OpenAIChatPromptExecutionSettings`), исключив служебный чат-бот из списка доступных инструментов через `tool_choice="auto"` (стр. 147, листинг 5.21).
  5. Организовать цикл ввода-вывода (`chat()`) с сохранением истории сообщений (`ChatHistory`), обрабатывая вызовы инструментов на лету (стр. 147–148, листинги 5.22, 5.23).
- **Правила и числа:**
  - Настройки генерации в примере: `max_tokens=2000`, `temperature=0.7`, `top_p=0.8` (стр. 147).
  - Код успешного ответа HTTP API для проверки: `response.status_code == 200` (стр. 144).
- **Шаблоны и примеры:**
  - Архитектура слоев (рис. 5.8, стр. 142): Пользователь $\to$ Веб/Чат/Агент $\to$ Semantic Kernel (как плагин) $\to$ Семантический слой (маппинг функций) $\to$ Внешний API.
- **Ошибки и предупреждения:**
  - Не забудьте исключить сам чат-бот из списка инструментов (`tools`), иначе модель попытается вызвать функцию чата рекурсивно (стр. 147).
- **Где нам пригодится:** для создания локального ИИ-помощника, подключенного к вашим собственным базам данных и скриптам через Semantic Kernel.
