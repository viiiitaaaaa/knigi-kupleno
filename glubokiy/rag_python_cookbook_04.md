## 4.5 Рекурсивное разбиение текста (стр. 116‑119)  
- **Главная мысль** – Делить текст на фрагменты, соблюдая естественные границы (параграфы, переносы строк, пунктуацию, пробелы), чтобы каждый кусок сохранял смысл.  
- **Как делать**  
  1. Установить зависимости: `pip install PyPDF2 langchain-text-splitters`.  
  2. Считать PDF‑файл через `PyPDF2.PdfReader` и собрать весь текст.  
  3. Создать splitter:  

     ```python
     from langchain_text_splitters import RecursiveCharacterTextSplitter
     text_splitter = RecursiveCharacterTextSplitter(
         chunk_size=200,          # (стр. 116)
         chunk_overlap=0,
         length_function=len,
         is_separator_regex=False,
     )
     ```  
  4. Получить список фрагментов: `chunks = text_splitter.split_text(text)`.  
- **Правила и числа** – Приоритетные разделители: параграф → одиночный перенос строки → пунктуация → пробел. Параметры из примера: `chunk_size=200`, `chunk_overlap=0`.  
- **Шаблоны и примеры** – Список `chunks` – массив строк, каждая ≤ 200 симв. (рис. 4‑14).  
- **Ошибки и предупреждения** –  
  * Не рекомендуется использовать для разметки (Markdown, LaTeX, HTML) – см. ниже.  
  * Добавление перекрытия улучшает контекст, но увеличивает объём хранения и может вызвать избыточный поиск.  
- **Где нам пригодится** – При работе с документами, где есть чёткая параграфная структура (статьи, отчёты, книги) и формат документа заранее неизвестен.

## 4.6 Разбиение с учётом разметки (стр. 119‑122)  
- **Главная мысль** – Использовать синтаксис конкретного формата (Markdown, Python, LaTeX) для деления текста на семантические блоки и сохранения метаданных о заголовках/структуре.  
- **Как делать**  
  1. Установить пакет: `pip install langchain-text-splitters`.  
  2. Импортировать нужные сплиттеры:  

     ```python
     from langchain_text_splitters import (
         PythonCodeTextSplitter,
         LatexTextSplitter,
         MarkdownHeaderTextSplitter,
     )
     ```  
  3. Определить тип файла (`os.path.splitext`).  
  4. Выбрать соответствующий сплиттер:  

     ```python
     if ext == ".py":
         splitter = PythonCodeTextSplitter(chunk_size=500, chunk_overlap=50)
     elif ext == ".tex":
         splitter = LatexTextSplitter(chunk_size=500, chunk_overlap=50)
     elif ext == ".md":
         headers = [("#", "Header 1"), ("##", "Header 2"), ("###", "Header 3")]
         splitter = MarkdownHeaderTextSplitter(headers)
     ```  
  5. Разбить текст: `chunks = splitter.split_text(file_text)`.  
- **Правила и числа** – Для кода: `chunk_size=500`, `chunk_overlap=50`. Для Markdown задаются кортежи `("<знак>", "<имя‑уровня>")`.  
- **Шаблоны и примеры** – Каждый объект‑фрагмент содержит поля `header_1`, `header_2`, `header_3` и `page_content` (рис. 4‑17).  
- **Ошибки и предупреждения** –  
  * Не использовать для обычного текста без разметки (применять рекурсивное).  
  * Не подходит для PDF/Word после конвертации в plain‑text (потеря синтаксиса).  
  * Сложно применять к смешанным форматам, где нужен несколько сплиттеров.  
- **Где нам пригодится** – При обработке репозиториев кода, README‑ов, статей в Markdown, HTML‑страниц, LaTeX‑документов и вообще любого markup‑контента.

## 4.7 Семантико‑ориентированное разбиение (стр. 122‑124)  
- **Главная мысль** – Делить несструктурированный текст (транскрипты, чаты) в местах, где меняется смысл, используя эмбеддинги и измерение семантического сходства.  
- **Как делать**  
  1. Установить экспериментальный пакет: `pip install langchain-experimental langchain-openai`.  
  2. Загрузить «сырой» текст без заголовков/параграфов.  
  3. Создать `SemanticChunker`:  

     ```python
     from langchain_experimental.text_splitter import SemanticChunker
     from langchain_openai.embeddings import OpenAIEmbeddings
     
     text_splitter = SemanticChunker(
         OpenAIEmbeddings(),
         breakpoint_threshold_type="percentile",   # (стр. 123)
         breakpoint_threshold_amount=90,           # (стр. 123)
     )
     chunks = text_splitter.split_text(text)
     ```  
- **Правила и числа** – Порог разрыва задаётся перцентилем: `breakpoint_threshold_type="percentile"`, `breakpoint_threshold_amount=90`.  
- **Шаблоны и примеры** – На рис. 4‑19 показаны получившиеся фрагменты (пример не текстовый).  
- **Ошибки и предупреждения** –  
  * Требует два прохода эмбеддингов (во время разбиения + при загрузке в векторную БД).  
  * Стоимость: $0.02 / 1 M токен → может стать значительной при больших объёмах.  
  * В реальном продакшене лучше реализовать собственный чункер, основанный на исходном коде LangChain, чтобы избежать нестабильных экспериментальных API.  
- **Где нам пригодится** – Для транскрипций аудио, журналов чатов, склеенных текстов, где тема меняется без визуальных разделителей.

## 4.8 Агентное (LLM‑основанное) разбиение (стр. 126‑129)  
- **Главная мысль** – Превратить любой текст в набор **пропозиций** – самостоятельных, полностью контекстно‑независимых утверждений, используя большую языковую модель (LLM).  
- **Как делать**  
  1. Установить зависимости: `pip install langchain langchain-openai pydantic`.  
  2. Подготовить шаблон‑prompt (полный шаблон доступен в LangChain Hub; в конспекте – сокращённый вариант).  
  3. Создать LLM с структурированным выводом:  

     ```python
     from langchain import hub
     from langchain_openai import ChatOpenAI
     from pydantic import BaseModel
     from typing import List
     
     obj = hub.pull("wfh/proposal-indexing")     # шаблон
     llm = ChatOpenAI(model="gpt-5.2")           # (стр. 127)
     
     class Sentences(BaseModel):
         sentences: List[str]
     
     extraction_llm = llm.with_structured_output(Sentences)
     extraction_chain = obj | extraction_llm
     propositions = extraction_chain.invoke("""...text...""")
     ```  
  4. (Опционально) Объединить похожие пропозиции:  
     - Сгенерировать эмбеддинги для всех пропозиций.  
     - Вычислить косинусное сходство; если > 0.9 → объединить.  
     - Отправить объединённый набор обратно в LLM для финального формулирования.  
- **Правила и числа** – Порог схожести при мердже: `cosine similarity > 0.9`. Стоимость: ≈ 30‑60 мин и $15‑$40 на 500 фрагментов (стр. 129).  
- **Шаблоны и примеры** – Пример входа/выхода (стр. 127‑128):  

  ```
  Input:  Title: Eostre … Content: The earliest evidence …
  Output: ["The earliest evidence … in 1678 …", "..."]
  ```  

  Пример пропозиций о полёте на Луне (стр. 127): получаем 4 строки JSON.  
- **Ошибки и предупреждения** –  
  * Высокие затраты и задержки (2‑3 вызова LLM / фрагмент).  
  * Неэффективно для больших корпусов или реального‑времени.  
  * Не нужен, если документ уже состоит из самостоятельных абзацев.  
- **Где нам пригодится** – Юридические контракты, технические спецификации, документы с множеством перекрёстных ссылок, где критична точность поиска.

## 5.1 Преобразование смыслового содержания в числовой вектор (стр. 131‑135)  
- **Главная мысль** – Модели‑встраивания переводят слова/предложения в многомерные векторы, где семантически близкие фрагменты находятся рядом.  
- **Как делать**  
  1. Установить SDK: `pip install openai sentence-transformers`.  
  2. Пример с OpenAI:  

     ```python
     from openai import OpenAI
     client = OpenAI()
     for txt in ["The sky is blue.", "The grass is green."]:
         resp = client.embeddings.create(input=[txt], model="text-embedding-3-small")
         vec = resp.data[0].embedding   # 1 536 измерений
     ```  
  3. Пример с открытой моделью:  

     ```python
     from sentence_transformers import SentenceTransformer
     model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")
     embeddings = model.encode(["The sky is blue.", "The grass is green."])
     # shape (2, 384)
     ```  
- **Правила и числа** – Таблица 5‑1 (стр. 132) — ограничения токенов и размерность:  

  | Model | Макс‑токен | Размерность |
  |-------|------------|-------------|
  | text‑embedding‑3‑small (OpenAI) | 8 191 | 1 536 |
  | voyage‑large‑2‑instruct (Voyage AI) | 16 000 | 1 536 |
  | text‑embedding‑005 (Google) | 2 048 | 768 |
  | all‑MiniLM‑L6‑v2 (HF) | 512 | 384 |  

- **Шаблоны и примеры** – Список векторов (рис. 5‑2); показано, что каждый вектор ‑ список `float`.  
- **Ошибки и предупреждения** –  
  * Векторные модели требуют соответствия длины фрагмента — не превышать `max tokens`.  
  * OpenAI‑модели дорогостоящие, открытые модели менее точные, но работают локально.  
- **Где нам пригодится** – При построении векторных хранилищ для RAG‑поиска, классификации, рекомендаций.

## 5.3 Вычисление расстояния между встраиваниями (стр. 140‑144)  
- **Главная мысль** – Оценить сходство двух фрагментов текста через косинусное сходство их векторов.  
- **Как делать**  
  1. Установить: `pip install openai numpy sentence-transformers pandas`.  
  2. Сгенерировать эмбеддинги для наборов текстов и для запроса (см. пример).  
  3. Вычислить косинусную схожесть:  

     ```python
     import numpy as np
     from numpy.linalg import norm
     
     def cosine(a, b):
         return np.dot(a, b) / (norm(a) * norm(b))
     ```  

  4. Добавить столбец `similarity` в DataFrame.  
- **Правила и числа** – Приоритетный метрик — **косинусное сходство** (стр. 144). Другие: евклидово расстояние, манхэттен (не рекомендуется).  
- **Шаблоны и примеры** – Таблица с результатами (рис. 5‑8): наибольший `similarity` у фразы о «Чёрной смерти». Формула изображена (рис. 5‑9).  
- **Ошибки и предупреждения** –  
  * Не использовать `Manhattan` для плотных векторов.  
  * Косинус НЕ учитывает длину, поэтому короткий запрос может быть «равносильным» длинному абзацу.  
- **Где нам пригодится** – При ранжировании результатов векторного поиска, оценке качества эмбеддинга, построении фильтраций.

## 5.4 Выбор подходящей модели‑встраивания (стр. 145‑146)  
- **Главная мысль** – Подобрать модель, учитывая точность, стоимость, требования к latency и ограничения инфраструктуры.  
- **Как делать**  
  1. Оценить рейтинги на **MTEB** (мультизадачные бенчмарки) и, если нужен мультилингвальный поиск – **MIRACL**.  
  2. Определить, допускаете ли вы облачные API (OpenAI, Google, Cohere) или требуется локальное развертывание.  
  3. Запустить базовый набор‑тест: взять 50‑100 типовых запросов, измерить топ‑N релевантность с моделью‑по‑умолчанию (OpenAI `text‑embedding‑3‑small` или `all‑MiniLM‑L6‑v2`).  
  4. При необходимости протестировать более крупные модели (например, `text‑embedding‑3‑large`).  
  5. Замерить среднее время ответа **< 100 мс** для интерактивных приложений (стр. 145).  
  6. Подсчитать стоимость: токены × цена (пример $0.02 / 1 M токен).  
- **Правила и числа** – Таблица 5‑2 (стр. 146) с критериями:  
  * > 1 M документов / > 1 000 запросов день → приоритет скорости и цены.  
  * Высокая точность (юридика, медицина) → большие модели, даже при меньших объёмах.  
  * Реальное время → latency < 50 мс.  
- **Ошибки и предупреждения** –  
  * Не «переборщить» с размером модели: 2 % прирост точности часто не оправдывает удвоение стоимости/задержки (стр. 146).  
  * Прогонять модели только на бенчмарках недостаточно – всегда тестировать на своих данных.  
- **Где нам пригодится** – При планировании инфраструктуры RAG‑системы (какой провайдер/модель выбрать).

## 5.5 Генерация эмбеддингов для изображений и текста (CLIP) (стр. 147‑150)  
- **Главная мысль** – CLIP (Contrastive Language‑Image Pre‑training) создает совместное векторное пространство для изображений и текста, позволяя выполнять кросс‑модальный поиск и классификацию без дополнительного обучения.  
- **Как делать**  
  1. Установить: `pip install transformers torch pillow`.  
  2. Загрузить модель и процессор:  

     ```python
     from transformers import CLIPProcessor, CLIPModel
     model = CLIPModel.from_pretrained("openai/clip-vit-base-patch32")
     processor = CLIPProcessor.from_pretrained("openai/clip-vit-base-patch32")
     ```  
  3. Подготовить описания и изображения.  
  4. Получить logits‑по‑тексту и преобразовать в вероятности:  

     ```python
     with torch.no_grad():
         inputs = processor(text=descriptions, images=images, return_tensors="pt", padding=True, truncation=True)
         outputs = model(**inputs)
     probs = outputs.logits_per_text.softmax(dim=1)   # (стр. 149)
     ```  
- **Правила и числа** – Выход – матрица вероятностей, строки — изображения, столбцы — текстовые метки. Пример: 0.9999 для «cat».  
- **Шаблоны и примеры** – Код выше; результаты на рис. 5‑13.  
- **Ошибки и предупреждения** –  
  * CLIP плохо работает с текстом внутри изображения (знаки, таблички).  
  * Для большинства RAG‑задач проще генерировать текстовое описание изображения и использовать обычные текстовые эмбеддинги.  
- **Где нам пригодится** – Классификация изображений при большом количестве категорий без обучения, кросс‑модальный поиск (по изображению → текст, и наоборот).
