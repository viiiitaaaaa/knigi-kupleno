## 3.1 Exploring GPT assistants through ChatGPT (стр. 64–68)
- **Главная мысль:** Платформа GPT Assistants в ChatGPT Plus позволяет создавать, настраивать и публиковать ИИ-ассистентов с помощью простого чата-конструктора и панели ручной настройки.
- **Как делать (создание ассистента):**
  1. Перейти в магазин GPT (chatgpt.com/gpts) и нажать кнопку **Create** (стр. 64).
  2. Общаться с интерфейсом GPT Builder, который поможет определить требования и составить базовые инструкции (стр. 64–65).
  3. Открыть панель ручной настройки (**Configure panel**) для точной доработки имени, описания, стартовых вопросов и инструкций (стр. 65).
  4. Прописать четкие правила (RULES) для генерации стабильных и предсказуемых результатов (стр. 67).
- **Шаблоны и примеры:** 
  - *Пример персоны:* Кулинарный компаньон в стиле шеф-повара Джулии Чайлд (Culinary Companion) (стр. 65–66).
  - *Пример правил:* «При генерации рецепта всегда создавай изображение готового блюда, оценивай калории, создавай список покупок с ценами и рассчитывай стоимость за порцию» (стр. 67).
- **Ошибки и предупреждения:** Выходные данные ассистента могут содержать неточности; например, цены, калории и рецепты являются лишь приблизительными (стр. 67).
- **Где нам пригодится:** для быстрой сборки прототипов агентов и проверки пользовательских сценариев (промпты, проверка).

## 3.2 Building a GPT that can do data science (стр. 68–73)
- **Главная мысль:** Ассистенты GPT могут выполнять полноценный анализ данных (Data Science) при включенном инструменте интерпретации кода (Code Interpreter), который автоматически разрешает загрузку файлов.
- **Как делать (создание дата-научного агента):**
  1. Попросить LLM спроектировать шаги эксперимента для CSV-файла в ходе итеративного диалога (стр. 68).
  2. Попросить LLM перевести эти шаги в формальные инструкции для агента и выбрать подходящую персону (например, статистика Нейта Сильвера) (стр. 69).
  3. Вставить инструкции в панель Configure и поставить галочку **Code Interpretation** (стр. 70).
  4. Загрузить CSV-файл (например, `netflix_titles.csv`) и отправить запрос на фильтрацию и поиск трендов (стр. 70–71).
- **Правила и числа:** 
  - Компоненты агентов, поддерживаемые в платформе на момент написания: *knowledge* (знания), *memory* (память) и *actions* (действия/инструменты) (стр. 68).
- **Шаблоны и примеры:** 
  - *Промпт для анализа:* «Analyze the attached CSV and filter the results to the country Canada and output any significant discoveries in trends etc.» (стр. 71).
- **Ошибки и предупреждения:** Если ассистент испытывает проблемы с парсингом файла, рекомендуется обновить окно браузера и повторить попытку (стр. 71).
- **Где нам пригодится:** для обработки датасетов, запуска скриптов анализа данных и построения графиков без ручного кодирования (данные, свои скрипты, помощники).

## 3.3 Customizing a GPT and adding custom actions (стр. 73–80)
- **Главная мысль:** Пользовательские действия (custom actions) позволяют динамически расширять возможности ассистента, подключая его к внешним API (например, через FastAPI и туннель ngrok) с помощью спецификации OpenAPI.
- **Как делать (создание кастомного действия):**
  1. Создать вспомогательного GPT-помощника для генерации кода FastAPI и OpenAPI-спецификации (стр. 73).
  2. Запросить у помощника эндпоинт (например, GET-запрос для списка задач) (стр. 74).
  3. Сохранить сгенерированный код (`daily_tasks_api.py`), установить зависимости (`fastapi`, `uvicorn`) и запустить API локально через терминал (стр. 74–75):
     `uvicorn daily_tasks_api:app --reload`
  4. Открыть `http://127.0.0.1:8000/docs`, скопировать JSON/YAML документ `openapi.json` (стр. 75–76).
  5. Запустить туннель `ngrok` для доступа к локальному порту извне (стр. 76–77):
     `./ngrok authtoken <YOUR_AUTHTOKEN>`
     `./ngrok http 8000`
  6. В настройках нового ассистента нажать **Create New Action**, вставить OpenAPI-спецификацию и добавить блок `servers` с вашим ngrok URL (стр. 77–78).
- **Правила и числа:** 
  - Порт по умолчанию для FastAPI в примере: `8000` (стр. 75).
- **Шаблоны и примеры:** 
  - *Промпт для создания эндпоинта:* «I want to define a GET endpoint that replies with my list of daily tasks» (стр. 74).
- **Ошибки и предупреждения:** Опубликованные публично ассистенты с кастомными действиями могут активироваться неизвестными пользователями. Нельзя выставлять наружу сервисы, взимающие плату за запросы, или передавать конфиденциальные личные данные через ngrok (стр. 79).
- **Где нам пригодится:** для интеграции агентов со своими скриптами, базами данных и локальными API-сервисами (свои скрипты, данные, агенты).

## 3.4 Extending an assistant’s knowledge using file uploads (стр. 80–61)
- **Главная мысль:** Функция загрузки файлов позволяет снабдить ассистента статической базой знаний объемом до 512 МБ для поиска, сравнения и обучения на основе документов и книг.
- **Как делать (создание ассистента со знаниями):**
  1. Создать нового GPT-ассистента и во вкладке Configure загрузить файлы (например, PDF-книги) через кнопку **Upload files** (стр. 80).
  2. Написать инструкции, задать экспертную персону (например, математика Теренса Тао или фантаста Айзека Азимова) и прописать жесткие правила (например, «ссылаться только на загруженную базу знаний») (стр. 80–83).
  3. Включить Code Interpreter, если ассистент должен визуализировать концепции (стр. 81).
- **Правила и числа:** 
  - Максимальный объем загружаемых файлов для одного ассистента: **до 512 МБ** (стр. 80).
  - За раз можно загружать пакет файлов (в среднем около 5 штук в зависимости от размера) (стр. 60).
- **Шаблоны и примеры (Таблица 3.1, стр. 61):**
  - *Поиск:* «Search for this phrase in your knowledge: “the robot servant.”»
  - *Сравнение:* «Identify the three most similar books...»
  - *Классификация:* «Which of these books is the most modern?»
- **Ошибки и предупреждения:** Без жесткого правила «использовать только загруженные файлы» ассистент может подтягивать стандартные знания из памяти LLM.
- **Где нам пригодится:** для создания персональных баз знаний по своим книгам, документации и архивам (данные, учеба, память).

## 3.5 Publishing your GPT (стр. 61–65)
- **Главная мысль:** Готовых ассистентов можно публиковать в магазине GPT Store по ссылке или публично, причем ресурсы на их использование списываются с аккаунта конечного пользователя, а не разработчика.
- **Как делать (публикация GPT):**
  1. Убедиться, что ассистент протестирован и корректно работает (стр. 64).
  2. Нажать кнопку **Share**, выбрать вариант публикации в **GPT Store** и нажать **Save** (стр. 61, 63).
  3. Указать категорию и привязать ссылки на социальные сети или GitHub для обратной связи (стр. 63–64).
- **Правила и числа:** 
  - Функции, резко повышающие нагрузку и могущие привести к временной блокировке аккаунта пользователя: генерация изображений, частая интерпретация кода, работа с Vision (описание картинок) и загрузка множества файлов (стр. 62).
- **Шаблоны и примеры:** 
  - *Правило для контроля ресурсов:* «RULE: When generating images, ensure the user is aware that creating multiple images quickly could temporarily block their account.» (стр. 62).
- **Ошибки и предупреждения:** Интенсивное создание картинок или запуск кода пользователями вашего публичного GPT может привести к временной блокировке *их* аккаунтов в ChatGPT, поэтому важно предупреждать их об этом (стр. 62).
- **Где нам пригодится:** для упаковки своих наработок в виде готовых инструментов и создания публичного портфолио (учеба, агенты).
