## 1. Code Prompting (стр. 373)

- **Главная мысль** – LLM‑модели, обученные на больших наборах кода, могут выступать «умными помощниками» разработчика: генерировать, объяснять, переводить и отлаживать код.  
- **Как делать**  
  1. Сформулируйте задачу чётко (что требуется: написать, объяснить, перевести, отладить).  
  2. При необходимости вставьте фрагмент кода в запрос.  
  3. Укажите язык и, если важно, версию/целевую платформу.  
  4. Для отладки добавьте трассировку ошибки (traceback).  
- **Шаблоны и примеры**  
  - *Генерация*: «Write a Python function that takes a list of numbers and returns the average.»  
  - *Объяснение*: «Explain the following JavaScript code snippet: [insert code].»  
  - *Перевод*: «Translate the following Java code to C++: [insert code].»  
  - *Отладка*: «The following Python code is giving a 'NameError'. What is wrong and how can I fix it? [insert code and traceback].»  
- **Ошибки и предупреждения** – Не указывайте слишком мало контекста (модель может «угадать» неверно); не забывайте про язык/версию, иначе полученный код может быть несовместим.  
- **Где пригодится** – При написании/рефакторинге скриптов, автогенерации функций, быстрой проверке чужого кода.

## 2. Multimodal Prompting (стр. 374)

- **Главная мысль** – Модели, умеющие работать с несколькими типами данных (текст + изображения + аудио + видео), открывают новые способы взаимодействия: комбинация входов управляет выводом.  
- **Как делать**  
  1. Загрузите визуальный/звуковой файл (например, скриншот диаграммы).  
  2. Добавьте короткий текстовый запрос, описывающий нужную задачу.  
  3. Укажите требуемый тип вывода (текстовое объяснение, подпись, и т.п.).  
- **Шаблоны и примеры**  
  - *Изображение → текст*: «Explain the process shown in this diagram» (Image + Prompt → Text).  
  - *Подпись к картинке*: «Generate a descriptive caption for this image» (Image + Prompt → Text).  
- **Ошибки и предупреждения** – Пока мультимодальные модели ещё в стадии активного развития, их ответы могут быть менее предсказуемы; проверяйте полученный текст на точность.  
- **Где пригодится** – При работе с UI‑скриншотами, графиками, схемами, аудио‑инструкциями; в проектах, где нужен быстрый перевод визуального контекста в текст.

## 3. Best Practices and Experimentation — общие рекомендации (стр. 374‑376)

| Пункт | Что делать (шаги) | Примечания / Число |
|-------|-------------------|--------------------|
| **Provide Examples** | Добавляйте 1‑2 примера (one‑/few‑shot) в запрос. | – |
| **Design with Simplicity** | Делайте запросы короткими, понятными, без лишнего жаргона. | – |
| **Be Specific about the Output** | Ясно задавайте формат, длину, стиль, тип данных (JSON, XML и т.д.). | – |
| **Use Instructions over Constraints** | Формулируйте «что нужно сделать», а не «что не делать». | – |
| **Control the Max Token Length** | Ограничивайте длину вывода через параметры модели или инструкцию. | – |
| **Use Variables in Prompts** | В шаблонах задавайте переменные вместо жёстко закодированных значений. | – |
| **Experiment with Input Formats and Writing Styles** | Пробуйте вопросы, утверждения, инструкции; меняйте тон. | – |
| **Mix Up the Classes (Few‑Shot Classification)** | Перемешивайте примеры разных классов, чтобы избежать переобучения. | – |
| **Adapt to Model Updates** | При выходе новой версии модели тестируйте и при необходимости дорабатывайте запросы. | – |
| **Experiment with Structured Output** | Запрашивайте JSON / XML для задач, где важна структура. | – |
| **Collaborate with Other Prompt Engineers** | Совместные эксперименты дают новые идеи. | – |
| **Chain‑of‑Thought (CoT) Best Practices** | Размещайте ответ **после** рассуждений; ставьте temperature = 0 для задач с однозначным ответом. | – |
| **Document Prompt Attempts** | Ведите таблицу/файл с запросами, параметрами, результатами, выводами. | – |
| **Save Prompts in Codebases** | Храните запросы в отдельных файлах, контролируйте версии. | – |
| **Rely on Automated Tests and Evaluation** | Для продакшн‑сервисов пишите автотесты, проверяющие корректность вывода. | – |

- **Шаблоны/примеры** – «Provide one‑shot example: ...», «Ask for JSON: { "name": ..., "date": ... }».  
- **Ошибки** – Перегрузка инструкций, отсутствие примеров, игнорирование изменений модели.  
- **Где пригодится** – При построении собственных агентов, настройке запросов к LLM в скриптах, создании репозитариев запросов.

## 4. Conclusion of Appendix (стр. 376‑376)

- **Главная мысль** – Промптинг — дисциплинированная инженерная практика, а не просто «задать вопрос». Четкость, лаконичность и итеративный эксперимент — базовые принципы, позволяющие превратить обобщённый LLM в надёжный инструмент.  
- **Где пригодится** – При любом проекте, где требуется стабильное поведение модели (агенты, RAG, автоматизация).

## 5. Appendix B — AI Agentic Interactions: From GUI to Real‑World Environment (стр. 378‑383)

### 5.1 Interaction: Agents with Computers (стр. 378‑381)

- **Главная мысль** – Через **Agent‑Computer Interfaces (ACI)** AI‑агенты могут видеть и управлять графическим интерфейсом (GUI) так же, как человек: делать скриншоты, распознавать элементы, кликать, вводить текст, реагировать на изменения экрана.  
- **Как делать** (производственный цикл)  
  1. **Visual Perception** – Сделать скриншот текущего экрана.  
  2. **GUI Element Recognition** – Выделить кнопки, поля ввода, ссылки и т.п.  
  3. **Contextual Interpretation** – Через ACI‑модуль «перевести» визуальные объекты в смысл (кнопка «Submit» → действие «отправить форму»).  
  4. **Dynamic Action and Response** – Управлять мышью/клавиатурой, наблюдать за изменениями UI, корректировать план в реальном времени.  
- **Примеры**  
  - *ChatGPT Operator*: автоматизирует перенос данных из таблицы в CRM, бронирование поездок, заполнение онлайн‑форм без API.  
  - *Google Project Mariner*: в Chrome ищет квартиры, заполняет фильтры, собирает результаты.  
- **Ошибки** – Не учитывать задержки загрузки, поп‑апы и другие динамические изменения UI.  
- **Где пригодится** – Автоматизация повторяющихся рабочих процессов в настольных приложениях (CRM, Excel, браузерные таски).

### 5.2 Interaction: Agents with the Environment (стр. 381‑383)

- **Главная мысль** – Современные проекты (Google Astra, Gemini Live, GPT‑4o) дают агентам **мультимодальные сенсоры** (камера, микрофон) и возможность говорить, слышать и «видеть» физический мир, превращая их в почти человекоподобных помощников.  
- **Как делать** – Подавайте модели одновременно текст + изображение/звуковую дорожку; модель генерирует ответ (текст/голос) и может выполнить действие (вызов API, управление устройством).  
- **Примеры**  
  - *Google Astra*: ищет потерянный предмет, отлаживая разговор с пользователем.  
  - *Gemini Live*: отвечает в реальном времени, воспринимает тон голоса, фильтрует шум.  
  - *GPT‑4o*: «Realtime API» позволяет вести диалог «говор‑в‑режиме» с низкой задержкой.  
- **Ошибки** – Сигналы с камер/микрофонов могут быть шумными; требуется проверка достоверности полученных данных.  
- **Где пригодится** – Интерактивные помощники в умных домах, роботы‑службы, контекст‑ориентированные AR/VR‑приложения.

### 5.3 Key Takeaways (стр. 383)

- **Итоги** – AI‑агенты переходят от простых скриптов к визуальному управлению GUI и к восприятию реального мира; появляется **универсальный помощник**, который «видит», «слышит» и «действует».  

### 5.4 Conclusion of Appendix B (стр. 384‑384)

- **Главная мысль** – Совмещение цифровых и физических способностей открывает новую эпоху проактивных, контекстно‑осведомлённых AI‑компаньонов и меняет сам процесс разработки ПО (vibe coding).

## 6. Appendix C — Quick Overview of Agentic Frameworks (стр. 385‑392)

### 6.1 LangChain (стр. 385‑386)

- **Главная мысль** – LangChain — базовый фреймворк, позволяющий «склеивать» (pipe) компоненты в **линейную цепочку** (Chain) → по‑другому — DAG без циклов.  
- **Типичные задачи**  
  - *Simple RAG*: извлечение документа → промпт → LLM‑ответ.  
  - *Summarization*: текст → промпт‑суммирование → резул­тат.  
  - *Extraction*: текст → промпт → структурированный JSON.  
- **Шаблон кода**  
  ```python
  chain = prompt | model | output_parse
  ```
- **Где пригодится** – Быстрые прототипы, простые пайплайны без обратных связей.

### 6.2 LangGraph (стр. 386‑387)

- **Главная мысль** – Расширение LangChain: граф из **узлов (функций/LCEL‑цепочек)** и **рёбер (условий)**, позволяющий **циклы** и **явное управление состоянием**.  
- **Типичные задачи**  
  - *Multi‑agent*: главный агент распределяет задачи между под‑агентами, повторяя попытки.  
  - *Plan‑and‑Execute*: план → выполнение → обновление плана (цикл).  
  - *Human‑in‑the‑Loop*: пауза до получения человеческого ввода.  
- **Ключевые отличия** – **State‑object** (TypedDict) хранит переменные между узлами.  
- **Пример кода** (параллельный генератор шутки, истории, стиха) – см. строки 390‑401.  
- **Где пригодится** – Сложные рабочие процессы, требующие обратной связи, повторных попыток, мульти‑агентных взаимодействий.

### 6.3 Google ADK (стр. 388‑389)

- **Главная мысль** – Высоко‑уровневый набор «готовых» паттернов для **командной работы агентов** (SequentialAgent, ParallelAgent) с **неявным** управлением состоянием и сессией.  
- **Как работает** – Разработчик объявляет агент и инструменты (например, `google_search`), а ADK автоматизирует оркестрацию.  
- **Код‑пример**  
  ```python
  dice_agent = LlmAgent(
      model="gemini-2.0-flash-exp",
      name="question_answer_agent",
      description="A helpful assistant agent that can answer questions.",
      instruction="Respond to the query using google search",
      tools=[google_search],
  )
  ```
- **Где пригодится** – Быстрое построение поисково‑ориентированных агентов без ручного описания графов.

### 6.4 Crew.AI (стр. 389‑390)

- **Главная мысль** – Фреймворк для **командной (team‑based) оркестрации**: каждый агент имеет *роль, цель, бэк‑стори*; задачи распределяются среди агентов, процесс — последовательный или иерархический.  
- **Компоненты** – `Agent`, `Task`, `Crew`.  
- **Код‑пример**  
  ```python
  @crew
  def crew(self) -> Crew:
      return Crew(
          agents=self.agents,
          tasks=self.tasks,
          process=Process.sequential,
          verbose=True,
      )
  ```
- **Где пригодится** – Проекты, имитирующие работу человеческой команды (исследования, маркетинг, генерация контента).

### 6.5 Другие агентные фреймворки (стр. 390‑391)

| Фреймворк | Сила | Ограничения |
|-----------|------|-------------|
| **Microsoft AutoGen** | Диалог‑центрированное взаимодействие множества агентов. | Менее предсказуемый путь исполнения; требует продвинутого промпт‑инжиниринга. |
| **LlamaIndex** | Интеграция LLM с внешними/приватными данными, мощные пайплайны RAG. | Ограниченные средства для сложного агентного управления. |
| **Haystack** | Высокая производительность и масштабируемость поисковых систем. | Жёсткая архитектура, не всегда удобна для творческого агентного поведения. |
| **MetaGPT** | SOP‑ориентированная мульти‑агентная система (роли как в компании). | Специализирована под кодогенерацию, мало гибкости для других задач. |
| **SuperAGI** | Полный жизненный цикл агента, мониторинг, UI. | Сложнее в настройке, более тяжёлый стек. |
| **Semantic Kernel** | Плагины/планировщики, глубокая интеграция с .NET / Python. | Крутая кривая обучения из‑за абстракций. |
| **Strands Agents** | Лёгкий, модель‑агностичный SDK, поддержка AWS MCP. | Требует самостоятельного построения инфраструктуры наблюдения и управления. |

- **Где пригодится** – Выбор зависит от задачи: простая линейная цепочка → LangChain; сложный цикл/мульти‑агент → LangGraph/ADK; командная работа → Crew.AI; работа с данными → LlamaIndex/Haystack.

### 6.6 Conclusion of Appendix C (стр. 392)

- **Главная мысль** – Плюрализм фреймворков даёт гибкость: **LangChain** — линейные цепочки; **LangGraph** — циклические графы; **ADK / Crew.AI** — командные решения; остальные ориентированы на данные или удобство развертывания. Выбор зависит от необходимости простоты vs. динамичности vs. командной структуры.

## 7. Appendix D — Building an Agent with AgentSpace (стр. 393‑398)

### 7.1 Overview (стр. 393‑395)

- **Главная мысль** – AgentSpace — платформа для создания «агент‑ориентированного предприятия»: единый поиск по всему цифровому следу компании, построение **knowledge graph**, а также **no‑code Designer** для быстрого создания кастомных агентов.  
- **Ключевые возможности**  
  - Универсальный поиск (документы, email, БД).  
  - Интеграция с сервисами (Calendar, Gmail, Jira, Service Now и т.д.).  
  - Публичный **Agent2Agent (A2A) Protocol** — агенты могут общаться между собой.  
  - Безопасность: RBAC, шифрование.  

### 7.2 How to Build an Agent with the UI (стр. 395‑398)

- **Шаги**  
  1. Откройте Google Cloud Console → **AI Applications** → **AgentSpace**.  
  2. Подключите нужные сервисы (Calendar, Gmail, Jira, …).  
  3. Выберите готовый шаблон промпта из галереи (Fig. 3) **или** создайте собственный (Fig. 4).  
  4. При необходимости подключите внешние хранилища (датасторы, Knowledge Graph).  
  5. Сохраните конфигурацию → откройте чат‑интерфейс (Fig. 6) и начинайте диалог с агентом.  
- **Шаблоны/пример** – Готовый промпт из галереи (не приводится в тексте, но упомянут).  
- **Ошибки** – Не привязать нужные сервисы → агент не сможет выполнять задачи; забыть про ограничение доступа (RBAC).  
- **Где пригодится** – Быстрая разработка бизнес‑агентов без кода, автоматизация аналитики, генерация отчётов с цитатами.

## 8. Appendix E — AI Agents on the CLI (стр. 399‑402)

### 8.1 Claude CLI (Claude Code) (стр. 399‑400)

- **Главная мысль** – Claude CLI — «агент‑кoder», умеющий построить **ментальную модель репозитория** и выполнять многокомпонентные рефакторинги, интеграцию API и генерацию документации.  
- **Как делается** – Через **Multi‑tool Control Protocol (MCP)** агент получает доступ к файлам, Git, может создавать ветки/коммиты, а также подключать пользовательские инструменты.  
- **Примеры**  
  - *Рефакторинг*: «Refactor the entire codebase to use stateless JWTs».  
  - *API‑интеграция*: «Create a service module for the weather API и добавить компонент».  
  - *Документация*: «Generate TSDoc comments for ./src/utils/data_processing.js».  

### 8.2 Gemini CLI (стр. 401‑401)

- **Главная мысль** – Открытый, мультимодальный CLI, основанный на Gemini 2.5 Pro, обладает огромным контекстным окном и поддержкой изображений.  
- **Встроенные инструменты** – файловая система, shell‑команды, web‑fetch, поиск, многократное чтение файлов, память для длительных сессий.  
- **Примеры**  
  - *Мультимодальная разработка*: «gemini describe component.png», затем «Write React component».  
  - *Управление облаком*: «Find all GKE clusters … generate gcloud upgrade commands».  
  - *Кастомный инструмент*: `get-employee-details` → «Draft welcome document».  

### 8.3 Aider (стр. 401‑402)

- **Главная мысль** – Aider — open‑source парный программист, который **напрямую** редактирует файлы и делает **git‑коммиты** после успешного теста.  
- **Типичные сценарии**  
  - *TDD*: Создать тест, заставить его провалиться, затем реализовать код.  
  - *Баг‑фиксы*: «Fix calculate_total for leap years, run test suite».  
  - *Обновление зависимостей*: «Upgrade requests library, поправить импорты».  

### 8.4 GitHub Copilot CLI (стр. 402)

- **Главная мысль** – Интегрирован в GitHub, понимает контекст репозитория, может автоматически создавать ветки, писать код, открывать Pull‑Request и отвечать на вопросы о структуре проекта.  
- **Примеры**  
  - *Авто‑issue resolution*: По задаче #123 → ветка, исправление, PR.  
  - *Repo‑aware Q&A*: «Where is the DB connection logic and which env vars are needed?».  
  - *Генерация shell‑команды*: «gh? find all files >50 MB, compress, archive».  

### 8.5 Terminal‑Bench (стр. 402)

- **Главная мысль** – Бенчмарк‑платформа для оценки AI‑агентов в командной строке. Включает 80 ручных задач (наука, анализ данных) и **терминального агента‑стандарта** (Terminus) для сравнения. Позволяет добавлять новые агенты через контейнеризацию.  

### 8.6 Conclusion of Appendix E (стр. 402)

- **Главная мысль** – CLI‑агенты делают терминал «интеллектуальным», позволяют вести диалог, автогенерировать код, управлять инфраструктурой и выполнять сложные цепочки действий без ручного ввода.  

- **Где пригодится** – Для одиночных предпринимателей: автоматизация локального развития, CI/CD, рефакторинг больших кодовых баз, интеграция с внутренними API через MCP, быстрый поиск и модификация инфраструктурных ресурсов.
