## 4.1. Введение в многоагентные системы с помощью AutoGen Studio (стр. 92–77)
- **Главная мысль:** Платформа AutoGen Studio позволяет настраивать многоагентные системы через естественный язык, используя паттерны прокси-общения, где UserProxy (пользовательский прокси) заменяет человека в цикле проверок и итераций помощников.
- **Как делать:**
  1. Откройте папку `chapter_04` в VS Code, создайте локальное виртуальное окружение Python и установите зависимости из `requirements.txt` (стр. 94).
  2. Задайте переменную окружения с вашим ключом OpenAI (`OPENAI_API_KEY`) (стр. 94–95).
  3. Запустите интерфейс командой: `autogenstudio ui --port 8081` (порт можно изменить, например, на 8082, если 8081 занят) (стр. 95).
  4. Перейдите в браузере на `http://localhost:8081`, введите задачу (например, создание графика) на вкладке *Playground* (стр. 95).
- **Правила и числа:** 
  - Рекомендуется использовать Docker для изоляции кода, чтобы агентские скрипты не повреждали ОС и не блокировали окна (стр. 96).
  - Напишите слово `TERMINATE` в конце, чтобы остановить сессию агента (стр. 96).
- **Шаблоны и примеры:** 
  - Пример прокси: официант берет заказ у клиента, несет на кухню (ассистенту) и приносят результат обратно. Цикл повторяется, пока прокси не удовлетворен (стр. 93–94).
- **Ошибки и предупреждения:** Агенты могут использовать устаревшие библиотеки/пакеты, которые больше не работают; лучше давать агентам готовые функции-инструменты, чем заставлять их писать код для инструментов «с нуля» (стр. 96, 97).
- **Где нам пригодится:** Для быстрой проверки концепций через веб-интерфейс без написания сложного кода оркестрации.

## 4.1.2. Добавление навыков в AutoGen Studio (стр. 97–76)
- **Главная мысль:** Навыки (инструменты/действия) расширяют возможности агентов, позволяя им вызывать API, выполнять код или проверять результаты (например, валидировать изображения через GPT-4 Vision).
- **Как делать:**
  1. В AutoGen Studio перейдите на вкладку **Build** -> **Skills** и нажмите **New Skill** (стр. 97).
  2. Вставьте код функции (например, `describe_image.py` для анализа картинок с использованием base64 и GPT-4 Vision) и нажмите **Save** (стр. 97–99).
  3. Перейдите во вкладку **Workflows**, отредактируйте `primary_assistant`, добавьте созданный навык и нажмите **OK** (стр. 100).
- **Правила и числа:**
  - В примере с GPT-4 Vision в полезной нагрузке (`payload`) задается модель `"model": "gpt-4-turbo"` и ограничение `"max_tokens": 300` (стр. 99).
- **Шаблоны и примеры:** 
  - Функция `describe_image(image_path='animals.png') -> str` кодирует картинку в base64, отправляет запросом на эндпоинт OpenAI `https://api.openai.com/v1/chat/completions` и возвращает текстовое описание (стр. 98–99).
- **Ошибки и предупреждения:** Навык нужно не просто создать, но и явно привязать к конкретному воркфлоу агента, иначе он его не увидит (стр. 100).
- **Где нам пригодится:** Для создания кастомных инструментов (например, парсеров, анализаторов файлов), подключаемых к агентам.

## 4.2. Исследование AutoGen (через код) (стр. 101–103)
- **Главная мысль:** Программирование агентов на чистом Python с использованием пакета `pyautogen` дает полный контроль над логикой взаимодействия UserProxy и ConversableAgent.
- **Как делать:**
  1. Установите библиотеку: `pip install pyautogen` (стр. 101).
  2. Скопируйте файл конфигурации `OAI_CONFIG_LIST.example` в `OAI_CONFIG_LIST` и удалите `.example` из имени (стр. 101).
  3. Заполните в файле ваш ключ API, модель (рекомендуется `gpt-4`) и параметры (поддерживаются OpenAI, Azure и локальные LLM через совместимые клиенты) (стр. 101–102).
  4. Напишите скрипт (например, `autogen_start.py`) с инициализацией `UserProxyAgent` и вызовом `user_proxy.initiate_chat(assistant, message="...")` (стр. 102).
- **Правила и числа:**
  - Параметр `human_input_mode="ALWAYS"` запрашивает ввод у человека на каждом шаге (стр. 102).
  - Терминация чата настраивается через лямбда-функцию по слову `TERMINATE` (стр. 102).
- **Шаблоны и примеры:** 
  - Конфигурационный файл JSON содержит список моделей: `[{"model": "gpt-4", "api_key": "...", "tags": ["gpt-4", "tool"]}]` (стр. 102).
- **Ошибки и предупреждения:** Запуск графических приложений (например, игр на Pygame) в скриптах может не закрывать окна на Windows — используйте WSL (Windows Subsystem for Linux) или Docker (стр. 103).
- **Где нам пригодится:** Для интеграции логики многоагентных систем прямо в свои локальные скрипты Python.

## 4.2.2. Улучшение генерации кода с помощью агентов-критиков (стр. 103–105)
- **Главная мысль:** Добавление второго агента-рецензента (Reviewer) через вложенные чаты (`register_nested_chats`) позволяет автоматически проверять, тестировать и исправлять код, написанный агентом-инженером.
- **Как делать:**
  1. Создайте агента-инженера (`AssistantAgent`) с системным промптом профессионального Python-разработчика (стр. 104).
  2. Создайте агента-критика (`AssistantAgent`) с системным промптом код-ревьюера для поиска уязвимостей и ошибок (стр. 104).
  3. Напишите вспомогательную функцию `review_code`, извлекающую последнее сообщение инженера (стр. 104).
  4. Зарегистрируйте вложенный чат для прокси: `user_proxy.register_nested_chats([{"recipient": critic, "message": review_code, "summary_method": "last_msg", "max_turns": 1}], trigger=engineer)` (стр. 104).
- **Правила и числа:**
  - `max_turns=1` для вложенного чата критика (стр. 104).
  - `max_turns=2` для основного вызова чата (стр. 105).
- **Шаблоны и примеры:** 
  - Системный промпт инженера: *«You are a profession Python engineer... Your preference is to write clean, well-structured code...»* (стр. 104).
- **Ошибки и предупреждения:** Последовательные и вложенные чаты могут приводить к искажению информации («испорченный телефон»), поэтому важно контролировать количество итераций (`max_turns`) (стр. 106).
- **Где нам пригодится:** Для автоматического код-ревью и отладки скриптов, генерируемых вашими локальными инструментами.

## 4.2.3. Понимание кэширования в AutoGen (стр. 105–106)
- **Главная мысль:** Кэширование в AutoGen сохраняет историю сообщений в базе данных SQLite (в папке `.cache`), что экономит токены при итерациях и позволяет возобновлять прерванные разговоры.
- **Как делать:**
  1. Оберните вызов чата в менеджер контекста `Cache.disk`: `with Cache.disk(cache_seed=42) as cache:` (стр. 105–106).
  2. Передайте кэш в параметры: `cache=cache` внутри `initiate_chat` (стр. 106).
- **Правила и числа:**
  - `cache_seed=42` (или любое другое число) задает конкретное хранилище кэша для сессии (стр. 106).
- **Шаблоны и примеры:**
  ```python
  with Cache.disk(cache_seed=42) as cache:    
      res = user_proxy.initiate_chat(
          recipient=engineer,
          message=task,
          max_turns=2,
          summary_method="last_msg",
          cache=cache,     
      )
  ```
- **Ошибки и предупреждения:** Без кэширования сложные многошаговые задачи быстро исчерпают лимиты токенов (Token Limits) вашей LLM (стр. 105).
- **Где нам пригодится:** Для экономии бюджета на API при разработке и отладке скриптов, обращающихся к LLM.

## 4.3. Групповой чат с агентами в AutoGen (стр. 106–108)
- **Главная мысль:** Групповой чат (`GroupChat` и `GroupChatManager`) работает по принципу каналов вроде Slack или Discord, позволяя всем агентам видеть общую историю и избегать эффекта «испорченного телефона».
- **How to do / Как делать:**
  1. Импортируйте `GroupChat` и `GroupChatManager` (стр. 106).
  2. Создайте объект группы, передав список агентов, пустой список сообщений и максимальное число раундов: `groupchat = GroupChat(agents=[user_proxy, engineer, critic], messages=[], max_round=20)` (стр. 107).
  3. Создайте менеджера группы: `manager = GroupChatManager(groupchat=groupchat, llm_config=llm_config)` (стр. 107).
  4. Запустите чат, передав менеджера в качестве получателя (`recipient=manager`) (стр. 108).
- **Правила и числа:**
  - `max_round=20` — максимальное число раундов обсуждения в группе (стр. 107).
  - `human_input_mode="NEVER"` отключает вмешательство человека для полностью автономной работы (стр. 107).
- **Шаблоны и примеры:** Сравнение: в «испорченном телефоне» цепочка искажает смысл, а в групповом чате менеджер координирует сообщения как модератор, давая доступ всем агентам ко всему контексту (стр. 106, 107).
- **Ошибки и предупреждения:** Групповые чаты значительно более «многословны» (verbose) и требуют больше токенов (стр. 108).
- **Где нам пригодится:** Для организации совместной работы нескольких агентов-специалистов над одной задачей без потери контекста.

## 4.4. Создание команды агентов (Crew) с помощью CrewAI (стр. 108–111)
- **Главная мысль:** CrewAI — это ориентированная на корпоративные задачи платформа, где агенты объединяются в команду (Crew) с фиксированными ролями, целями, предысторией (backstory) и последовательной (sequential) или иерархической обработкой задач без обязательного использования UserProxy.
- **Как делать:**
  1. Установите CrewAI и импортируйте классы: `from crewai import Agent, Crew, Process, Task` (стр. 109).
  2. Определите агентов, указав `role`, `goal`, `backstory`, `verbose=True`, `memory=True` (стр. 108–110).
  3. Определите задачи (`Task`), указав `description`, `expected_output` и привязанного `agent` (стр. 110).
  4. Соберите команду: `crew = Crew(agents=[...], tasks=[...], process=Process.sequential, memory=True, cache=True, max_rpm=100)` (стр. 111).
  5. Запустите процесс: `result = crew.kickoff(inputs={"topic": "..."})` (стр. 111).
- **Правила и числа:**
  - `max_rpm=100` — ограничение максимального числа запросов в минуту (стр. 111).
- **Шаблоны и примеры:** 
  - Агент-исследователь: `role="Senior Joke Researcher"`, `goal="Research what makes things funny about the following {topic}"` (стр. 108–109).
- **Ошибки и предупреждения:** Требует больше предварительной настройки (роли, бэкстори, ожидаемые выходы), чем AutoGen, но дает жесткий контроль над процессом (стр. 108).
- **Где нам пригодится:** Для построения четких конвейеров обработки данных (например: сбор -> анализ -> отчет).

## 4.4.2. Наблюдение за агентами с помощью AgentOps (стр. 111–114)
- **Главная мысль:** Платформа AgentOps обеспечивает глубокую наблюдаемость (observability) и трекинг многоагентных систем, позволяя отслеживать время вызовов LLM, структуру промптов и, самое главное, реальные денежные затраты на токены.
- **Как делать:**
  1. Установите пакет: `pip install agentops` (или `pip install crewai[agentops]`) (стр. 112).
  2. Зарегистрируйтесь на `https://app.agentops.ai`, создайте проект и скопируйте API-ключ (стр. 112).
  3. Добавьте в файл `.env` строку: `AGENTOPS_API_KEY="your API key"` (стр. 112).
  4. В Python-скрипте импортируйте `agentops` и инициализируйте его сразу после загрузки переменных окружения: `agentops.init()` (стр. 112).
- **Правила и числа:**
  - В дашборде AgentOps можно увидеть, что генерация одной шутки агентами может стоить чуть больше 50 центов (стр. 113).
- **Шаблоны и примеры:** Дашборд фиксирует общую длительность, среду выполнения, токены промптов и ответов, тайминги вызовов LLM и оценку стоимости (стр. 113).
- **Ошибки и предупреждения:** Агенты могут незаметно «сжигать» огромные суммы денег на API из-за многословности и повторов; трекинг затрат жизненно необходим перед коммерческим запуском (стр. 113).
- **Где нам пригодится:** Для контроля расходов на API и отладки того, что именно делают агенты на каждом шаге.

## 4.5. Пересмотр агентов-кодеров с помощью CrewAI (стр. 114–119)
- **Главная мысль:** В CrewAI можно реализовать команду разработчиков игр ( Senior Engineer, QA Engineer, Chief QA Engineer) как с последовательной обработкой (`Process.sequential`), так и с иерархической (`Process.hierarchical`), где менеджер координирует работу через LLM.
- **Как делать:**
  1. Создайте агентов с ролями разработчика и тестировщиков (стр. 114–115).
  2. Создайте задачи (`code_task`, `qa_task`, `evaluate_task`) с четким описанием и ожидаемым результатом (`expected_output`) (стр. 115–116).
  3. Для иерархического режима импортируйте `ChatOpenAI` из LangChain и укажите менеджер: `process=Process.hierarchical, manager_llm=ChatOpenAI(temperature=0, model="gpt-4")` (стр. 116–118).
  4. Запустите проект через `crew.kickoff()` (стр. 116).
- **Правила и числа:**
  - `temperature=0` для управляющей модели менеджера в иерархическом режиме (стр. 117–118).
- **Шаблоны и примеры:** Ожидаемый вывод задачи тестировщика: *"Your Final answer must be the full python code, only the python code and nothing else."* (стр. 115–116).
- **Ошибки и предупреждения:** 
  - Иерархический режим с менеджером может стоить **в два раза дороже**, чем последовательный, не давая при этом значительного прироста в качестве (стр. 118).
  - Следите за графиком *Repeat Thoughts* в AgentOps: если агент постоянно повторяет одни и те же мысли, значит, он нерешителен — нужно менять промпты, задачи или структуру команды (стр. 118).
- **Где нам пригодится:** Для автоматизации генерации кода, написания скриптов и автоматического контроля качества силами ИИ.
