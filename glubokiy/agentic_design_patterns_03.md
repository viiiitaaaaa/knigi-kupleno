## Параллельность (стр. 57‑64)

### Главная мысль  
Паттерн **Parallelization** позволяет выполнять независимые подзадачи одновременно, тем самым сокращая суммарную задержку, особенно когда задачи требуют обращения к внешним API или к другим моделям.

### Как делать (шаги)

1. **Идентифицировать независимые части workflow** –‑ такие, которые не зависят друг от друга (например, summarize, generate questions, extract key terms).  
2. **Создать отдельные цепочки (chains) для каждой подзадачи** –‑ в LangChain это `ChatPromptTemplate → LLM → StrOutputParser`.  
3. **Объединить цепочки в `RunnableParallel`**, добавив `RunnablePassthrough`, чтобы оригинальный ввод сохранялся.  
4. **Определить финальный синтезирующий шаблон** (`ChatPromptTemplate`) — в него передаются результаты параллельных цепочек + исходный запрос.  
5. **Сконструировать конечный pipeline**: `full_parallel_chain = map_chain | synthesis_prompt | LLM | StrOutputParser`.  
6. **Запускать асинхронно** через `await`/`asyncio.run` (см. `run_parallel_example`).  

### Правила и числа (стр. 62‑64)

- **Rule of thumb**: использовать, когда есть несколько независимых операций (например, запросы к разным API, генерация нескольких фрагментов контента) — их можно выполнять одновременно.  
- **Правило «параллель‑плюс‑последовательность»**: после завершения всех параллельных задач выполнить одну совмещённую LLM‑операцию, которая агрегирует результаты.  

### Шаблоны и примеры  

- **LangChain‑пример** (стр. 57‑58):  
  ```python
  RunnableParallel(
      summary_chain,
      questions_chain,
      terms_chain,
      RunnablePassthrough()
  )
  full_parallel_chain = map_chain | synthesis_prompt | llm | StrOutputParser()
  ```
- **Google ADK‑пример** (стр. 58‑61):  
  - Три `LlmAgent` — `RenewableEnergyResearcher`, `EVResearcher`, `CarbonCaptureResearcher`.  
  - `ParallelAgent(sub_agents=[researcher_agent_1, researcher_agent_2, researcher_agent_3])`.  
  - `SequentialAgent(sub_agents=[parallel_research_agent, merger_agent])`.  

### Ошибки и предупреждения  

- При параллелизме **увеличивается сложность разработки** (отладка, логирование).  
- Нужно убедиться, что **подзадачи действительно независимы**; иначе возможны гонки данных.  

### Где нам пригодится  

Для запросов, требующих одновременного обращения к нескольким API (поиск, сбор метрик, генерация разных вариантов контента) — экономия времени и более отзывчивые агенты.

## Отражение (Reflection) (стр. 65‑78)

### Главная мысль  
Паттерн **Reflection** вводит обратный цикл: агент (или отдельный критик) оценивает собственный вывод, выявляет недочёты и генерирует улучшенный вариант. Это повышает точность, полноту и соответствие сложным требованиям.

### Как делать (шаги)

1. **Выполнить начальную задачу** (Producer / Generator).  
2. **Сгенерировать оценку/критик** –‑ отдельный LLM‑запрос с системным промптом «ты — senior reviewer».  
3. **Если критика содержит специальный маркер «CODE_IS_PERFECT» (или аналог), остановиться**; иначе –‑ использовать полученные замечания как инструкцию к следующей генерации.  
4. **Повторять шаги 2‑3** до выполнения условия остановки либо достижения максимального числа итераций.  
5. **Сохранить финальный результат**.  

### Правила и числа (стр. 66‑68)

- **Rule of thumb**: применять, когда качество, точность и детализация важнее скорости и стоимости.  
- **Максимальное количество итераций** в примерах — `max_iterations = 3`.  
- **Маркер завершения** –‑ наличие строки `CODE_IS_PERFECT` в критике.  

### Шаблоны и примеры  

- **Generator‑Critic в LangChain** (стр. 70‑72):  
  ```python
  reflector_prompt = [
      SystemMessage("You are a senior software engineer ... respond with 'CODE_IS_PERFECT' if perfect."),
      HumanMessage(f"Original Task:\n{task_prompt}\n\nCode to Review:\n{current_code}")
  ]
  critique = llm.invoke(reflector_prompt).content
  ```
- **Producer‑Reviewer в ADK** (стр. 73‑74):  
  ```python
  generator = LlmAgent(..., output_key="draft_text")
  reviewer  = LlmAgent(..., output_key="review_output")
  review_pipeline = SequentialAgent(sub_agents=[generator, reviewer])
  ```
- **Цикл в функции `run_reflection_loop()`** (стр. 69‑71).  

### Ошибки и предупреждения  

- **Стоимость и задержка** растут линейно с количеством итераций (каждый круг — новый LLM‑вызов).  
- **Потребление контекстного окна**: история сообщений быстро заполняет предел модели.  

### Где нам пригодится  

Для задач, где требуется высокое качество: написание статей, генерация и отладка кода, построение подробных планов, создание точных суммаризаций.

## Использование инструментов (Tool Use / Function Calling) (стр. 79‑88)

### Главная мысль  
Паттерн **Tool Use** (или Function/Tool Calling) даёт агенту возможность вызывать внешние функции, API, базы данных или запускать код, тем самым преодолевая ограничения «только‑текстовой» генерации LLM.

### Как делать (шаги)

1. **Определить инструмент** –‑ написать функцию и оформить её метаданные (имя, параметры, типы, описание).  
2. **Зарегистрировать инструмент в фреймворке** (LangChain `@tool`, CrewAI `@tool`).  
3. **Создать запрос‑prompt**, включающий placeholder для `agent_scratchpad`.  
4. **Связать LLM с набором инструментов** (`create_tool_calling_agent` в LangChain, `AgentExecutor`).  
5. **Запустить агент** –‑ LLM решает, нужен ли вызов инструмента, генерирует JSON‑запрос.  
6. **Выполнить реальный вызов функции** и передать результат обратно LLM.  
7. **LLM формирует окончательный ответ** пользователю.  

### Правила и числа (стр. 80‑82)

- **Rule of thumb**: использовать, когда требуется доступ к актуальной информации, вычислениям, управлению внешними сервисами или устройствами.  
- **Шаги процесса** (стр. 80): 1‑Tool Definition, 2‑LLM Decision, 3‑Function Call Generation, 4‑Tool Execution, 5‑Observation/Result, 6‑LLM Processing (optional).  

### Шаблоны и примеры  

- **LangChain‑инструмент `search_information`** (стр. 83‑85):  
  ```python
  @langchain_tool
  def search_information(query: str) -> str:
      """Provides factual information on a given topic."""
      simulated_results = {...}
      return simulated_results.get(query.lower(), simulated_results["default"])
  ```
  Затем:  
  ```python
  agent = create_tool_calling_agent(llm, [search_information], agent_prompt)
  response = await agent_executor.ainvoke({"input": query})
  ```
- **CrewAI‑инструмент `get_stock_price`** (стр. 86‑87):  
  ```python
  @tool("Stock Price Lookup Tool")
  def get_stock_price(ticker: str) -> float:
      simulated_prices = {"AAPL": 178.15, ...}
      if ticker.upper() in simulated_prices:
          return simulated_prices[ticker.upper()]
      raise ValueError(...)
  ```
  Создание агента, задачи и `Crew`‑оркестрации в последующих строках.  

### Ошибки и предупреждения  

- **Отсутствие поддержки функции в модели** — нужно выбирать LLM с включённым Tool/Function Calling (например, Gemini‑2.0‑flash, GPT‑4o).  
- **Неправильное описание параметров** приводит к неверным JSON‑запросам.  
- **Необработанные исключения** в инструментах (см. `raise ValueError`) могут прервать выполнение, если агент не настроен ловить их.  

### Где нам пригодится  

Для запросов, требующих доступа к внешним данным (погода, цены акций), вычислений, отправки писем, управления умным домом, а также для выполнения кода в безопасной песочнице.
