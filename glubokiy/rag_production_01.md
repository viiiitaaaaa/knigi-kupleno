# Конспект книги «Hands-On RAG for Production» (Часть 1)

**Общая цель книги:** Переход от «игрушечных» демо-проектов RAG (которые легко собрать за вечер) к промышленным (production-grade) системам, которые отличаются высокой точностью, низкой задержкой (latency) и масштабируемостью.

## Введение и общие концепции (стр. 2–26)
- **Главная мысль:** RAG (Retrieval-Augmented Generation) — это стратегия интеграции больших языковых моделей (LLM) с уникальными знаниями организации. Это способ дать «мозгу» (LLM) «память» в виде внешних данных, чтобы избежать галлюцинаций и работать с актуальной информацией.
- **Термины:**
    - **RAG (Retrieval-Augmented Generation):** Генерация с дополненным поиском. Процесс, когда система сначала ищет нужные факты в данных, а затем передает их LLM для составления ответа.
    - **Галлюцинации:** Уверенные, но фактически неверные ответы LLM, не подкрепленные данными.
    - **LLM-as-a-Judge:** Использование одной мощной LLM для оценки качества ответов другой модели.
- **Ключевые задачи для внедрения:**
    1. Выбор между собственной разработкой (DIY) и готовой платформой (RAG-as-a-service).
    2. Борьба с галлюцинациями и обеспечение безопасности данных.
    3. Снижение задержек (latency) при ответе.
    4. Переход от «оценки по ощущениям» (vibe-based testing) к автоматическим метрикам.
- **Где нам пригодится:** Для построения архитектуры личного помощника, который будет точно отвечать по твоим документам, скриптам и базе знаний, не выдумывая факты.

## Глава 1. Введение в RAG (стр. 27–30)
- **Главная мысль:** LLM обладают «параметрическими знаниями» (тем, что выучили при обучении), но они «слепы» к частным или новым данным. RAG превращает «экзамен по памяти» (closed-book test) в «экзамен с учебником» (open-book test).

### Как работает RAG (процесс):
1. **R (Retrieval / Поиск):** Система ищет в частных данных документы, наиболее подходящие к запросу пользователя.
2. **G (Generation / Генерация):** LLM получает запрос + найденные факты и синтезирует ответ, опираясь только на этот контекст.

### Архитектура RAG стека (Blueprint):
Система делится на два основных потока:
1. **Поток загрузки (Ingestion Flow):** Извлечение данных из источников (PDF, базы данных, Notion) $\rightarrow$ преобразование в форматы для поиска (например, векторные эмбеддинги) $\rightarrow$ индексация.
2. **Поток запроса (Query Flow):** Обработка запроса пользователя $\rightarrow$ поиск релевантных фактов $\rightarrow$ генерация ответа через LLM.

### Шаблон промпта для RAG (стр. 29):
`«Вы — помощник по ответам на вопросы. Используйте следующие фрагменты контекста для ответа. Если не знаете ответа, просто скажите, что не знаете. <вопрос>{question}</вопрос> <контекст>{context}</контекст> Ответ:»`

### Сравнение подходов:
- **RAG против Fine-Tuning (Дообучения):** RAG позволяет мгновенно добавлять/удалять знания и обеспечивает прозрачность (можно проверить, из какого документа взят ответ), в то время как дообучение меняет внутренние веса модели и сложнее в обновлении.
- **RAG против «Chat with PDF»:** Промышленный RAG — это масштабируемая система с управлением доступом и проверкой качества, а не просто загрузка одного файла в чат.

### Преимущества RAG (стр. 12–14):
- Снижение галлюцинаций.
- Объяснимость (explainability) — модель может сослаться на источник.
- Почти мгновенное обновление знаний.
- Возможность настройки прав доступа к данным.

- **Где нам пригодится:** Для создания запросов (промптов) и понимания того, почему помощник может ошибаться (проблема в поиске данных или в самой модели).
