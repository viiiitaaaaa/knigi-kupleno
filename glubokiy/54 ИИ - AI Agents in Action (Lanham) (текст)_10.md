## 9. Mastering agent prompts with prompt flow (Окончание главы 9) (стр. 264–267)
- **Главная мысль:** В этом разделе завершается разбор инструмента Prompt Flow: создается блок агрегации результатов для оценки вариантов промптов, а также описывается процедура сравнения пакетных запусков (Batch Runs).
- **Как делать (сравнение результатов запусков):**
  1. Откройте расширение Prompt Flow в VS Code, найдите раздел истории пакетных запусков (*Batch Run History*) и прокрутите до секции *Run against Run* (стр. 264).
  2. Выберите нужные запуски (появится галочка) (стр. 264).
  3. Нажмите правой кнопкой мыши и выберите пункт *Visualize Runs* (Визуализировать запуски) (стр. 264).
  4. Сравните метрики агрегированных критериев в открывшемся окне (стр. 264).
- **Правила и числа:** 
  - Функция агрегации (`aggregate.py`) принимает список списков (`processed_results`), объединяет их, проверяет значения на числовой тип (`float`, `int`), суммирует по ключам критериев (исключая `title`), делит на общее количество элементов для получения среднего и логирует метрики (стр. 264).
- **Шаблоны и примеры:** Код функции `@tool def aggregate(processed_results: List[str]):` для усреднения числовых оценок критериев из результатов оценки (стр. 264).
- **Ошибки и предупреждения:** При выборе существующего запуска для оценки (grounding) нельзя использовать локальные JSON Lines файлы (стр. 265).
- **Где нам пригодится:** Для автоматической оценки и сравнения эффективности разных версий промптов агентов в скриптах.

## 10. Agent reasoning and evaluation (Введение в главу 10) (стр. 268–269)
- **Главная мысль:** Глава посвящена последнему и ключевому компоненту агентов — планированию, а также техникам промптиинга для рассуждений (reasoning), понимания, оценки (evaluation) и обратной связи.
- **Правила и числа:**

- **Где нам пригодится:** Общая карта паттернов и запросов для проектирования логики агентов-помощников.

## 10.1 Understanding direct solution prompting (стр. 269–276)
- **Главная мысль:** Базовые методы прямого промптиинга (вопрос-ответ, few-shot и zero-shot) устанавливают фундамент для понимания того, как заставлять языковые модели (LLM) решать задачи и обобщать знания.
- **Как делать (запуск пайплайна в Prompt Flow):**
  1. Откройте папку нужного флоу в VS Code, создайте виртуальное окружение и установите зависимости из `requirements.txt` (стр. 270).
  2. Откройте файл `flow.dag.yaml` в визуальном редакторе (стр. 270).
  3. Настройте подключение к LLM и блоку эмбеддингов (стр. 271).
  4. Запустите флоу кнопкой Play в визуальном редакторе или комбинацией `Shift-F5` в YAML-редакторе (стр. 271).
- **Правила и числа:** 
  - Терминология обучения: *Zero-shot* (без примеров), *One-shot* (один пример), *Few-shot* (несколько примеров) для настройки модели под новые паттерны (стр. 272).
- **Шаблоны и примеры:** 
  - *Промпт Вопрос-Ответ (`question_answer.jinja2`):* системное сообщение требует отвечать коротко на основе контекста и возвращать «Unsure about answer», если ответа нет (стр. 272).
  - *Few-shot промпт (`few_shot.jinja2`):* задает персону эксцентричного создателя словарей, дает примеры выдуманных слов («whatpu», «farduddle») и требует возвращать только запрошенное предложение (стр. 270, 274).
  - *Zero-shot промпт (`zero_shot.jinja2`):* классифицирует текст на neutral, negative или positive без примеров, выдавая строго результат (стр. 275).
- **Где нам пригодится:** Для создания базовых скриптов извлечения информации, классификации текста и создания кастомных «персон» агента.

## 10.2 Reasoning in prompt engineering (стр. 276–285)
- **Главная мысль:** Хотя LLM не созданы для логики и рассуждений, их можно натренировать/спровоцировать промптами (Chain of Thought, Zero-shot CoT, Prompt Chaining) решать сложные логические и математические задачи по шагам.
- **Как делать (Запуск CoT и цепочек промптов):**
  1. Откройте соответствующую папку флоу (`chain-of-thought-prompting`, `zero-shot-cot-prompting` или `prompt-chaining`) в VS Code (стр. 277, 282, 283).
  2. Проверьте входной файл `flow.dag.yaml` и структуру шагов (стр. 277).
  3. Нажмите `Shift-F5` для запуска и анализа вывода LLM (стр. 279, 283).
- **Правила и числа:** 
  - *Рассуждение (Reasoning)* — способность понимать мыслительный процесс и последовательность действий (стр. 276).
  - *Планирование (Planning)* — способность выстраивать порядок действий для достижения цели (стр. 276).
- **Шаблоны и примеры:** 
  - *Chain of Thought (CoT):* промпт содержит примеры сложных задач (например, с путешествиями во времени) с детальным пошаговым решением (*Chain of Thought*) (стр. 279, 280).
  - *Zero-shot CoT:* простой промпт с магической фразой *"Let's think step by step"* («Давайте подумаем шаг за шагом»), заставляющей модель рассуждать без примеров (стр. 282).
  - *Prompt Chaining:* разделение задачи на отдельные шаги через несколько блоков LLM (`decompose_steps.jinja2`, `calculate_steps.jinja2`, `calculate_solution.jinja2`) (стр. 283–285).
- **Ошибки и предупреждения:** Цепочки промптов (Prompt Chaining) могут быть избыточно многословными (*overly verbose*), а пошаговые рассуждения не всегда гарантируют 100% правильный итоговый ответ без механизма оценки (стр. 283, 285).
- **Где нам пригодится:** Для написания сложных запросов к агентам, требующих декомпозиции задач, логического анализа и пошагового выполнения скриптов.

## 10.3 Employing evaluation for consistent solutions (стр. 285–289)
- **Главная мысль:** Чтобы повысить точность и надежность агентов, применяют самосогласованность (self-consistency) — генерацию нескольких вариантов решений с последующей пакетной оценкой и агрегацией для выбора самого частого/корректного ответа.
- **Как делать (Запуск Self-Consistency в пакетном режиме):**
  1. Откройте папку `self-consistency-prompting/flow.dag.yaml` в визуальном редакторе Prompt Flow (стр. 284).
  2. Нажмите кнопку **Batch Run** (иконка колбы) (стр. 284).
  3. Выберите локальный файл данных JSON Lines (`statements.jsonl`) со списком идентичных проблем для симуляции множественных прогонов (стр. 284).
  4. Кликните по ссылке **Run** в сгенерированном YAML для старта пакетной обработки (стр. 284).
  5. Для оценки результатов откройте `self-consistency-evaluation/flow.dag.yaml`, где эмбеддинги предсказаний обрабатываются скриптом `consistency.py` для вычисления косинусного расстояния (*cosine similarity*) и поиска наиболее стабильного ответа (стр. 287).
- **Правила и числа:** 
  - Самосогласованность позволяет использовать высокую температуру (temperature) модели для генерации разнообразных идей, а затем выбирать наиболее повторяющийся/согласованный результат (стр. 286).
- **Шаблоны и примеры:** Файл `consistency.py` использует библиотеку `scipy.spatial.distance` (`cosine`) для расчета схожести пар ответов и выбора лучшего (стр. 287).
- **Где нам пригодится:** Для написания надежных скриптов валидации ответов ИИ-агента, когда требуется запустить задачу несколько раз и выбрать наиболее консенсусный результат.
