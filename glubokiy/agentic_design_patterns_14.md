## 1. Сильные AI‑агенты‑командные строки меняют разработку (стр. 403)  
- **Главная мысль** – Появление мощных CLI‑агентов (Claude, Gemini, Aider, GitHub Copilot) преобразует терминал в совместную, динамичную среду; выбор инструмента зависит от конкретных задач.  
- **Где пригодится** – запросы к терминалу, автоматизация сборки/деплоя, быстрый поиск ошибок, работа с Git.

## 2. Appendix G – Coding Agents (стр. 404‑405)  

### 2.1 Vibe Coding: стартовая точка (стр. 404‑405)  
- **Главная мысль** – «Vibe‑coding» — быстрая генерация черновиков кодов с помощью LLM, помогает преодолеть «проблему пустой страницы» и быстро исследовать незнакомые API. Настоящая надёжность достигается только при переходе к специализированным агентам.  
- **Шаблон примера** – *нет конкретного шаблона, только описание практики.*  
- **Где пригодится** – быстрый прототип, мозговой штурм, исследование новых библиотек.  

### 2.2 Agents as Team Members (стр. 404‑405)  
- **Главная мысль** – Современные команды используют набор специализированных код‑агентов (Scaffolder, Tester, Documenter, Optimizer, Process), которые дополняют, а не заменяют разработчика.  
- **Где пригодится** – любой проект, где нужны повторяющиеся задачи: тесты, документация, рефакторинг.

## 3. Три фундаментальных принципа человеческо‑агентной команды (стр. 405‑406)  

1. **Human‑Led Orchestration** – разработчик — лидер, задаёт цели, выбирает агента, принимает окончательное решение.  
2. **Primacy of Context** – качество вывода агента = качеству контекста. Нужно вручную собрать:  
   - *полный кодбейс*;  
   - *внешние знания* (документация, API);  
   - *human brief* (цели, требования, PR‑описание, стилистика).  
3. **Direct Model Access** – использовать прямой доступ к передовым моделям (Gemini 2.5 PRO, Claude Opus 4, OpenAI, DeepSeek). Промежуточные платформы ухудшают результат.  

- **Где пригодится** – построение надёжных запросов к агентам, настройка контекста, работа с чувствительными данными.

## 4. Core Components – структура команды (стр. 406‑407)  

| Компонент | Роль | Пример реализации |
|-----------|------|-------------------|
| **Orchestrator** (человек) | Team lead, архитектор, «финальный судья». | Терминал + редактор + веб‑UI агентов. |
| **Context Staging Area** | Папка‑брифинг для задачи. | `task-context/` → markdown‑файлы: `01_BRIEF.md`, `02_CODE/` и др. |
| **Specialist Agents** | Специализированные роли (см. ниже). | Вызываются через **role‑prompt**. |

### 4.1 Специализированные агенты (стр. 406‑407)  

| Агент | Цель | Пример invocation‑prompt |
|-------|------|--------------------------|
| **Scaffolder** (Implementer) | Пишет новый код/фичи, создаёт шаблоны. | «You are a senior software engineer. Based on the requirements in 01_BRIEF.md and the existing patterns in 02_CODE/, implement the feature…» |
| **Test Engineer** (Quality Guard) | Генерирует unit / integration / e2e‑тесты. | «You are a quality assurance engineer. For the code provided in 02_CODE/, write a full suite of unit tests using pytest…» |
| **Documenter** (Scribe) | Пишет документацию (markdown). | «You are a technical writer. Generate markdown documentation for the API endpoints defined in the provided code…» |
| **Optimizer** (Refactoring Partner) | Находит узкие места, предлагает рефакторинг. | «Analyze the provided code for performance bottlenecks or areas that could be refactored for clarity…» |
| **Process** (Code Supervisor) | Выполняет критику, затем рефлексию → приоритетный список. | «You are a principal engineer conducting a code review. First, perform a detailed critique… Second, reflect on your critique to provide a concise, prioritized summary…» |

- **Где пригодится** – автоматизация типовых этапов CI/CD, быстрый отклик на PR.

## 5. Практическая реализация – Setup Checklist (стр. 407‑408)  

1. **Provision Access to Frontier Models** – получить безопасные API‑ключи минимум двух моделей (Gemini 2.5 Pro, Claude 4 Opus).  
2. **Implement a Local Context Orchestrator** – использовать лёгкий CLI‑инструмент (или «local agent runner») с конфигурацией `context.toml`, собирающей файлы/директории/URL в один payload.  
3. **Establish a Version‑Controlled Prompt Library** – создать директорию `/prompts` в репозитории, хранить в ней markdown‑файлы с приглашениями (`reviewer.md`, `documenter.md`, `tester.md`).  
4. **Integrate Agent Workflows with Git Hooks** – в Git‑hooks (например, `pre‑commit`) автоматически запускать Reviewer‑Agent на staged‑изменения и выводить резюме в терминал.  

- **Правила и числа** – пункты 1‑4 (стр. 407).  
- **Где пригодится** – любой проект с Git, требующий автоматической проверки кода.

## 6. Principles for Leading the Augmented Team (стр. 408‑409)  

| Принцип | Краткое содержание |
|--------|-------------------|
| **Maintain Architectural Ownership** | Руководитель задаёт «что» и «почему», а агенты помогают реализовать «как». |
| **Master the Art of the Brief** | Качество вывода = качеству брифа; бриф = полный набор целей, кода, стиля. |
| **Act as the Ultimate Quality Gate** | Вывод агента — предложение, финальная проверка только у человека. |
| **Engage in Iterative Dialogue** | Диалог, а не монолог: исправлять, уточнять, повторять запрос. |

- **Где пригодится** – при управлении командой AI‑агентов, ревью PR, подготовке документации.

## 8. Conclusion – Обзор ключевых агентных принципов (стр. 416‑417)  

- **Главная мысль** – 21 паттерн сгруппированы в 4 категории:  
  1. **Core Execution & Task Decomposition** – Prompt Chaining, Routing, Parallelization, Planning.  
  2. **Interaction with External Environment** – Tool Use (Function Calling), Knowledge Retrieval (RAG).  
  3. **State, Learning & Self‑Improvement** – Memory Management, Reflection, Self‑Correction, Learning & Adaptation.  
  4. **Collaboration & Communication** – Multi‑Agent Collaboration, Inter‑Agent Communication (A2A), Model Context Protocol (MCP).  

- **Где пригодится** – построение любой сложной системы из нескольких агентных паттернов.

## 9. Сочетание паттернов в сложных системах (стр. 418)  

**Пример** – автономный AI‑исследователь:  

1. **Planning** – планирует исследовательскую задачу.  
2. **Tool Use** – вызывает поисковые API (Google, arXiv).  
3. **Multi‑Agent Collaboration** – «Researcher» собирает материалы, «Writer» создает черновик.  
4. **Reflection + Self‑Correction** – «Critic» проверяет черновик, «Writer» улучшает его.  
5. **Memory Management** – хранит план, собранные данные, черновики, обратную связь.  

- **Где пригодится** – построение автономных аналитических помощников, генерация отчётов, исследовательские боты.  

---  

## 10. Взгляд в будущее (стр. 419‑420)  

- **Главная мысль** – агентные системы перейдут от «human‑in‑the‑loop» к «human‑on‑the‑loop», где агенты выполняют длительные задачи с минимальным контролем, а человек получает лишь отчёты.  
- Появятся открытые маркеты «agents‑as‑a‑service», стандарты MCP и A2A, а также новые **safety‑patterns** для предотвращения дрейфа, атак и непредсказуемого поведения.  

- **Где пригодится** – построение масштабируемых сервисов AI, интеграция в продакшн‑окружения, создание новых бизнес‑моделей вокруг AI‑агентов.

## 11. Glossary (стр. 421‑426)  

| Термин | Краткое определение (из текста) |
|--------|---------------------------------|
| **Prompt** | Ввод (вопрос, инструкция) к модели, от которого зависит ответ. |
| **Context Window** | Максимальное число токенов, которое модель обрабатывает одновременно. |
| **In‑Context Learning** | Обучение задаче через примеры в самом запросе, без дообучения модели. |
| **Zero‑Shot / One‑Shot / Few‑Shot Prompting** | Техники задания задачи модели без/с одним/с несколькими примерами. |
| **Multimodality** | Способность модели работать с несколькими типами данных (текст, изображение, аудио). |
| **Grounding** | Привязка вывода модели к проверенным внешним источникам (часто через RAG). |
| **Transformer** | Базовая архитектура большинства современных LLM, использующая self‑attention. |
| **RNN** | Предшествующая Transformer архитектура, обрабатывающая последовательность последовательно. |
| **Mixture of Experts (MoE)** | Архитектура, где «router» выбирает несколько «экспертов»‑подмоделей. |
| **Diffusion Models** | Генеративные модели изображений; обучаются восстанавливать шум в данные. |
| **Mamba** | Альтернатива Transformer, использующая Selective State Space Model для длинных контекстов. |

- **Где пригодится** – быстрый справочник при построении запросов, объяснение терминов клиенту, обучение.

## 12. LLM Development Lifecycle (стр. 427‑432)  

1. **Pre‑training** – обучение модели на огромном корпусе текста (CLM, MLM, Denoising, Contrastive Learning, NSP).  
2. **Fine‑tuning** – адаптация к конкретным задачам:  
   - *Supervised Fine‑Tuning (SFT)*,  
   - *Instruction Tuning*,  
   - *Parameter‑Efficient Fine‑Tuning (PEFT)* – LoRA, QLoRA;  
   - *Retrieval‑Augmented Generation (RAG)* – подключение к внешним источникам.  
3. **Alignment** – обеспечение «полезности и безвредности» через:  
   - *Reinforcement Learning from Human Feedback (RLHF)* (PPO),  
   - *Direct Preference Optimization (DPO)*,  
   - *Kahneman‑Tversky Optimization (KTO)*,  
   - *Guardrails* – фильтры в реальном времени.  

- **Где пригодится** – при создании собственного LLM‑агента, настройка параметров, обеспечение безопасности.

## 13. Enhancing AI Agent Capabilities (стр. 433‑436)  

| Паттерн | Суть | Применение |
|---------|------|------------|
| **Chain of Thought (CoT)** | Модель «думает вслух», шаг‑за‑шагом, повышая точность сложных рассуждений. |
| **Tree of Thoughts (ToT)** | Одновременно исследует несколько веток рассуждения, выбирает лучшую. |
| **ReAct (Reason and Act)** | Чередует размышление и действие (вызов инструмента), затем использует наблюдение для следующего шага. |
| **Planning** | Делит большую цель на последовательные подзадачи и создаёт план их выполнения. |
| **Deep Research** | Автономно проводит глубокий поиск: итеративно собирает, синтезирует, формулирует новые вопросы. |
| **Critique Model** | Специальный модель‑критик, оценивающая и дающий обратную связь на выводы другого агента. |

- **Где пригодится** – построение интеллектуальных ассистентов, автоматизированный анализ данных, сложные задачи, требующие несколько ходов рассуждения.
