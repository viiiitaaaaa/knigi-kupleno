## Глава 9. Управление промптами агентов с помощью prompt flow (стр. 236)
- **Главная мысль:** Введение в системную инженерию промптов (Systematic Prompt Engineering) и обзор стратегии «Систематическое тестирование изменений» с использованием инструмента Microsoft prompt flow.
- **Шаблоны и примеры:** Сравнение расплывчатого запроса («can you recommend something») и точного («Can you please recommend a time travel movie set in the medieval period») (стр. 237). Использование системного промпта через ключевое слово `system` (стр. 239).
- **Ошибки и предупреждения:** Обычные итерации в чате работают, но не дают системного метода для оценки эффективности и определения того, когда промпт действительно хорош (стр. 240).
- **Где нам пригодится:** Для запросов, проверки, памяти, помощников, данных или учёбы: Создание структурированных системных сообщений для ИИ-помощника.

## 9.1 Почему нам нужна системная инженерия промптов (стр. 237–240)
- **Главная мысль:** Итеративное улучшение промптов требует перехода от ручного ввода в чате к системному циклу оценки изменений (стратегия *Test Changes Systemically*).
- **Правила и числа:** 
  - Базовые стратегии OpenAI (рис. 9.2, стр. 238): Пишите четкие инструкции (Write Clear Instructions), предоставляйте справочный текст (Provide Reference Text), используйте внешние инструменты (Use External Tools), разбивайте сложные задачи на подзадачи (Split Complex Tasks into Simpler Subtasks), давайте моделям время на «размышление» (Give Models Time to “Think”), тестируйте изменения систематически (Test Changes Systemically).
- **Где нам пригодится:** Для запросов, проверки, памяти, помощников, данных или учёбы: Построение базы для написания надежных скриптов запросов к LLM.

## 9.2 Понимание профилей агентов и персон (стр. 240–241)
- **Главная мысль:** Профиль агента (Agent Profile) — это капсула из компонентов и сообщений, описывающая персону агента, его инструкции, инструменты, память и знания.
- **Шаблоны и примеры:** Основные элементы профиля агента (рис. 9.6, стр. 241): Персона (Persona), Инструменты агента (Agent Tools), Оценка и рассуждения (Agent Evaluation and Reasoning), Память и знания (Agent Memory and Knowledge), Планирование и обратная связь (Agent Planning and Feedback).
- **Где нам пригодится:** Для запросов, проверки, памяти, помощников, данных или учёбы: Проектирование архитектуры одиночного агента со всеми его зависимостями.

## 9.3 Настройка вашего первого prompt flow (стр. 241–246)
- **Главная мысль:** Установка и первичная настройка инструмента *prompt flow* от Microsoft в VS Code для разработки, многопоточной пакетной обработки и оценки промптов.
- **Как делать (настройка и запуск):**
  1. Установите VS Code, расширение prompt flow, настройте виртуальное окружение Python (стр. 242).
  2. Установите пакеты командой: `pip install promptflow promptflow-tools` (стр. 242).
  3. Получите доступ к GPT-4 или выше через OpenAI / Azure OpenAI (стр. 242).
  4. Создайте подключение к LLM в расширении prompt flow (заполните YAML-файл без указания ключей в самом файле) (стр. 242). Вставьте ключ в терминале (правый клик мыши на Windows для вставки) (стр. 242).
  5. Откройте папку `chapter_09/promptflow/simpleflow`, откройте `flow.dag.yaml` и перейдите в визуальный редактор (Visual Editor) (стр. 242, 244).
  6. Настройте блок LLM (имя подключения, тип API: `chat` или `completion`, модель/деплоймент) (стр. 244, 245).
  7. Проверьте входные данные (`user_input`) и нажмите кнопку Play для запуска графа (стр. 245).
- **Правила и числа:** 
  - Важные параметры LLM-блока (стр. 245): `Connection` (подключение/сервис), `API` (`chat` для GPT-4 или `completion` для старых моделей вроде Davinci), `Model` (имя модели или имя развертывания в Azure), `Temperature` (от 0 — нет случайности, до 1 — высокая вариативность), `Stop` (остановка генерации токенов), `Max tokens` (лимит токенов для масштабируемости).
- **Где нам пригодится:** Для запросов, проверки, памяти, помощников, данных или учёбы: Настройка локального окружения для запуска и тестирования агентов через код.

## 9.3.2 Создание профилей с помощью шаблонов Jinja2 (стр. 246–247)
- **Главная мысль:** Использование шаблонизатора Jinja2 (файлы `.jinja2`) для создания гибких шаблонов промптов и профилей агентов.
- **Шаблоны и примеры:** Ссылки на `.jinja2` файлы внутри блоков prompt flow для разделения системных и пользовательских частей промпта (рис. 9.12, стр. 246). Шаблонизатор позволяет внедрять переменные (например, `{{ user_input }}`) прямо в текст промпта.
- **Где нам пригодится:** Для запросов, проверки, памяти, помощников, данных или учёбы: Создание динамических шаблонов промптов для своих скриптов.

## 9.3.3 Развертывание API prompt flow (стр. 247–248)
- **Главная мысль:** Быстрое развертывание готового prompt flow в виде локального веб-приложения или Docker-контейнера.
- **Как делать:**
  1. В файле `flow.dag.yaml` нажмите кнопку **Build** в верхней части экрана (стр. 247).
  2. Выберите развертывание в качестве локального приложения (Local App) (стр. 247).
  3. Оставьте настройки по умолчанию и нажмите ссылку **Start Local App** (стр. 247).
  4. В открывшейся вкладке браузера введите текст в поле `user_input` (помечено красной звёздочкой) и нажмите Enter (стр. 247).
- **Где нам пригодится:** Для запросов, проверки, памяти, помощников, данных или учёбы: Быстрое превращение прототипа агента в локальный API-сервис.

## 9.4 Оценка профилей: Рубрики и граундинг (стр. 248–252)
- **Главная мысль:** Масштабируемая оценка эффективности промптов с помощью создания вариаций, таблиц критериев (рубрик) и проверки на соответствие контексту (граундинг).
- **Правила и числа:** 
  - Варианты вариаций в prompt flow (Таблица 9.1, стр. 227 / 277): Шаблоны Jinja2 (сравнение системных и пользовательских промптов), Сама LLM (сравнение GPT-4 и GPT-4 Turbo, или локальных открытых моделей с коммерческими), Температура (сравнение 0 и 1), Максимум токенов, Продвинутые параметры (`top_p`, `presence_penalty`, `frequency_penalty`, `logit_bias`), Вызовы функций (Function calls).
  - Два варианта сбора входных данных (стр. 250): Опция A — классический UI (строгие ограничения и валидация полей), Опция Б — прокси-агент (гибкий диалог с пользователем для сбора параметров).
- **Ошибки и предупреждения:** Опция А ограничивает будущие сценарии использования, а Опция Б при большей гибкости создает больше неизвестных для оценки (стр. 250).
- **Где нам пригодится:** Для запросов, проверки, памяти, помощников, данных или учёбы: Сравнение разных версий промптов и моделей для выбора оптимальной связки.

## 9.5 Понимание рубрик и граундинга (стр. 252–254)
- **Главная мысль:** Рубрика (Rubric) — это структурированный набор критериев и стандартов для оценки ответов агента, а граундинг (Grounding) определяет, насколько ответ соответствует этим стандартам.
- **Как делать (создание рубрики):**
  1. Определите цель и задачи (Purpose and objectives) (стр. 252).
  2. Определите критерии оценки (Define criteria) (стр. 253).
  3. Создайте шкалу оценивания (Create a scale), например, от 1 до 5 (стр. 253).
  4. Опишите уровни шкалы (Provide descriptions) (стр. 253).
  5. Примените рубрику для оценки (Apply the rubric) (стр. 253).
  6. Рассчитайте общий балл (Calculate the total score), используя сумму или средневзвешенное значение (стр. 253).
  7. Обеспечьте консистентность оценки (Ensure evaluation consistency) (стр. 253).
  8. Регулярно пересматривайте и дорабатывайте рубрику (Review, revise, and iterate) (стр. 253).
- **Правила и числа:** 
  - Базовая шкала рубрики рекомендателя (Таблица 9.2, стр. 230): 1 — Плохое соответствие (Poor alignment), 2 — Двусмысленное/плохое (Bad alignment), 3 — Среднее (Mediocre alignment), 4 — Хорошее (Good alignment), 5 — Отличное (Excellent alignment).
- **Где нам пригодится:** Для запросов, проверки, памяти, помощников, данных или учёбы: Автоматизированная или ручная проверка качества работы вашего ИИ-агента.

## 9.6 Оценка граундинга с помощью профиля LLM (стр. 254–256)
- **Главная мысль:** Использование второго блока LLM для автоматической оценки и проверки ответов первого промпта по заданной рубрике без участия человека.
- **Шаблоны и примеры:** Структура оценочного промпта (Рис. 9.19, стр. 255): определение роли, критерии рубрики, шкала с описаниями, пример ожидаемого вывода. Пример вывода LLM-оценки в формате JSON: название фильма и оценки по критериям Subject (Тема), Format (Формат), Genre (Жанр) (стр. 256).
- **Ошибки и предупреждения:** При сравнении разных профилей допускается использовать ту же модель для оценки, но для глубокого граундинга часто лучше использовать другую (более сильную) модель (стр. 254–255).
- **Где нам пригодится:** Для запросов, проверки, памяти, помощников, данных или учёбы: Создание автотестов для проверки ответов вашего ИИ-помощника.

## 9.7 Сравнение профилей: Получение идеального профиля (стр. 256–263)
- **Главная мысль:** Парсинг неструктурированного текста ответа LLM в структуры данных Python, пакетная обработка (batch processing) с использованием файлов JSONL и агрегация результатов для поиска идеального промпта.

### 9.7.1 Парсинг вывода оценки LLM (стр. 256–259)
- **Как делать:**
  1. Создайте Python-файл (например, `parsing_results.py`) (стр. 256).
  2. Используйте декоратор `@tool` для превращения функции в блок prompt flow (стр. 257).
  3. Напишите код, разбивающий строковый ответ на блоки по двойному переносу строки (`\n\n`) и разделяющий строки по двоеточию (`: `) в словарь ключ-значение (Листинг 9.2, стр. 257).
- **Шаблоны и примеры:** Превращение строки `"Title: The Butterfly Effect\nSubject: 5..."` в список словарей JSON с ключами `"title"`, `"subject"`, `"format"`, `"genre"` (стр. 258).
- **Где нам пригодится:** Для запросов, проверки, памяти, помощников, данных или учёбы: Написание Python-парссеров для приведения ответов LLM к строгому JSON.

### 9.7.2 Запуск пакетной обработки в prompt flow (стр. 259–262)
- **Главная мысль:** Тестирование профилей на множестве разнообразных входных данных одновременно с помощью пакетной обработки (batch processing) файлов JSON Lines (JSONL).
- **Как делать:**
  1. Сгенерируйте с помощью ChatGPT случайный список критериев в формате JSONL (сохраните в файл, например, `bulk_recommend.jsonl` с 10 элементами) (стр. 259–260).
  2. Откройте `flow.dag.yaml` в визуальном редакторе, нажмите кнопку **Batch** (значок колбы) (стр. 260).
  3. Выберите локальный файл данных (Local Data File) (стр. 261).
  4. В созданном конфигурационном YAML-файле нажмите ссылку **Run** для запуска батча (стр. 261).
  5. Следите за логированием воркеров в терминале и откройте визуализатор результатов через расширение prompt flow (стр. 261–262).
- **Где нам пригодится:** Для запросов, проверки, памяти, помощников, данных или учёбы: Массовое тестирование промптов на датасетах перед выкатом в продакшн.

### 9.7.3 Создание потока оценки для граундинга (стр. 262–263)
- **Главная мысль:** Использование специализированного потока без LLM (только Python-блоки) для математического подсчета средних оценок (граундинга) по всем критериям рекомендаций.
- **Как делать:**
  1. Откройте поток оценки `evaluate_groundings` (стр. 262).
  2. Используйте функцию обработки строк (`line_process`), которая итерирует по словарю рекомендаций, игнорирует поле `"title"`, переводит оценки в тип `float`, считает общую сумму и вычисляет среднее арифметическое (`avg_score`) (Листинг 9.3, стр. 263).
  3. Округлите средний балл до 2 знаков (`round(avg_score, 2)`) и добавьте в словарь как оценку граундинга (стр. 263).
- **Шаблоны и примеры:** Функция `line_process(recommendations)` принимает список словарей, вычисляет средний балл (`avg_score`) по всем критериям и возвращает обогащенный список (Листинг 9.3, стр. 263).
- **Где нам пригодится:** Для запросов, проверки, памяти, помощников, данных или учёбы: Написание скриптов для математической агрегации метрик качества работы ИИ.
