## 1. Что такое *skill* (навык) (стр. —)

- **Главная мысль** – навык – это конкретная способность агента выполнять действие (от простого до сложного) и тем самым изменять мир, а не только выдавать информацию.  
- **Как делать**:  
  1. Определить задачу, которую агент должен решить.  
  2. Выделить набор действий, необходимых для её решения.  
  3. Оформить каждое действие как отдельный “skill”.  
- **Правила и числа** – нет.  
- **Шаблоны и примеры** – сравнение с компетенциями человека (врач → диагностика, лечение).  
- **Ошибки и предупреждения** – нет.  
- **Где пригодится** – при планировании функциональности агента (какие действия ему нужны).

---

## 2. Hand‑crafted (ручные) локальные навыки (стр. —)

- **Главная мысль** – это навыки, написанные разработчиком вручную, работают локально и дают полное управление, но ограничены в масштабируемости и гибкости.  
- **Как делать** (процесс создания):  
  1. Сформулировать логику, правила и пути принятия решений.  
  2. Программно реализовать их (функции, классы).  
  3. Тестировать и интегрировать в агент.  
- **Правила и числа** – **проблемы**:  
  - *Scalability* – усилия растут экспоненциально при усложнении задачи.  
  - *Flexibility* – жесткость, плохая адаптация к новым ситуациям.  
  - *Maintenance* – частые правки при изменении окружения.  
- **Шаблоны и примеры** – калькуляторные навыки:  

  ```python
  @tool
  def multiply(x: float, y: float) -> float: return x * y
  @tool
  def exponentiate(x: float, y: float) -> float: return x**y
  @tool
  def add(x: float, y: float) -> float: return x + y
  ```
  Регистрация в LangChain:

  ```python
  tools = [multiply, exponentiate, add]
  llm = ChatOpenAI(model_name="gpt-4o", temperature=0)
  llm_with_tools = llm.bind_tools(tools)
  ```
- **Ошибки и предупреждения** – не упомянуто, но подразумевается, что при росте сложности → неэффективно.  
- **Где пригодится** – задачи, где нужны точные математические операции, конверсия единиц, работа с картами/графами.

## 3. Навыки доступа к вебу (пример)

- **Главная мысль** – агентов можно снабдить способностью выполнять внешние запросы (например, к Wikipedia).  
- **Как делать**:  
  1. Создать `WikipediaAPIWrapper` и `WikipediaQueryRun`.  
  2. Привязать к LLM через `bind_tools`.  
  3. Отправить запрос пользователю, получить `tool_calls`, вызвать их, собрать ответы.  
- **Шаблон** (кратко):

  ```python
  api_wrapper = WikipediaAPIWrapper(top_k_results=1, doc_content_chars_max=300)
  tool = WikipediaQueryRun(api_wrapper=api_wrapper)
  llm = ChatOpenAI(model_name="gpt-4o", temperature=0)
  llm_with_tools = llm.bind_tools([tool])
  ```

- **Ошибки** – нет.  
- **Где пригодится** – быстрый поиск актуальной информации при ответах агента.

## 4. Дизайн навыков (Skill Design Considerations) (стр. —)

- **Главная мысль** – при проектировании навыков важно уравновешивать **generalization vs. specialization**, **robustness**, **efficiency**, **scalability**.  
- **Как делать** (проверочный чек‑лист):  

  1. **Определить уровень специализации**: один‑единственный сценарий или набор схожих задач.  
  2. **Тестировать на разнообразных входных данных** → убедиться в **robustness**.  
  3. **Оптимизировать** (алгоритмы, аппаратные ускорители) → **efficiency**.  
  4. **Планировать рост**: возможность объединения/расширения навыков → **scalability**.  

- **Правила и числа** – нет конкретных цифр.  
- **Шаблоны** – не представлены.  
- **Ошибки** – отсутствие любого из пунктов приводит к плохой работе агента.  
- **Где пригодится** – при любой разработке новых навыков.

## 5. API‑based навыки (стр. —)

- **Главная мысль** – навыки, которые вызывают внешние API, позволяют агенту получать актуальные данные и выполнять ресурсоёмкие операции без локального вычисления.  
- **Как делать** (пример “stock price”):  

  1. Описать функцию‑обёртку с `@tool`.  
  2. Внутри функции выполнить HTTP‑запрос к нужному API, обработать статус‑код.  
  3. Возвратить нужный результат (например, `price`).  
  4. Зарегистрировать функцию в `bind_tools`.  
  5. Вызвать через LLM, получить `tool_calls`, выполнить их, собрать ответ.  

  ```python
  @tool
  def get_stock_price(ticker: str) -> float:
      api_url = f"https://api.example.com/stocks/{ticker}"
      response = requests.get(api_url)
      if response.status_code == 200:
          data = response.json()
          return data["price"]
      else:
          raise ValueError(...)
  ```

- **Правила и числа** – при проектировании учитывать:  

  * **Reliability** – обработка сбоев, fallback.  
  * **Security** – HTTPS, аутентификация, авторизация.  
  * **Rate limits** – не превышать лимиты API.  
  * **Privacy** – соответствие требованиям защиты данных, анонимизация при необходимости.  
  * **Error handling** – graceful degradation при ошибках сети/ответов.  

- **Шаблоны** – вышеуказанный код.  
- **Ошибки** – игнорировать отказ API → падение агента; не соблюдать безопасность → утечка данных.  
- **Где пригодится** – любые задачи, требующие текущих данных (погода, цены, перевод, и т.п.).

## 6. Plug‑in навыки (стр. —)

- **Главная мысль** – готовые модули от площадок (OpenAI, Anthropic, Google Gemini, Microsoft Phi) и от open‑source сообществ позволяют быстро добавить функциональность без значительной разработки.  
- **Как делать** – просто «подключить» (plug‑in) к модели; детали зависят от конкретного провайдера, но общий процесс:  

  1. Выбрать нужный plug‑in (например, для NLU, генерации кода, анализа данных).  
  2. Активировать его в настройках модели (на уровне execution layer).  
  3. Вызывать в запросах так же, как обычные инструменты.  

- **Плюсы** – быстрая интеграция, масштабируемость, поддержка от платформы.  
- **Минусы** – ограниченная кастомизация и адаптируемость; общие‑назначения, не всегда подходят под уникальные бизнес‑требования.  
- **Пример экосистем** – Hugging Face Transformers, TensorFlow, PyTorch (многие готовые модели/утилиты).  
- **Ошибки** – полагаться только на plug‑in, когда нужны специфичные функции → потеря гибкости.  
- **Где пригодится** – быстрый прототип, добавление стандартных функций (перевод, распознавание изображений, аналитика).

## 7. Иерархии навыков (Skill Hierarchies) (стр. —)

- **Главная мысль** – группировать навыки в иерархию: сложные навыки → набор простых суб‑навыков. Это упрощает выбор и уменьшает конфликты (semantic collisions).  
- **Как делать** (общий алгоритм):  

  1. **Разбить** сложные задачи на подзадачи.  
  2. **Сгруппировать** связанные подзадачи в отдельные группы (например, «account management», «technical support», «billing»).  
  3. **Назначить** каждому запросу соответствующую группу, затем конкретный навык внутри группы.  
  4. **Оркестрация** (см. следующую главу) будет управлять выполнением.  

- **Ошибки** – отсутствие иерархии в больших проектах → путаница в выборе навыков.  
- **Где пригодится** – проекты с большим набором навыков (например, поддержка клиентов, где есть множество типов запросов).

## 8. Автоматическая разработка навыков (Automated Skill Development) (стр. —)

### 8.1 Real‑time Code Generation (Генерация кода в реальном времени)

- **Главная мысль** – агент может писать и исполнять код «на лету», создавая/модифицируя навыки под новые задачи.  
- **Как делать** (процесс):  

  1. Агент анализирует задачу, формулирует необходимые шаги.  
  2. На основе понимания генерирует фрагмент кода.  
  3. Пытается исполнить код.  
  4. При неудаче итеративно исправляет код, пока не получит желаемый результат.  

- **Плюсы** – адаптивность, быстрая реакция на новые API/проблемы.  
- **Риски / Ошибки** –  
  - **Quality control**: плохой код → баги, уязвимости.  
  - **Security**: возможность исполнения вредоносного кода.  
  - **Resource consumption**: высокие требования к CPU/памяти.  
  - **Ethical / regulatory**: соблюдение правовых ограничений (особенно в медицине, финансах, автотранспорте).  

### 8.2 Imitation Learning (Обучение подражанием)

- **Главная мысль** – агент учится, наблюдая за действиями человека (демонстрациями).  
- **Ключевые преимущества** – быстрая и естественная передача навыков, особенно когда формальные правила тяжело задать.  
- **Проблемы** –  
  - Недостаток демонстраций; плохое качество примеров.  
  - Трудность обобщения на новые ситуации.  
  - Требования к вычислительным ресурсам при масштабных задачах.  
- **Методы** –  
  - **Behavior cloning** (прямое копирование наблюдаемых действий).  
  - **Inverse Reinforcement Learning (IRL)** (вывод скрытой функции награды).  
  - **Generative Adversarial Imitation Learning (GAIL)** (GAN‑подобный подход).  

### 8.3 Skill Learning from Rewards (Обучение от наград, Reinforcement Learning)

- **Главная мысль** – агент обучается через проб‑и‑ошибку, получая вознаграждения/штрафы.  
- **Плюсы** – автономность, исследование (exploration), достижение оптимальности.  
- **Трудности** –  

  1. Наличие качественной среды с корректными наградами.  
  2. **Sample efficiency** – требуется много взаимодействий.  
  3. **Stability** – сложность обеспечения сходимости.  
  4. **Reward design** – плохая функция награды → нежелательное поведение.  

- **Подходы** –  

  - **Value‑based**: Q‑learning, DQN (для дискретных действий).  
  - **Policy‑based**: REINFORCE, PPO (для непрерывных действий).  
  - **Actor‑critic**: комбинация обеих, более стабильное обучение.  

- **Где пригодится** – задачи, где нельзя собрать набор демонстраций, требуются самостоятельные исследования (автономные машины, стратегии торговли, игровые боты).

## 9. Заключение (Conclusion) (стр. —)

- **Главная мысль** – навыки – фундаментальная часть агента; их типы (ручные, API‑based, plug‑in) имеют свои плюсы/минусы. Иерархия навыков упрощает управление. Автоматическое создание навыков (real‑time code gen, imitation learning, RL) делает агентов гибче и способным к самостоятельному росту. Дальше будет рассматриваться **оркестрация** – планирование, выбор и параметризация навыков.  

- **Где пригодится** – любой этап разработки, от первоначального набора функций до их динамического расширения.

## 10. Глава 5. Оркестрация (стр. —)

### 10.1 Вводная часть

- **Главная мысль** – после того как у агента есть набор навыков, необходимо их правильно сочетать, учитывать зависимости и порядок выполнения.  

### 10.2 Выбор навыка (Skill Selection)

#### 10.2.1 Generative Skill Selection (Генеративный выбор навыка)

- **Главная мысль** – модель‑основа (LLM) получает список навыков (их описания) и генерирует ответ, выбирая наиболее подходящий навык; потом сравнивают с реальным набором и берут ближайший.  
- **Как делать** (псевдокод):  

  1. Сформировать запрос к LLM, включив описание всех навыков.  
  2. Получить от LLM название выбранного навыка.  
  3. Сопоставить полученное название с реальными функциями в коде.  
  4. Вызвать соответствующий навык.  

- **Плюсы** – простота, нет необходимости в обучении/встраивании эмбеддингов.  
- **Минусы** – дополнительный вызов LLM → латентность; может потребоваться few‑shot подсказка (in‑context learning).  

- **Шаблон** (пример `wolfram_alpha` и `zapier`):

  ```python
  @tool
  def query_wolfram_alpha(expression: str) -> str: ...
  @tool
  def trigger_zapier_webhook(zap_id: str, payload: dict) -> str: ...
  @tool
  def send_slack_message(channel: str, message: str) -> str: ...
  # ... bind tools to LLM, invoke …
  ```

- **Ошибки** – избыток запросов к модели, увеличивается расход токенов и время ответа.  

- **Где пригодится** – быстрый прототип, небольшой набор навыков, отсутствие инфраструктуры для эмбеддингов.

#### 10.2.2 Semantic Skill Selection (Семантический выбор навыка)

- **Главная мысль** – каждый навык предварительно эмбеддится (преобразуется в вектор) и сохраняется в лёгкой векторной базе; при запросе пользовательского контекста тоже делается эмбеддинг, а затем поиск ближайшего вектора выбирает подходящий навык. Это быстрее и масштабируемее, чем генеративный метод.  

- **Как делать** (шаги, прямой из кода):  

  1. **Подготовка**:  
     - Выбрать модель‑эмбеддер (OpenAI ada, Titan, Cohere, BERT и т.п.).  
     - Создать словарь `tool_descriptions` (название → описание).  
  2. **Эмбеддинг описаний**:  

     ```python
     embeddings = OpenAIEmbeddings(openai_api_key=OPENAI_API_KEY)
     for tool_name, description in tool_descriptions.items():
         embedding = embeddings.embed_text(description)
         tool_embeddings.append(embedding)
         tool_names.append(tool_name)
     ```
  3. **Инициализация векторного хранилища** (FAISS):  

     ```python
     dimension = len(tool_embeddings[0])
     index = faiss.IndexFlatL2(dimension)
     faiss.normalize_L2(np.array(tool_embeddings).astype('float32'))
     index.add(np.array(tool_embeddings).astype('float32'))
     ```
  4. **Поиск** – при запросе пользователя:  

     ```python
     query_embedding = embeddings.embed_text(query).astype('float32')
     faiss.normalize_L2(query_embedding.reshape(1, -1))
     D, I = index.search(query_embedding.reshape(1, -1), top_k)
     selected_tools = [index_to_tool[idx] for idx in I[0] if idx in index_to_tool]
     ```
  5. **Определение параметров** – (в тексте часть кода не завершена, но подразумевается вызов `determine_parameters`).  

- **Плюсы** – быстрее (один вызов эмбеддера + поиск), хорошая масштабируемость, часто используется в продакшене.  
- **Минусы** – требуется отдельный процесс создания и обновления векторного индекса; нужен эмбеддер.  

- **Шаблоны** – полностью приведён в тексте (см. блок `Skill database setup`).  

- **Ошибки** – несоответствие эмбеддеров (разные модели для описаний и запросов) → плохой поиск; забыть обновлять индекс после изменения описаний навыков.  

- **Где пригодится** – любые реальные системы с десятками‑сотнями навыков, где важна скорость и предсказуемость выбора.
