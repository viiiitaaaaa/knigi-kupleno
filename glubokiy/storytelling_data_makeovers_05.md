**Конспект части 5 (стр. 182‑234) книги *Storytelling with Data* (Knaflic).**  
Каждый блок – отдельный раздел (глава/подраздел), указаны номера страниц, главная идея, практические шаги, правила, шаблоны, типичные ошибки и примеры применения для предпринимателя‑одиночки, работающего с данными, скриптами и агентами.

## 1. Storyboarding + переход к титрам (стр. 182‑183)  
- **Главная мысль:** Планировать презентацию “вручную” (стикеры, story‑board) помогает понять структуру, количество слайдов и нужные типы графиков до того, как открыть PowerPoint.  
- **Как делать:**  
  1. Сформулируйте **Big Idea** — короткое утверждение, почему аудитория должна слушать.  
  2. Разместите идеи на стикерах: каждый – одна мысль/график.  
  3. При необходимости добавьте к стикерам пометку о возможных типах графиков (цветом, напр., синий).  
  4. Если презентация сложная, нарисуйте «нарративный арк» — схему уровней вовлечения слушателя.  
  5. Проверьте storyboard коллегой, внесите правки.  
- **Правила и числа:**  
  - Не более ≈ 10‑12 слайдов (не указано в тексте, но в примере рассчитано число слайдов).  
- **Шаблоны/примеры:**  
  - Figure 9.5 — пример storyboard (разные цвета для вариантов графиков).  
- **Ошибки:** Не начинайте сразу с компьютера — это приводит к “мозольной” работе без ясного плана.  
- **Где пригодится:** При планировании любого отчёта, митинга или демо‑скрипта — быстрая визуальная проверка структуры.

## 2. Takeaway‑заголовки для слайдов (стр. 184)  
- **Главная мысль:** Каждый слайд должен иметь **однострочный, чёткий заголовок‑вывод**, который сразу сообщает основную идею.  
- **Как делать:**  
  1. Возьмите текст со стикера.  
  2. Перепишите его в виде **заголовка‑вывода** (sentence case, первая буква — заглавная, остальные — строчные).  
  3. Ограничьте заголовок одной строкой; при необходимости «отшлифуйте» слова.  
  4. Выделите ключевые слова (жирным шрифтом) при финальном оформлении.  
- **Правила:**  
  - Заголовки — sentence case (только первая буква заглавная) (стр. 184).  
  - Один‑единственный смысл на слайд → один‑единственный заголовок.  
- **Шаблон:** Figure 9.7 — пример набора заголовков‑выводов.  
- **Ошибки:** Длинные заголовки «засоряют» восприятие, заставляют аудиторию читать вместо слушать.  
- **Где пригодится:** При подготовке презентаций, обучающих модулей, скриптов‑диалогов с визуальными подсказками.

## 3. Форматирование текста и добавление поддерживающего контента (стр. 185‑187)  
- **Главная мысль:** После создания заголовков добавьте **форматирование** (жирный шрифт, увеличение размера) и **визуальные элементы** (графики, диаграммы), учитывая читаемость и визуальный баланс.  
- **Как делать:**  
  1. Пройдитесь по каждому слайду, **жирным** выделите ключевые фразы в заголовке.  
  2. Для слайдов без графиков (1‑3, 6, 11‑12) разместите текст в центре, увеличьте шрифт.  
  3. При необходимости «растяните» текст, чтобы заполнить место (не более одной строки).  
  4. Выберите фон: **пурпурный** для входных/заключительных слайдов, **тёмный** для слайдов с графиками (чтобы текст читался).  
  5. Добавьте графики:  
     - Бар‑чарт вместо таблицы (Figure 9.10).  
     - Gantt‑диаграмма вместо «крутого» таймлайна (Figure 9.12).  
  6. При необходимости разделите один график на несколько слайдов (анимация).  
- **Правила:**  
  - Не ставьте графики на тёмный фон, если в них много мелкого текста (стр. 185).  
- **Шаблоны:** Figure 9.8 — отформатированный слайд, Figure 9.10 — бар‑чарт, Figure 9.12 — Gantt‑диаграмма.  
- **Ошибки:** Слишком много данных в таблице → неочевидная «проблема»; неуместный цвет фона.  
- **Где пригодится:** При создании клиентских отчётов, дашбордов, обучающих материалов.

## 4. Финальные слайды + рассказ (стр. 188‑194)  
- **Главная мысль:** Привязывайте каждый визуальный элемент к заранее продуманному заголовку‑выводу, а также **приводите разговорные «talking points»** для живого объяснения.  
- **Как делать:**  
  1. Добавьте бар‑чарт и Gantt‑диаграмму к соответствующим слайдам (Figure 9.13).  
  2. При необходимости покажите части графика на разных слайдах → анимация (слайды 7‑10).  
  3. Сформулируйте **скрипт** для каждой части (пример – текст Figure 9.14‑9.25).  
  4. Завершите слайд‑презентацию «call‑to‑action» (Figure 9.25).  
- **Шаблоны:**  
  - Figure 9.14 — ввод с ощущением срочности.  
  - Figure 9.15‑9.25 — последовательные «talking points».  
- **Ошибки:** Переход сразу от идеи к компьютеру, без проверки аудитории, приводит к неэффективной коммуникации.  
- **Где пригодится:** При подготовке встречи с инвесторами, клиентскими презентациями, обучением команды.

## 5. Краткое резюме процесса (стр. 195‑198)  
- **Главная мысль:** Пять‑шаговый метод от идеи к готовой визуализации:  
  1. **Craft a persuasive and succinct message** — сформулировать Big Idea.  
  2. **Shape your story offline** — storyboard, low‑tech.  
  3. **Move from low tech to tools through titles** — заголовки‑выводы.  
  4. **Format the text and add supporting content** — выбор графиков, оформление.  
  5. **(Не описано отдельно, но подразумевается — тестировать/получать обратную связь).**  
- **Шаблоны:** список в тексте (стр. 197‑198).  
- **Ошибки:** Не прописывайте «следующие шаги» явно; не ограничивайтесь одной версией слайдов.  
- **Где пригодится:** При подготовке любой презентации, отчёта, обучающего курса.

## 6. Простые графики vs. сложные сообщения (стр. 199‑200)  
- **Главная мысль:** **Простые графики не гарантируют простого сообщения** – контекст и объяснение обязательны.  
- **Ключевые пункты:**  
  - Дизайн для себя → «проклятие знания» (стр. 200).  
  - Слишком много данных в простом графике → путаница (пример «wolf in sheep’s clothing»).  
- **Ошибки:** Убирая контекст, даже чистый бар‑чарт может вводить в заблуждение.  
- **Где пригодится:** При подготовке быстрых дашбордов, инфографики, клиентских обзоров.

## 7. Пример – Mellow Bean: «What? → So what? → Now what?» (стр. 201‑206)  
- **Главная мысль:** Для каждой визуализации нужно ответить **три вопроса**:  
  1. **What?** — что показывается.  
  2. **So what?** — почему это важно.  
  3. **Now what?** — какое действие следует предпринять.  
- **Как делать (пошагово):**  
  1. Добавьте **заголовок** и **определение** (ADS = Average Daily Sales).  
  2. Перепишите подписи баров, укажите конкретные сравнения (Figure 10.2).  
  3. Добавьте **контекст** под заголовком (рост продаж в сентябре, цель) – Figure 10.3.  
  4. Вставьте **рекомендацию** внизу слайда – Figure 10.4.  
- **Ошибки:** Пропуск контекста; отсутствие «Now what?».  
- **Где пригодится:** Для клиентских рекомендаций, бизнес‑отчетов, скриптов продаж.

## 8. Не заменяй — добавляй новое (стр. 206‑208)  
- **Главная мысль:** Если заказчик требует «старый» формат (gap‑analysis), **не убирайте** его, а **дополни** более понятной визуализацией.  
- **Как делать:**  
  1. Оставьте оригинальный график (gap‑analysis), но **поверните** его 90° и уменьшите (Figure 10.6).  
  2. Поставьте рядом **новый бар‑чарт** с реальными среднедневными продажами (Figure 10.5).  
  3. Используйте цвет и позицию, чтобы первая (большая) диаграмма привлекала внимание, а вторая – давала дополнительную глубину.  
- **Правила:** Добавляйте, а не удаляйте, чтобы не «разрушать» привычный контекст клиента.  
- **Ошибки:** Полное удаление требуемого формата → сопротивление клиента.  
- **Где пригодится:** При работе с клиентскими требованиями к формату отчётов, соблюдая их нужды и улучшая читаемость.

## 9. Обобщённые выводы «What? → Now what?» (стр. 211‑212)  
- **Главная мысль:** Четко сформулируйте три вопроса и соблюдайте простоту визуалов.  
- **Кратко:**  
  - *Simple charts + complex messages → путаница.*  
  - *Make next steps explicit.*  
  - *Don’t replace – augment.*

## 10. Пять типичных ошибок в визуализации (стр. 212‑230)  

### 10.1 Ошибка #1 — «Слишком много данных в одном графике» (стр. 213‑215)  
- **Суть:** Плотный график заставляет аудиторию тратить усилия на разбор.  
- **Как исправлять:** Делить данные на несколько графиков, каждый — одна идея.  
- **Пример:** Исходный график (Figure 11.1) → два графика рядом (Figure 11.2).  

### 10.2 Ошибка #2 — «Неподходящий тип графика» (стр. 216‑219)  
- **Суть:** Выбор типа графика, не соответствующего данным (например, вертикальные столбцы для тренда).  
- **Как исправлять:** Перейти к линейному графику для тренда (Figure 11.3) и к 100 % stacked bar для долей (Figure 11.4).  

### 10.3 Ошибка #3 — «Игнорирование структуры графика» (стр. 218‑220)  
- **Суть:** Плохие подписи, слишком яркие рамки, несогласованные оси.  
- **Как исправлять:** Убрать лишние линии, добавить подписи и названия осей, использовать серый цвет для вспомогательных элементов, разместить легенду рядом с графиком (Figure 11.6).  

### 10.4 Ошибка #4 — «Недооценка силы цвета» (стр. 221‑225)  
- **Суть:** Цвета либо слишком яркие/много, либо схожие и неразличимые.  
- **Как исправлять:**  
  - Выделять ключевой сегмент (2025‑й год) красным/ярко‑красным (Figure 11.8).  
  - При брендовом ограничении использовать контрастные оттенки (purple, electric blue, teal) и добавить белую кайму для читаемости (Figure 11.10‑11.11).  

### 10.5 Ошибка #5 — «Создание одной версии слайдов» (стр. 226‑230)  
- **Суть:** Одна «универсальная» версия слишком лаконична для рассылки и слишком перегружена для живой презентации.  
- **Как исправлять:**  
  1. **Презентация:** минимум текста, буллеты, анимация графиков.  
  2. **Электронный дистрибутив:** полные предложения, пояснительный текст под графиками.  
  3. Пример: Figure 11.12 (презентация) → Figure 11.13 (документ).  

- **Где пригодится:** При подготовке отчётов для совета директоров и их последующей отправки клиентам/партнёрам.

## 12. Ключевые уроки для предпринимателя‑одиночки (стр. 234)  
- **Time constrained:** ищите стороннюю точку зрения.  
- **Template constrained:** адаптируйте под жирные (яркие) фоны.  
- **Space constrained:** впишите всё в один слайд, если нужно.

### Как использовать эти подсказки в работе с ИИ‑помощником Claude  
- **Запросы к Claude:** «Смоделируй storyboard для моего проекта X, используя стикеры‑титулы, и предложи 3‑5 вариантов графиков».  
- **Проверка готового слайда:** «Проверь, есть ли в моём слайде заголовок‑вывод в sentence case и выделены ли ключевые слова».  
- **Память:** Храни в базе «правила оформления (sentence case, один‑единственный вывод)», «список типичных ошибок #1‑#5».  
- **Помощники/агенты:** Автоматический конвертер таблиц → бар‑чарт; скрипт, который разбивает единый график на несколько слайдов‑анимаций.  
- **Обучение:** Применяй метод «What → So what → Now what» при подготовке учебных материалов, чтобы каждый слайд сопровождался чёткой рекомендацией к действию.
