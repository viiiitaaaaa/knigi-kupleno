## Создание агентов с LlamaIndex (стр. 240–245)
- **Главная мысль**: LlamaIndex позволяет создавать продвинутых агентов, которые используют набор инструментов (поиск, калькулятор, RAG) для решения многошаговых задач.
- **Как делать**:
    1. **Определить инструменты**: использовать класс `FunctionTool` (например, для интеграции с поиском Tavily).
    2. **Выбрать «мозг»**: назначить LLM (в примере — Claude Sonnet 4.5).
    3. **Настроить агента**: использовать `FunctionAgent`, задав список инструментов и `system_prompt` (инструкции по поведению).
    4. **Запустить процесс**: через `agent.run` с передачей контекста (`ctx`) для хранения истории переписки.
    5. **Отслеживать шаги**: использовать `stream_events()`, чтобы видеть в реальном времени: ввод $\rightarrow$ вызов инструмента $\rightarrow$ результат $\rightarrow$ финальный ответ.
- **Правила и числа**:
    - Для веб-поиска рекомендуются «агентские сервисы» (Tavily, Exa), которые отдают данные в Markdown или JSON, а не просто ссылки (стр. 240).
- **Шаблоны и примеры**:
    - *Пример задачи*: Планирование поездки в Санта-Круз (поиск активностей $\rightarrow$ расчет стоимости $\rightarrow$ создание маршрута на 6 часов).
- **Ошибки и предупреждения**: Для продакшена обязательно добавлять таймауты, политики повторов (retry), логирование всех вызовов и мониторинг, чтобы агент не попал в «бесконечный цикл» вызовов инструментов (стр. 240).
- **Где нам пригодится**: Для создания персональных помощников, которые сами ищут информацию в сети и делают расчеты.

## Создание агента с Vectara (стр. 245–249)
- **Главная мысль**: В отличие от библиотек (LangChain/LlamaIndex), Vectara — это управляемая платформа (turnkey), где инфраструктура и цикл работы агента уже настроены.
- **Как делать**:
    1. **Загрузить данные**: через API `upload_file` (автоматически парсит PDF, таблицы и изображения).
    2. **Настроить инструмент**: определить `tool_configurations` (например, поиск по корпусу с указанием лимитов и реранкера).
    3. **Создать агента**: одним API-запросом задать имя, описание, модель (например, gpt-4o) и системные инструкции.
    4. **Запустить сессию**: создать сессию через API $\rightarrow$ отправить запрос $\rightarrow$ получить ответ.
- **Где нам пригодится**: Когда нет времени/ресурсов на поддержку своей инфраструктуры и нужно быстрое решение «под ключ» для работы с данными.

## Мультиагентные системы с CrewAI (стр. 249–253)
- **Главная мысль**: Сложные задачи лучше решать не одним «супер-агентом», а командой узкоспециализированных агентов, которые передают результаты друг другу.
- **Как делать**:
    1. **Определить роли**: создать агентов с четкой ролью (`role`), целью (`goal`) и предысторией (`backstory`).
    2. **Разбить задачу на подзадачи**: создать объекты `Task` с описанием и ожидаемым результатом (`expected_output`).
    3. **Настроить зависимости**: через параметр `context` указать, что одна задача начинается только после завершения другой.
    4. **Запустить «экипаж» (Crew)**: объединить агентов и задачи, выбрав процесс (например, `sequential` — последовательный).
- **Правила и числа**:
    - Подход «смесь агентов» (Mixture-of-Agents) позволяет делегировать простые задачи дешевым моделям (GPT-4o-mini), что снижает расходы на 80–90% (стр. 252).
- **Преимущества перед одним агентом**:
    - **Решение «бутылочного горлышка» инструментов**: меньше инструментов на одного агента $\rightarrow$ меньше путаницы и галлюцинаций.
    - **Когнитивная точность**: маленькие контексты для каждого агента $\rightarrow$ выше точность (избегаем эффекта «потери в середине»).
    - **Отказоустойчивость**: сбой одного агента не всегда обрушивает всю систему.
- **Где нам пригодится**: Для сложных контент-воронок (например: Аналитик ищет тренды $\rightarrow$ Копирайтер пишет статью).

## Память агентов (Agentic Memory) (стр. 253–255)
- **Главная мысль**: Память превращает агента из «одноразового» инструмента в постоянного ассистента, который знает пользователя.
- **Типы памяти**:
    1. **Краткосрочная (Рабочая)**: хранит данные внутри одной сессии (текущий диалог). Реализуется через «скользящее окно» истории.
    2. **Долгосрочная**: сохраняет данные между сессиями (предпочтения, стиль кода). Реализуется через векторные базы данных.
- **Как улучшить**:
    - **Консолидация сессий**: периодическое сжатие истории диалога в краткое резюме (снижает затраты токенов и повышает точность).
    - **Семантический поиск**: поиск по старым воспоминаниям и вставка их в текущий контекст.
- **Ошибки и предупреждения (Риски)**:
    - *Приватность*: необходимость реализации удаления данных по требованию (GDPR).
    - *Отравление памяти*: риск сохранения вредоносных инструкций (инъекций). Решение — «шлюз валидации» (вторая легкая LLM проверяет факт перед записью в память).
    - *Устаревание*: данные имеют срок годности $\rightarrow$ нужна политика «затухания» (decay policy).
- **Где нам пригодится**: Для создания «второго мозга» или ассистентов, которые помнят ваши предпочтения и историю проектов.

## Оценка и наблюдаемость (Observability) (стр. 255–264)
- **Главная мысль**: Обычного мониторинга серверов (CPU, RAM) недостаточно; агент может быть «здоров» технически, но выдавать полную чушь.
- **Типы сбоев агентов**:
    - *Галлюцинации*: инструментальные (поверил ложному ответу инструмента) или ответные (инструмент прав, но агент исказил данные).
    - *Ошибки планирования*: шаги перепутаны или неполны.
    - *Неправильное использование инструментов*: выбор не того инструмента или неверные аргументы.
    - *Сбои завершения*: агент либо остановился слишком рано, либо зациклился.
- **Как контролировать (Agentic Observability)**:
    - **Трассировка (Tracing)**: запись всей цепочки событий (spans). Позволяет увидеть: какой промпт был отправлен $\rightarrow$ какой инструмент вызван $\rightarrow$ что он вернул.
    - **Специфические метрики**:
        - Расход токенов (контроль затрат).
        - Задержка вывода (Latency).
        - Частота передачи задачи человеку (Human handoff rate).
        - Успешность вызовов инструментов.
- **Инструменты**:
    - Стандарт **OpenTelemetry (OTel)** — позволяет менять платформы мониторинга без переписывания кода.
    - Платформы: Langfuse, Arize Phoenix, LangSmith.
- **Где нам пригодится**: Для отладки сложных скриптов и понимания, почему агент «тупит» или тратит слишком много денег.

## Мультимодальный RAG (стр. 263–264)
- **Главная мысль**: Данные в компаниях — это не только текст, но и таблицы, изображения, аудио.
- **Два подхода к реализации**:
    1. **Конверсионный**: перевод всего в текст (через распознавание речи ASR или Vision-модели VLM).
    2. **Нативный**: использование моделей, которые изначально понимают разные типы данных в одном пространстве (Multimodal LLMs).
- **Где нам пригодится**: Если в данных есть скриншоты, PDF-таблицы или записи звонков.
