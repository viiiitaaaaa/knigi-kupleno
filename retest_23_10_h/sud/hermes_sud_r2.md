# Проба 23.10: Hermes как судья на Hall r2 (30 ответов), сравнение с судьёй Sonnet
Sonnet: 29 из 30 (FAIL только S-5). Hermes: PASS 15, FAIL 15 — совпало с Sonnet 16 из 30.
Hermes PASS: 2,4,8,11,12,16,18,19,22,24,25,26,27,28,30. FAIL: 1,3,5,6,7,9,10,13,14,15,17,20,21,23,29.
Причины Hermes часто нелогичны: «ответ добавил своё предложение», «нет полного перечня элементов», «упомянул НЛП» — то есть штрафует за адаптацию, которая по ключу как раз нужна; в S-14, S-7 говорит про техники, которых в ответе может не быть (не проверено).
Вывод: как судья «PASS/FAIL по ключу» Hermes слишком строг и ненадёжен; годится только на формальное (есть ли поле, длина, нет ли запретных фраз), не на смысл.

## Gemini (gemini-3.5-flash-lite, по одному запросу) и проверяльщик
Gemini: PASS 25/30, совпало с Sonnet 24/30 (расхождения 2,3,5,7,10,14; файл gemini_sud_r2.md). Ключ — переменная Windows GEMINI_API_KEY; 3 запроса сразу дают 429, слать по одному.
Проверяльщик по тексту книги на спорных 3,5,7,10,14: Sonnet прав в 4 из 5 (3,7,10,14 — PASS); S-5 «на грани», FAIL строже ключа. Gemini/Hermes придираются к названию приёма, а не к смыслу.
Вывод: Gemini — быстрый первый фильтр (флагует кандидатов на FAIL), окончательно — Sonnet/проверяльщик. Hermes — не судить смысл.
