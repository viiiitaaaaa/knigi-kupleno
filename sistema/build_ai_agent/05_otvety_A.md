## A1

Агент — это программа, которая сама делает шаги к цели, пока не скажет «готово».
Внутри три части: «мозг» (модель вроде Claude), «руки» (инструменты: открыть сайт, записать файл) и «цикл» (сделала шаг, посмотрела результат, сделала следующий).
Это похоже на помощницу: ты говоришь «найди поставщиков», а она сама ходит по сайтам и приносит список.

С чего начать (общее правило из нашего скилла, не из книги):
1. Сначала сверим, что у нас уже есть. Для новостей и поставщиков у нас уже стоят скиллы (tg-news, sourcing-1688, vendor-check); сверь по списку скиллов, не строить второй раз.
2. Начни с одной задачи, не с «агента на всё». Например, только новости.
3. Повторяющиеся шаги (собрать посты, посчитать) — обычным скриптом. Модель — только там, где нужно думать: отобрать и написать итог.
4. В задаче заранее напиши «готово = …» и потолок шагов (например, не больше 2 попыток на сайт).
5. Результат проверяй сама или скриптом («совпало N из M»), а не словом агента «готово».

Не знаю: какой именно инструмент лучше собрать под твои поставщиков — это зависит от того, какие сайты и какие данные. Ключи и пароли агенту в чат не давай, их кладут в переменную Windows, об этом позже.

Как это выглядит на пальцах (идея, общее правило, не из книги):
- Память прошлых прогонов — это обычный файл-журнал: «что пробовал, что получилось, что нет».
- Перед новым прогоном агент читает журнал, после — дописывает в него.
- Исправление ошибок — не «сам решает всё», а: попытка, проверка скриптом, одна новая попытка, потом стоп и доклад тебе.

```python
with open("журнал.txt", "a") as f:   # открыть файл-тетрадь и дописывать в конец
    f.write("сайт X не открылся, попытка 2\n")   # записать одну строку в тетрадь
for попытка in range(2):   # for — повтори; range(2) — два раза и не больше
```

`for` — «повтори»; `range(2)` — потолок попыток; `open(..., "a")` — открыть тетрадь, `"a"` — дописывать, не стирать.

Риск: журнал растёт, агент может «выучить» неправильный урок. Журнал правишь ты, раз в неделю.

Почему так бывает (общее правило скилла, не из книги): каждый следующий шаг тащит весь прошлый разговор, поэтому длинная ночная работа дорожает с каждым кругом. Пауза дольше часа сбрасывает кэш, и всё читается заново по полной цене.

Как не повторить:
1. Потолок шагов и «готово = …» в задаче; три неудачи подряд значит стоп и доклад.
2. Кнопки и чтение — Haiku или Sonnet, Opus только ставит задачу.
3. Effort у помощников не max, средний.
4. Длинный разговор вовремя сжимать или начать новую сессию.
5. Ночью только то, что можно откатить; остальное днём при тебе.

Проверка: утром смотри журнал, что он делал, не только «готово». Если лимит 70% — остановить агентов.

## A6

«Описать инструмент» значит написать для агента короткую инструкцию, как карточку для нового сотрудника. Агент не видит код. Он видит только название и описание. По описанию он решает, брать ли инструмент и что в него подать.

Пример, поиск по сайту поставщика (общее правило, не из книги). Описание по-русски:

- Название: `iskat_na_sayte_postavshchika`
- Что делает: ищет товары на сайте поставщика по слову.
- Что принимает: `zapros` (слово, например «юбка клетка») и `limit` (сколько результатов, по умолчанию 10).
- Что возвращает: список из названия, цены, ссылки. Если ничего нет, пишет «данных нет».
- Когда не использовать: чтобы войти в кабинет или оплатить, для этого есть другой путь.
- Если сайт не открылся: назови это точно и остановись, не придумывай цены.

В коде это выглядит так, три главных строки:

```python
def iskat_na_sayte_postavshchika(zapros, limit=10):   # def — «создать инструмент»; в скобках — что он принимает
    """Ищет товары на сайте по слову. Если пусто, пишет «данных нет»."""   # это и есть описание, его читает агент
    ...
```

Плохое описание: «ищет». Агент не поймёт, что подать и что получит, и начнёт гадать (это одна из причин зацикливания).

Сайт публичный (🟢), но пароли и ключи в описание не пишут.
