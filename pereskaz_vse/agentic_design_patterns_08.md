## Appendix A. Advanced Prompting Techniques / Приложение A. Продвинутые техники промптинга

#### Главная мысль автора

Эффективное использование языковых моделей в составе автономных ИИ-агентов требует перехода от простых текстовых запросов к систематической инженерии промптов и контекста (Context Engineering), основанной на строгих принципах, структурировании вывода, методах явного рассуждения (CoT, ToT, Self-Consistency, Step-Back) и операционных циклах действия (ReAct, Tool Calling).

#### Ключевые формулировки автора

1. *"Prompting, the primary interface for interacting with language models, is the process of crafting inputs to guide the model towards generating a desired output."* — «Промптинг, основной интерфейс взаимодействия с языковыми моделями, представляет собой процесс создания входных данных для направления модели к генерации желаемого результата.»
2. *"The objective of prompt engineering is to consistently elicit high-quality responses from language models."* — «Цель инженерии промптов состоит в том, чтобы стабильно получать высококачественные ответы от языковых моделей.»
3. *"Context engineering expands this scope to include several layers of information... ultimate quality of a model's output depends more on the richness of the provided context than on the model's architecture."* — «Контекстная инженерия расширяет этот охват, включая несколько уровней информации... итоговое качество вывода модели больше зависит от богатства предоставленного контекста, чем от архитектуры самой модели.»

#### Introduction to Prompting / Введение в промптинг

##### Мысли автора по порядку

* Промптинг служит базовым интерфейсом взаимодействия с языковыми моделями через структурирование запросов, предоставление контекста и демонстрацию примеров.
* Качество ответа прямо зависит от промпта: плохо сконструированные промпты приводят к двусмысленности и ошибкам.
* Понимание архитектурных паттернов агентов (планирование, память, инструменты) бесполезно без умения формировать эффективные промпты.

#### Core Prompting Principles / Основные принципы промптинга

##### Мысли автора по порядку

* **Clarity and Specificity (Ясность и специфика):** Исключение двусмысленности, чёткое определение задачи, формата вывода и ограничений.
* **Conciseness (Лаконичность):** Прямые инструкции без лишних сложных конструкций, которые путают модель.
* **Using Verbs (Использование глаголов действия):** Прямые глаголы в повелительном наклонении активируют нужные паттерны модели.
  * *Список 28 эффективных глаголов действия**:* Act (действуй), Analyze (анализируй), Categorize (категоризируй), Classify (классифицируй), Contrast (противопоставляй), Compare (сравнивай), Create (создавай), Describe (описывай), Define (определяй), Evaluate (оценивай), Extract (извлекай), Find (находи), Generate (генерируй), Identify (идентифицируй), List (составляй список), Measure (измеряй), Organize (организуй), Parse (парьси), Pick (выбирай), Predict (прогнозируй), Provide (предоставляй), Rank (ранжируй), Recommend (рекомендуй), Return (возвращай), Retrieve (извлекай), Rewrite (переписывай), Select (выбирай), Show (показывай), Sort (сортируй), Summarize (резюмируй), Translate (переводи), Write (пиши).
* **Instructions Over Constraints (Инструкции вместо ограничений):** Указание того, что *нужно* сделать, работает эффективнее, чем массив запретов того, чего делать *нельзя*.
* **Experimentation and Iteration (Экспериментирование и итерация):** Инженерия промптов — итеративный процесс с тестированием, анализом ошибок и подбором параметров (температура, top-p).

#### Basic Prompting Techniques / Базовые техники промптинга

##### Мысли автора по порядку

* **Zero-Shot Prompting:** Модели дается задача без примеров. Подходит для стандартных задач (простой перевод, суммаризация) .
  * *Что делает пример промпта:* просит перевести предложение с английского на французский без демонстрационных пар.
* **One-Shot Prompting:** Предоставление одного демонстрационного примера пара «вход-выход» перед целевой задачей для задания формата и тона.
  * *Что делает пример промпта:* показывает перевод слова "Thank you" -> "Gracias", после чего запрашивает перевод слова "Please".
* **Few-Shot Prompting:** Предоставление **3–5** примеров «вход-выход».
  * *Важность качества и разнообразия примеров:* ошибки в примерах сбивают модель.
  * *Перемешивание классов (Mixing Up Classes):* случайный порядок категорий в примерах предотвращает переобучение на последовательность.
  * *Evolution to "Many-Shot" Learning:* современные модели с длинным контекстом (например, Gemini) эффективно обучаются на **сотнях** примеров прямо в промпте.
  * *Что делает пример промпта:* демонстрирует классификацию тональности рецензий к фильмам на **3** класса (POSITIVE, NEUTRAL, NEGATIVE) перед классификацией нового отзыва.

#### Structuring Prompts / Структурирование промптов

##### Мысли автора по порядку

* **System Prompting:** Задает базовые правила, ограничения безопасности и операционные параметры (например, "You are a technical writer").
* **Role Prompting:** Назначает модели конкретную персонаж-роль или уровень экспертности (например, "Act as a seasoned travel blogger").
* **Using Delimiters:** Использование разделителей (```, <instruction>, <context>, ---) четко разграничивает инструкции, внешние данные и пользовательский ввод.
  * *Что делает пример промпта:* оборачивает инструкцию в тег <instruction>, а текст статьи в тег <article>.
* **Contextual Engineering (Контекстная инженерия):**
  * Охватывает **3 слоя информации**:
    1. *System prompts:* фундаментальные операционные правила.
    2. *External data:* извлеченные документы (RAG) и результаты вызова инструментов (Tool outputs).
    3. *Implicit data:* идентификация пользователя, история взаимодействия и состояние среды (требует строгого управления приватностью).
  * Для автоматической оптимизации промптов используется инструмент Vertex AI Prompt Optimizer.
* **Structured Output (Структурированный вывод):**
  * Требование вывода в машиночитаемых форматах (JSON, XML, CSV, Markdown) снижает риск галлюцинаций.
  * *Что делает пример промпта:* извлекает имя, адрес и телефон из текста в виде JSON-объекта с ключами "name", "address", "phone_number".
  * *Leveraging Pydantic:* определение Pydantic-моделей в Python создает строго валидированный объектно-ориентированный фасад поверх генерируемого текста.

#### Reasoning and Thought Process Techniques / Техники рассуждения и мыслительного процесса

##### Мысли автора по порядку

* **Chain of Thought (CoT):** Явное побуждение модели генерировать промежуточные шаги перед итоговым ответом.
  * *Zero-Shot CoT:* добавление фразы *"Let's think step by step"*.
  * *Few-Shot CoT:* демонстрация примеров с пошаговыми математическими или логическими выводами.
  * *Рекомендация:* установка температуры в **0** (greedy decoding) для математических задач с единым точным ответом.
* **Self-Consistency (Самосогласованность):** Генерация множества параллельных путей рассуждения для одной задачи и выбор наиболее частый/согласованного ответа (majority vote).
* **Step-Back Prompting:** Модель сначала просят выделить общие принципы или концепции высшего уровня (сделать "шаг назад"), а затем применить их к конкретной задаче.
  * *Пример (Детектив):* Промпт 1 извлекает **5** факторов хорошего детектива -> Промпт 2 использует эти **5** факторов для составления сюжета.
* **Tree of Thoughts (ToT):** Построение дерева мыслей с ветвлением, оценкой перспективности промежуточных узлов и возможностью отката (backtracking).

#### Action and Interaction Techniques / Техники действия и взаимодействия

##### Мысли автора по порядку

* **Tool Use / Function Calling:** Модель анализирует описание функции и аргументов, определяя необходимость вызова инструмента, и генерирует структурированный JSON-запрос.
  * *Что делает пример промпта:* передает описание функции get_current_weather с параметром city. На запрос пользователя "What's the weather like in London right now?" модель возвращает JSON-вызов инструмента с аргументом "London".
* **ReAct (Reason & Act):** Пошаговый цикл *Thought (рассуждение) -> Action (вызов инструмента) -> Observation (получение результата) -> Thought...* до получения финального ответа.

#### Advanced Techniques / Продвинутые техники

##### Мысли автора по порядку

* **Automatic Prompt Engineering (APE):** Использование "мета-модели" для авто-генерации и оценки кандидатов промптов по метрикам BLEU/ROUGE.
* **Programmatic Prompt Optimization (DSPy):** Фреймворк DSPy оптимизирует промпты как программные модули на базе:
  1. *Goldset:* эталонного датасета пар вход-выход.
  2. *Objective function:* функции оценки качества.
  3. *Bayesian optimizer:* оптимизатора, подбирающего лучшие few-shot примеры и формулировки инструкций.
* **Iterative Prompting / Refinement:** Человеко-управляемый цикл последовательного уточнения промпта.
* **Providing Negative Examples:** Демонстрация недопустимых вариантов вывода (что делать *нельзя*).
* **Using Analogies:** Использование аналогий для сложных ролей (например, "data chef", готовый выдать "summary dish").
* **Factored Cognition / Decomposition:** Разбиение сложной цели на независимые подзадачи (например, составление плана статьи -> генерация каждого раздела по отдельности -> сборка и вывод).
* **Retrieval Augmented Generation (RAG):** Извлечение релевантных чанков из базы знаний и добавление их в промпт.
* **Persona Pattern (User Persona):** Описание целевой аудитории ответа (например, "Explain quantum physics to a high school student").

## Appendix B. AI Agentic Interactions: From GUI to Real World Environment / Приложение B. Взаимодействие ИИ-агентов: от GUI к реальному миру

#### Главная мысль автора

ИИ-агенты эволюционируют от текстовых интерфейсов к визуальному управлению графическими интерфейсами ПО (GUI/ACI) на компьютерах и прямому мультимодальному восприятию физического мира через сенсоры, а также к парадигме интуитивной разработки кода (Vibe Coding).

#### Ключевые формулировки автора

1. *"These interfaces allow AI to interact directly with a computer's Graphical User Interface (GUI), enabling it to perceive and manipulate visual elements like icons and buttons just as a human would."* — «Эти интерфейсы позволяют ИИ взаимодействовать напрямую с графическим интерфейсом пользователя (GUI) компьютера, позволяя ему воспринимать и манипулировать визуальными элементами, такими как иконки и кнопки, так же, как это делал бы человек.»
2. *"By using the visual 'front door' of software, AI can now automate complex digital tasks in a more flexible and powerful way..."* — «Используя визуальную "парадную дверь" программного обеспечения, ИИ теперь может автоматизировать сложные цифровые задачи более гибким и мощным способом...»
3. *"Vibe coding moves away from precise, step-by-step instructions and instead relies on a more intuitive, conversational, and iterative interaction between the developer and an AI coding assistant."* — «Vibe coding отходит от точных пошаговых инструкций и вместо этого опирается на более интуитивное, разговорное и итеративное взаимодействие между разработчиком и ИИ-ассистентом по кодингу.»

#### Interaction: Agents with Computers / Взаимодействие: Агенты с компьютерами

##### Мысли автора по порядку

* Концепция **Agent-Computer Interfaces (ACIs)** позволяет агентам работать с программами через "парадную дверь" GUI без необходимости наличия API.
* **4 этапа взаимодействия ACI:**
  1. *Visual Perception:* снятие скриншота экрана.
  2. *GUI Element Recognition:* распознавание интерактивных элементов (кнопки, текстовые поля, иконки).
  3. *Contextual Interpretation:* интерпретация смысла элементов с помощью LLM/VLM.
  4. *Dynamic Action and Response:* программное управление мышью и клавиатурой (клики, ввод, скроллинг) с отслеживанием изменений.
* **Проекты и примеры:**
  * *Google Project Mariner:* исследовательский агент внутри браузера Chrome, способный автономно искать и выгружать предложения по аренде **3** квартир в рамках заданного бюджета.
  * *Anthropic's Computer Use:* прямая работа модели Claude с десктопом (чтение PDF -> расчеты в таблице -> построение диаграммы -> вставка в письмо).

#### Interaction: Agents with the Environment / Взаимодействие: Агенты со средой

##### Мысли автора по порядку

#### Vibe Coding: Intuitive Development with AI / Vibe Coding: Интуитивная разработка с помощью ИИ

##### Мысли автора по порядку

* **Vibe Coding:** новая парадигма разработки ПО, при которой программист задает общее направление ("vibe") и естественный контекст, а ИИ генерирует и переписывает код.
* **3 ключевых компонента:**
  1. *Conversational Prompts:* высокоуровневые описания стиля (например, "создай современный лендинг" или "сделай функцию более Pythonic").
  2. *Iterative Refinement:* диалоговая доработка деталей в реальном времени.
  3. *Optional Memory Banks:* сохранение стиля кодинга, требований и ограничений проекта в базах памяти.

## Appendix C. Quick Overview of Agentic Frameworks / Приложение C. Краткий обзор агентских фреймворков

#### Главная мысль автора

Современный ландшафт агентских фреймворков предлагает спектр инструментов — от низкоуровневых библиотек управления линейными цепочками (LangChain) и циклических машин состояний (LangGraph) до высокоуровневых платформ оркестрации команд специализированных агентов (Google ADK, CrewAI) и узкоспециализированных фреймворков (LlamaIndex, AutoGen, MetaGPT).

#### Ключевые формулировки автора

1. *"LangChain is a framework for developing applications powered by LLMs. Its core strength lies in its LangChain Expression Language (LCEL), which allows you to 'pipe' components together into a chain."* — «LangChain — это фреймворк для разработки приложений на базе LLM. Его главная сила заключается в языке LangChain Expression Language (LCEL), который позволяет объединять компоненты в конвейерную цепочку.»
2. *"LangGraph is a library built on top of LangChain... Its main advantage is the ability to create cycles, allowing the application to loop, retry, or call tools in a flexible order until a task is complete."* — «LangGraph — это библиотека, построенная поверх LangChain... Ее главное преимущество — способность создавать циклы, позволяя приложению повторять действия, делать повторные попытки или вызывать инструменты в гибком порядке до завершения задачи.»
3. *"While LangGraph gives you the detailed tools to design the intricate wiring of a single robot or a team, Google's ADK gives you a factory assembly line designed to build and manage a fleet of robots that already know how to work together."* — «В то время как LangGraph дает вам детальные инструменты для проектирования сложной проводки одиночного робота или команды, Google ADK предоставляет заводскую сборочную линию, предназначенную для создания и управления флотом роботов, которые уже умеют работать вместе.»

#### LangChain vs. LangGraph / Сравнение LangChain и LangGraph

##### Мысли автора по порядку

* **LangChain:** ориентирован на линейные направленные ациклические графы (DAG) через синтаксис LCEL (chain = prompt | model | output_parser).
* **LangGraph:** построен поверх LangChain для реализации сложных циклических процессов с явным управлением объектом состояния (State), поддержкой петель, ретраев и Human-in-the-Loop.

*Сравнение LangChain и LangGraph:*

| Feature / Характеристика | LangChain | LangGraph |

#### Google's ADK / Google ADK

##### Мысли автора по порядку

* Google ADK предоставляет готовые шаблоны оркестрации команд агентов (SequentialAgent, ParallelAgent, LoopAgent), абстрагируя ручное конструирование графов.
* Аналогия автора: LangGraph — инструменты для ручной прокладки проводки робота; Google ADK — сборочный конвейер завода для управления целым флотом роботов.

##### Что делает пример кода (без самого кода)

* Инициализирует агента dice_agent на базе gemini-2.0-flash-exp с встроенным инструментом google_search для ответов на вопросы с заземлением на актуальные поисковые данные.

#### Crew.AI / CrewAI

##### Мысли автора по порядку

* CrewAI абстрагирует логику взаимодействия через человекоподобную модель команды (Agents, Tasks, Crew, Process).
* Каждая роль содержит описание цели и бэкстори. Процесс может быть последовательным (Process.sequential) или иерархическим.

##### Что делает пример кода (без самого кода)

* Декоратор @crew создает исследовательскую команду Crew, связывая список агентов, задач и устанавливая последовательный режим выполнения process=Process.sequential с логированием.

#### Other Agent Development Frameworks / Другие фреймворки разработки агентов

##### Мысли автора по порядку

* **Microsoft AutoGen:** мультиагентная диалоговая оркестрация решений через общение агентов.
* **LlamaIndex:** специализированный фреймворк для индексации, структурирования данных и RAG-пайплайнов.
* **Haystack:** промышленный открытый фреймворк для масштабируемых поисковых систем и Q&A.
* **MetaGPT:** мультиагентная система на базе стандартных операционных процедур (SOP), симулирующая ИТ-компанию.
* **SuperAGI:** автономная платформа с графическим UI, управлением ресурсами и защитой от зацикливания.
* **Semantic Kernel (Microsoft):** SDK для интеграции LLM с традиционным кодом через плагины и планировщики (.NET / Python).
* **Strands Agents (AWS):** легкий SDK с нативной поддержкой стандарта MCP.

Приложение C содержит систематический обзор агентских фреймворков.
