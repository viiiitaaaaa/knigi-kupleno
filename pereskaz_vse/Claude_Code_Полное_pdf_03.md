### Глава 6. Написание кода с нуля (Writing Code from Scratch)

#### 6.1. От идеи до рабочего кода: методология (From Idea to Working Code: Methodology)
* **Главные мысли автора:** Создание ПО с нуля с Claude Code превращает генерацию кода из лотереи в предсказуемый процесс через описание проекта на человеческом языке. (стр. 80)
* **Правила:** Использование пятишаговой методологии применимо к проектам любого масштаба и стека:
  * Этап 1: Описание (Specification) (стр. 80)
  * Этап 2: Архитектура (Architecture) (стр. 80)
  * Этап 3: Скаффолдинг (Scaffolding) (стр. 81)
  * Этап 4: Реализация (Implementation) (стр. 81)
  * Этап 5: Интеграция и тестирование (Integration and Testing) (стр. 81)
* **Примеры и кейсы:**
  * Описание проекта (Шаг 1):
    > Мне нужно приложение для управления личными финансами.
    > Пользователь может:
    > – Регистрировать доходы и расходы по категориям
    > – Видеть баланс по месяцам
    > – Просматривать аналитику: графики расходов по категориям,
    > тренд доходов/расходов за год
    > – Устанавливать бюджеты по категориям и получать
    > предупреждения при превышении
    > Это веб-приложение, одинопользовательское (пока),
    > данные хранятся локально.
    *(стр. 80)*
  * Запрос архитектуры (Шаг 2):
    > Прежде чем писать код, предложи архитектуру проекта:
    > – Технологический стек (обоснуй выбор)
    > – Структуру файлов
    > – Модели данных
    > – Основные компоненты и их взаимодействие
    *(стр. 80-81)*
  * Скаффолдинг (Шаг 3):
    > Отлично, мне нравится план. Создай скелет проекта:
    > – Инициализируй npm, установи зависимости
    > – Создай структуру каталогов
    > – Настрой конфигурацию (TypeScript, ESLint, Prettier)
    > – Создай базовый сервер, который запускается и
    > показывает пустую страницу
    *(стр. 81)*
  * Реализация (Шаг 4):
    > Теперь реализуй первую функцию: добавление транзакций.
    > Модель транзакции уже определена в types/transaction.ts.
    > Нужен:
    > – API endpoint POST /api/transactions
    > – Форма добавления на фронтенде
    > – Сохранение в SQLite
    *(стр. 81)*
  * Интеграция и тестирование (Шаг 5):
    > Запусти приложение, добавь тестовые транзакции
    > и проверь, что всё работает корректно.
    > Если есть ошибки – исправь.
    *(стр. 81)*

#### 6.3. Бэкенд-разработка (Backend Development)
* **Главные мысли автора:** Поддержка бэкенда на различных языках программирования и фреймворках (Python + FastAPI, Node.js + Express, Go, Django) с генерацией полной структуры файлов и эндпоинтов. (стр. 84-86)
* **Цифры и факты:**
  * Версия Django: Django 5.0 (стр. 86).
* **Примеры и кейсы:**
  * Python + FastAPI:
    > Создай API на FastAPI для сервиса коротких ссылок.
    > Функциональность:
    > – POST /api/links – создание короткой ссылки
    > Request: { "url": "https://example.com/long-path" }
    > Response: { "short_url": "https://s.hr/abc123", "clicks": 0 }
    > – GET /{short_code} – редирект на оригинальный URL
    > – GET /api/links/{short_code}/stats – статистика переходов
    > Response: { "url": "…", "clicks": 42,
    > "created_at": "…", "last_clicked": "…" }
    > Технические требования:
    > – SQLAlchemy + SQLite для хранения
    > – Алгоритм генерации: base62 от autoincrement ID
    > – Rate limiting: 10 запросов в минуту на IP
    > – CORS: разрешить все origins
    > Структура проекта:
    > app/
    > +– main.py
    > +– models.py
    > +– schemas.py
    > +– crud.py
    > +– database.py
    > +– config.py
    *(стр. 84)*
  * Node.js + Express:
    > Создай RESTful API на Express.js для управления задачами
    > (Task Manager).
    > Модели:
    > – User: id, email, name, password_hash
    > – Project: id, name, description, owner_id
    > – Task: id, title, description, status, priority,
    > assignee_id, project_id, due_date
    > Endpoints:
    > – Auth: register, login, refresh token
    > – Projects: CRUD + список участников
    > – Tasks: CRUD + смена статуса + назначение исполнителя
    > Middleware:
    > – Аутентификация (JWT)
    > – Валидация (Joi)
    > – Обработка ошибок
    > – Логирование (Morgan)
    > – Rate Limiting
    > Database: PostgreSQL + Knex.js
    > Организация: controller -> service -> repository
    *(стр. 85)*
  * Go API:
    > Создай REST API на Go с использованием Chi router.
    > Функциональность: API для блог-платформы.
    > Структура проекта (Clean Architecture):
    > cmd/api/main.go
    > internal/
    > +– handler/ – HTTP handlers
    > +– service/ – бизнес-логика
    > +– repository/ – работа с БД
    > +– model/ – доменные модели
    > +– middleware/ – middleware
    > База данных: PostgreSQL через pgx.
    > Миграции: golang-migrate.
    > Конфигурация: через переменные окружения (envconfig).
    > Логирование: slog (stdlib).
    *(стр. 85-86)*
  * Django:
    > Создай Django-проект для системы управления контентом (CMS).
    > Django 5.0, Django REST Framework, PostgreSQL.
    > Приложения:
    > – accounts: расширенная модель User, профили
    > – articles: статьи с категориями, тегами, черновиками
    > – media: управление изображениями
    > – api: сериализаторы и viewsets для всех моделей
    > Фичи:
    > – Админка с кастомизированным интерфейсом
    > – Полнотекстовый поиск (PostgreSQL FTS)
    > – Кеширование через Redis
    > – Celery для фоновых задач
    > – API документация через drf-spectacular
    *(стр. 86)*

#### 6.6. Паттерны генерации кода (Code Generation Patterns)
* **Главные мысли автора:** Использование проверенных паттернов для упорядочивания процесса генерации кода (слои, TDD, копирование стиля, прототип-продакшен). (стр. 89-90)
* **Примеры и кейсы:**
  * Паттерн «Слой за слоем»:
    1. > Создай модели данных (Prisma schema)
    2. > Создай repository layer
    3. > Создай service layer с бизнес-логикой
    4. > Создай API endpoints
    5. > Создай фронтенд-компоненты
    6. > Добавь тесты
    *(стр. 89)*
  * Паттерн «От тестов к коду» (TDD):
    > Напиши тесты для модуля расчёта скидок.
    > Бизнес-правила:
    > – Скидка 5% при заказе от 5000
    > – Скидка 10% при заказе от 10000
    > – Скидка 15% для VIP-клиентов
    > – Скидки не суммируются – применяется максимальная
    > – Скидка не может превышать 20%
    > ТОЛЬКО тесты, код пока не пиши.
    > 
    > Теперь напиши реализацию, которая проходит все эти тесты.
    *(стр. 90)*
  * Паттерн «Скопируй стиль»:
    > Посмотри, как реализован модуль src/modules/users/.
    > Создай аналогичный модуль src/modules/products/
    > с такой же структурой и стилем кода.
    > Product: id, name, description, price, category_id,
    > is_active, created_at
    *(стр. 90)*
  * Паттерн «Прототип -> Продакшен»:
    > Создай простейший чат на WebSocket.
    > Минимум кода, без базы данных, всё в памяти.
    > 
    > Теперь доработай до продакшен-версии:
    > – Сохранение сообщений в PostgreSQL
    > – Аутентификация через JWT
    > – Комнаты (rooms)
    > – Типизация (TypeScript)
    > – Обработка ошибок
    > – Reconnection logic на клиенте
    > – Тесты
    *(стр. 90)*

### Глава 7. Рефакторинг и улучшение существующего кода (Refactoring and Improving Existing Code)

#### 7.1. Понимание чужого кода: первый контакт (Understanding Unfamiliar Code: First Contact)
* **Главные мысли автора:** Превращение процесса разбора чужой кодовой базы в структурированное исследование при помощи первичного анализа, погружения в модули, построения карт зависимостей и поиска проблем. (стр. 93-94)
* **Примеры и кейсы:**
  * Первичный анализ проекта:
    > Проанализируй этот проект. Мне нужно понять:
    > 1. Что это за приложение и что оно делает
    > 2. Какой технологический стек используется
    > 3. Как организована кодовая база
    > 4. Какие основные модули и как они связаны
    > 5. Есть ли документация и тесты
    *(стр. 93)*
  * Анализ конкретного модуля:
    > Объясни, как работает модуль авторизации (src/auth/).
    > Покажи:
    > – Flow аутентификации (от запроса до ответа)
    > – Какие middleware задействованы
    > – Как хранятся и проверяются токены
    > – Какие роли и разрешения существуют
    *(стр. 93)*
  * Визуализация зависимостей:
    > Построй карту зависимостей между модулями в src/.
    > Какие модули от каких зависят?
    > Есть ли циклические зависимости?
    *(стр. 93)*
  * Поиск «скелетов в шкафу»:
    > Найди в проекте:
    > – TODO и FIXME комментарии
    > – Закомментированный код
    > – Неиспользуемые переменные и импорты
    > – Дублирование кода
    > – Файлы без тестов
    > – Захардкоженные значения (magic numbers/strings)
    *(стр. 94)*

#### 7.2. Code Smells: обнаружение и устранение (Code Smells: Detection and Elimination)
* **Главные мысли автора:** Выявление запахов кода (по классификации Мартина Фаулера) и систематический аудит метрик сложности. (стр. 94-95)
* **Примеры и кейсы:**
  * Обнаружение code smells:
    > Проанализируй файл src/services/orderService.ts на наличие
    > code smells. Для каждого найденного smell укажи:
    > – Название (по каталогу Мартина Фаулера)
    > – Строки кода
    > – Почему это проблема
    > – Как исправить
    *(стр. 94)*
  * Устранение God Object:
    > Этот класс UserManager слишком большой (800 строк) и делает
    > слишком много. Разбей его на несколько классов по принципу
    > Single Responsibility.
    *(стр. 94)*
  * Систематический аудит кода:
    > Проведи полный аудит кода в каталоге src/services/.
    > Проверь на:
    > 1. Сложность (цикломатическая > 10)
    > 2. Дублирование (> 5 строк повторяющегося кода)
    > 3. Длинные функции (> 50 строк)
    > 4. Глубокая вложенность (> 3 уровня)
    > 5. Магические числа и строки
    > 6. Нарушение DRY
