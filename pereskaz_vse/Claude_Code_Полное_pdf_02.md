### 3.5. Первый проект: создание веб-приложения (First project: Creating a web application) (стр. 39)

* Главные мысли автора: Claude Code позволяет строить полноценные проекты с нуля через итеративные запросы, помня контекст предыдущих шагов и наращивая функциональность на существующей основе (стр. 39, 41).
* Пример: создание веб-приложения «Менеджер заметок» со стеком Node.js, Express, SQLite, EJS.
  * Шаг 1 (Инициализация): пользователь отправляет промпт:
    > Создай новый проект – менеджер заметок.
    > Стек: Node.js, Express, SQLite, EJS для шаблонов.
    > Базовая функциональность: создание, чтение, редактирование,
    > удаление заметок. Каждая заметка имеет заголовок, содержимое
    > и дату создания/обновления.
    (стр. 39). Результат: Claude Code создаёт package.json, структуру каталогов (`notes-app/` с вложенными `server.js`, `database.js`, каталогами `routes/`, `views/`, `public/`, `README.md`), пишет код, устанавливает зависимости и проверяет работоспособность (стр. 39–40).
  * Шаг 2 (Проверка и запуск): пользователь отправляет:
    > Запусти приложение и проверь, что главная страница открывается
    (стр. 40). Результат: Claude Code выполняет `node server.js` и проверяет доступность через curl или встроенный инструмент (стр. 40).
  * Шаг 3 (Доработка): пользователь отправляет:
    > Добавь поиск по заметкам: поле поиска на главной странице,
    > которое фильтрует заметки по заголовку и содержимому.
    > Поиск должен быть нечувствительным к регистру.
    (стр. 40). Результат: Claude Code изменяет файлы: добавляет маршрут `/search` в `routes/notes.js`, SQL-запрос с `LIKE` в `database.js`, обновляет шаблоны и стили (стр. 40).
  * Шаг 4 (Итерация): процесс продолжается запросами на добавление категорий, markdown-рендеринга, экспорта в PDF и тёмной темы (стр. 40–41).

### 3.6. Работа с файлами (Working with files) (стр. 41)

* Главные мысли автора: работа с файлами — одна из основных возможностей Claude Code, поддерживающая агентный подход и массовые операции (стр. 41, 42).
* Кейсы и операции:
  * Чтение: `> Покажи содержимое файла server.js`, `> Прочитай все файлы в каталоге src/`, `> Что находится в package.json?` (стр. 41).
  * Создание: создание файла `config.js` с настройками приложения (порт, БД, JWT) (стр. 41–42). Пример сгенерированного кода:
    ```javascript
    // config.js
    const config = {
    port: process.env.PORT || 3000,
    database: {
    url: process.env.DATABASE_URL || 'sqlite:./data/app.db',
    },
    jwt: {
    secret: process.env.JWT_SECRET || 'change-me-in-production',
    expiresIn: '24h',
    },
    app: {
    name: 'Notes Manager',
    version: '1.0.0',
    },
    };
    module.exports = config;
    ```
    (стр. 41–42).
  * Редактирование: точечное изменение без перезаписи всего файла (`> В файле server.js добавь middleware для логирования запросов с помощью morgan`) (стр. 42).
  * Удаление: `> Удали файл temp.js – он больше не нужен` (Claude Code запрашивает подтверждение) (стр. 42).
  * Переименование и перемещение: `> Переименуй database.js в db/connection.js` (Claude Code создаёт каталог, перемещает файл и обновляет все import/require-ссылки) (стр. 42).
  * Массовые операции: `> Добавь JSDoc-комментарии ко всем экспортируемым функциям в каталоге src/utils/` (Claude Code последовательно обрабатывает файлы) (стр. 42).

### 3.7. Работа с терминалом (Working with the terminal) (стр. 43)

* Главные мысли автора: Claude Code взаимодействует с ОС, инструментами разработки и инфраструктурой через терминал, используя систему разрешений (стр. 43).
* Правила безопасности (система разрешений):
  * Безопасные команды (`ls`, `cat`, `find`, `grep`, чтение файлов) — выполняются без подтверждения (стр. 43).
  * Команды разработки (`npm run`, `pytest`, `go build`) — зависят от настроек (стр. 43).
  * Потенциально опасные (установка пакетов, изменение конфигурации) — требуют подтверждения (стр. 43).
  * Опасные (`rm`, `sudo`, `curl | bash`) — всегда требуют подтверждения (стр. 43). Уровень доверия настраивается в `.claude/settings.json` (стр. 43).
* Кейсы и сценарии:
  * Установка зависимостей: `> Установи необходимые зависимости для проекта` (Claude Code предлагает команду `npm install express ejs better-sqlite3 morgan` с опциями `Allow? [Y/n/always]`) (стр. 43).
  * Запуск тестов: `> Запусти тесты и исправь падающие` (выполняет `npm test`, анализирует вывод и исправляет код) (стр. 43).
  * Сборка проекта: `> Собери проект для продакшена` (выполняет `npm run build`) (стр. 43).
  * Работа с Git: `> Создай коммит с осмысленным сообщением` (анализирует diff, формирует сообщение и выполняет `git add` + `git commit`) (стр. 43–44).
  * Анализ системы: проверка дискового пространства, портов (порт 3000), проверка работы Docker (стр. 44).
  * Конвейеры команд: `> Найди все TypeScript файлы с неиспользуемыми импортами` (выполнение `npx ts-prune | head -50` с анализом результатов) (стр. 44).

### 3.11. Управление сессиями (Session management) (стр. 47)

* Главные мысли автора: поддержка сохранения и возобновления диалогов позволяет продолжить работу с прерванного места (стр. 47).
* Команды и правила организации:
  * `claude –continue` или `claude -c` — загружает последний диалог со всей историей и контекстом (стр. 47).
  * `claude –resume` — открывает список предыдущих диалогов с описаниями для выбора (стр. 47).
  * Рекомендации по организации: один диалог — одна задача (фича, баг, рефакторинг); использовать `/clear` перед новой задачей; `--continue` для незавершённой работы; `/compact` перед сохранением длинного диалога (стр. 47).

### 4.1. Как Claude Code понимает вашу кодовую базу (How Claude Code understands your codebase) (стр. 50)

* Главные мысли автора: Claude Code использует многоуровневую систему построения понимания проекта (стр. 50).
* Уровни системы:
  * Уровень 1: Метаданные проекта (`package.json`, `pyproject.toml`, `go.mod`, `Cargo.toml`, `README.md`, `CLAUDE.md`, `.gitignore`, `Dockerfile`, `tsconfig.json` и др.) (стр. 50).
  * Уровень 2: Структура файловой системы (анализ иерархии каталогов, например, MVC-архитектура или feature-based архитектура) (стр. 50–51).
  * Уровень 3: Индексация кода (стратегия «ленивой загрузки»: загрузка метаданных, точечный запрос файлов, использование grep/find, отслеживание кросс-ссылок) (стр. 51).
  * Уровень 4: Семантическое понимание (распознавание паттернов проектирования Singleton, Factory, Observer и др., понимание бизнес-логики, анализ потока данных, выявление проблем вроде race conditions и утечек памяти) (стр. 51).

### 4.2. Инструменты (Tools): как Claude Code действует (Tools: How Claude Code acts) (стр. 52)

* Главные мысли автора: в основе агентных возможностей лежит система атомарных инструментов, которые модель вызывает самостоятельно (стр. 52).
* Список инструментов и примеры:
  * Файловые инструменты:
    * `ReadFile` — чтение содержимого файла (`Input: path: "src/utils/helpers.ts"`) (стр. 52).
    * `WriteFile` — создание или перезапись файла (`Input: path: "src/models/user.ts"`, `content: "export interface User { … }"`) (стр. 52).
    * `EditFile (MultiEdit)` — точечное редактирование без полной перезаписи (`Input: path: "src/server.ts"`, `edits: [...]`) (стр. 52).
  * Терминальные инструменты:
    * `Bash` — выполнение команд оболочки (`Input: command: "npm test"`) для установки зависимостей, тестов, сборки, Git, Docker (стр. 52–53).
  * Поисковые инструменты:
    * `Search (grep/ripgrep)` — поиск по содержимому файлов (`Input: query: "function calculateDiscount"`, `path: "src/"`) (стр. 53).
    * `Find (fd)` — поиск файлов по имени (`Input: pattern: "*.test.ts"`, `path: "src/"`) (стр. 53).
  * Веб-инструменты:
    * `WebSearch` — поиск в интернете для получения актуальной информации и документации (стр. 53).
    * `ReadURL` — чтение содержимого веб-страницы (API-документация, StackOverflow) (стр. 53).
  * MCP-инструменты (Model Context Protocol): подключение внешних инструментов (Jira, Slack, GitHub, Database, Kubernetes) (стр. 53).
* Координация инструментов: пример цепочки действий при исправлении падающего теста (`npm test` -> `ReadFile` (тест) -> `ReadFile` (код) -> `Search` -> `ReadFile` (репозиторий) -> `EditFile` -> `npm test`) (стр. 54).

### 4.3. Модель разрешений и безопасность (Permissions model and security) (стр. 54)

* Главные мысли автора: для безопасного доступа к файловой системе и терминалу используется многоуровневая система контроля (стр. 54).
* Иерархия разрешений:
  * Уровень 1: Встроенные ограничения модели (отказ удалять системные файлы, ставить вредоносное ПО, сливать данные) (стр. 54–55).
  * Уровень 2: Категории инструментов (Read-only — без подтверждения; Write, Execute, Network — требуют подтверждения; Destructive — всегда требуют подтверждения) (стр. 55).
  * Уровень 3: Настраиваемые разрешения через `.claude/settings.json` (стр. 55). Пример конфигурации:
    ```json
    {
    "permissions": {
    "allow": [
    "Read",
    "Write(src/**)",
    "Write(tests/**)",
    "Bash(npm run *)",
    "Bash(pytest *)",
    "Bash(git add *)",
    "Bash(git commit *)"
    ],
    "deny": [
    "Write(*.env)",
    "Write(.claude/settings.json)",
    "Bash(rm -rf *)",
    "Bash(sudo *)",
    "Bash(curl * | *)"
    ]
    }
    }
    ```
    (стр. 55).
  * Уровень 4: Интерактивное подтверждение в реальном времени с опциями `[Y] Allow once`, `[n] Deny`, `[a] Always allow ...`, `[d] Always deny ...` (стр. 55–56).
* Аудит действий: логирование всех операций с временными метками (стр. 56).
* Работа с секретами: использование переменных окружения (`process.env.API_KEY`), добавление `.env` в `.gitignore`, запрет записи в файлы `.env` через настройки разрешений, использование `.env.example` (стр. 56).

### 4.4. Агентный режим: планирование и выполнение (Agentic mode: Planning and execution) (стр. 57)

* Главные мысли автора: агентный режим позволяет самостоятельно планировать и выполнять многоэтапные задачи (стр. 57).
* Цикл AGI (Act-Grounded-Iterate):
  1. THINK (Подумать) — проанализировать запрос, шаги, нужную информацию (стр. 57).
  2. ACT (Действовать) — вызвать инструмент, выполнить операцию (стр. 57).
  3. OBSERVE (Наблюдать) — проанализировать результат, проверить ошибки и достижение цели (стр. 57).
  4. ITERATE (Итерировать) — если цель достигнута, вернуть результат; если нет, скорректировать план (стр. 57).
* Ограничение количества шагов: настройка `maxTurns` в `.claude/settings.json` (например, `"maxTurns": 50`) для защиты от бесконечных циклов (стр. 58).
* Режим расширенного планирования: активация фразой «Подумай внимательно и составь детальный план перед началом работы» (стр. 58).

### 4.5. Модели Claude: Opus, Sonnet, Haiku (Claude models: Opus, Sonnet, Haiku) (стр. 58)

* Главные мысли автора: поддержка нескольких моделей с разными характеристиками и стоимостью (стр. 58–59).
* Характеристики и применение моделей:
  * Claude Opus: самая мощная модель, лучшее качество рассуждения и генерации кода, самая высокая стоимость, контекст 200K. Применение: архитектура, сложный рефакторинг legacy, неизвестные фреймворки, code review (стр. 59).
  * Claude Sonnet: оптимальный баланс качества и стоимости, модель по умолчанию, контекст 200K, высокая скорость. Применение: повседневная разработка, новый код, отладка, тесты, рефакторинг (стр. 59).
  * Claude Haiku: самая быстрая и дешёвая модель, контекст 200K. Применение: автодополнение, boilerplate-код, простые вопросы, линтинг, массовые операции (стр. 59–60).
* Переключение моделей: команда `/model claude-opus-4-20250514` или параметр `"defaultModel"` в `.claude/settings.json` (стр. 60).

### 4.6. Контекстный протокол: что знает Claude Code (Context protocol: What Claude Code knows) (стр. 60)

* Главные мысли автора: понимание структуры контекста помогает оптимизировать работу (стр. 60).
* Структура контекста:
  * Системный промпт (Instructions: кто ты, инструменты, безопасность, форматирование) (стр. 60).

### 4.7. Кэширование промптов (Prompt caching) (стр. 62)

* Главные мысли автора: механизм Prompt Caching от Anthropic снижает стоимость повторных запросов с похожим контекстом (стр. 62).
* Как максимизировать кэширование: не менять часто `CLAUDE.md`, работать с одним набором файлов, не использовать `/clear` без необходимости, предпочитать `/compact` вместо `/clear` (стр. 62).

---

### 4.8. Границы возможностей (Capabilities and limitations) (стр. 62)

* Главные мысли автора: понимание ограничений инструмента критически важно (стр. 62).
* Технические ограничения: нет постоянной памяти между сессиями, нет фонового выполнения, нет прямого доступа к GUI, есть ограничение длительности команд (таймаут) (стр. 62).
* Концептуальные ограничения: не понимает бизнес-контекст по умолчанию, не заменяет тестирование, не гарантирует безопасность, не оптимизируется автоматически (стр. 63).

---

### 4.9. Архитектура расширяемости (Extensibility architecture) (стр. 63)

* Главные мысли автора: Claude Code спроектирован с возможностью расширения (стр. 63).
* Механизмы:
  * Пользовательские команды (Slash Commands): создание собственных команд в каталоге `.claude/commands/` (стр. 63).
  * Hooks: выполнение действий до или после вызовов инструментов (`preToolUse`, `postToolUse`) в `.claude/settings.json` (стр. 63–64).
  * MCP (Model Context Protocol): протокол для подключения внешних инструментов и источников данных (стр. 64).

### Глава 5. Эффективное общение с AI-ассистентом (Chapter 5. Effective communication with the AI assistant) (стр. 65)

---

### 5.1. Искусство промпт-инжиниринга для разработки (Prompt engineering art for development) (стр. 65)

* Главные мысли автора: промпт-инжиниринг в разработке требует точности, полноты и однозначности, так как заданием управляется агент-исполнитель (стр. 65).
* Три уровня зрелости промптов:
  * Уровень 1: Наивный промпт (например, `> Сделай логин`) — расплывчат, модель пытается угадать (стр. 65).
  * Уровень 2: Структурированный промпт (указание формы, валидации, редиректа, сервиса) (стр. 65–66).
  * Уровень 3: Экспертный промпт — детальные требования к функциональности, технические требования, ограничения (пример полной спецификации страницы входа на стр. 65–66).

---

### 5.2. Принципы эффективных промптов (Effective prompt principles) (стр. 66)

* Главные мысли автора: соблюдение базовых принципов формулировки заданий экономит время и повышает качество результата (стр. 66).
* Принципы:
  * Принцип конкретности (точные цвета, шрифты, размеры вместо «сделай красиво») (стр. 66).
  * Принцип контекста (предоставление релевантных деталей, например пути к файлу и типа ошибки) (стр. 66–67).
  * Принцип разделения (разбиение сложных задач на этапы) (стр. 67).
  * Принцип примеров (демонстрация ожидаемого результата через примеры входных и выходных данных) (стр. 67).
  * Принцип ролевой модели (задание роли, например старшего DevOps-инженера) (стр. 67).

---

### 5.3. Типы промптов для разных задач (Prompt types for different tasks) (стр. 68)

* Главные мысли автора: под каждый класс задач (генерация, отладка, рефакторинг, review, документирование) существуют специализированные шаблоны промптов (стр. 68).
* Примеры шаблонов:
  * Для генерации кода: структура с указанием `Создай [что] для [цель] используя [технологии]`, входных/выходных данных, граничных случаев и обработки ошибок (стр. 68).
  * Для отладки: указание ошибки, файла, шагов воспроизведения, ожидаемого и фактического поведения, попыток решения (стр. 68).
  * Для рефакторинга: указание файла/модуля, целей (разделение, извлечение логики), ограничений (обратная совместимость) и паттернов (стр. 69).
  * Для code review: фокус проверки, контекст задачи (что делает код, почему так сделано), требуемый формат ответа (серьёзность, описание, исправление) (стр. 69–70).
  * Для документирования: аудитория, формат (JSDoc/Docstring/README), что включить и исключить (стр. 70).

---

### 5.4. CLAUDE.md: память проекта (CLAUDE.md: Project memory) (стр. 70)

* Главные мысли автора: файл `CLAUDE.md` решает проблему потери контекста между сессиями, храня стек, структуру, команды и соглашения в одном загружаемом автоматически месте (стр. 70).
* Структура эффективного `CLAUDE.md`: описание, технологический стек, архитектура (структура каталогов), команды разработки, соглашения по коду, важные решения, чего НЕ делать (стр. 70–71).
* Продвинутый пример: детальный шаблон для SaaS-приложения (Next.js, Prisma, tRPC, Tailwind) с правилами именования, организации кода, Git-коммитов и списком запретов (`НЕ использовать any`, `НЕ хранить секреты в коде` и др.) (стр. 71–72).
* Иерархические `CLAUDE.md`: поддержка файлов на разных уровнях вложенности (глобальный + локальные для каждого пакета/модуля) (стр. 73).

---

### 5.5. Антипаттерны: чего не стоит делать (Antipatterns: What not to do) (стр. 73)

* Главные мысли автора: типичные ошибки снижают эффективность работы с AI (стр. 73).
* Список антипаттернов:
  1. «Рыхлый промпт» (`> Сделай что-нибудь с кодом...`) (стр. 73).
  2. «Микроменеджмент» (построчное указание действий, которые агент может сделать сам) (стр. 73).
  3. «Вся кодовая база за раз» (просьба прочитать все файлы проекта) (стр. 73).
  4. «Слепое доверие» (отсутствие проверок сгенерированного кода) (стр. 73–74).
  5. «Бесконечные исправления» (попытки исправить одну ошибку более 10–20 раз без смены стратегии) (стр. 74).
  6. «Переключение контекста» (смешивание разных задач в одном диалоге) (стр. 74).

---

### 5.6. Итеративная разработка: уточнение и корректировка (Iterative development: Refinement and adjustment) (стр. 74)

* Главные мысли автора: работа с Claude Code строится как итеративный диалог (стр. 74).
* Техники:
  * Техника «Да, но» (последовательное добавление слоёв: пагинация, фильтрация, кэширование поверх базового REST API) (стр. 74).
  * Техника «Расширение горизонта» (движение от простого MVP к валидации, защите, уведомлениям и админке) (стр. 74).
  * Техника «Критик» (просьба к Claude Code провести review собственной работы для поиска недочётов) (стр. 75).
  * Техника «Сравнение» (реализация модуля двумя способами для выбора оптимального) (стр. 75).

---

### 5.7. Продвинутые техники промптинга (Advanced prompting techniques) (стр. 75)

* Главные мысли автора: использование продвинутых подходов повышает качество генерации (стр. 75).
* Техники:
  * Chain-of-Thought (Цепочка рассуждений): просьба рассуждать пошагово (например, о причинах deadlock) (стр. 75).
  * Few-Shot Learning (Обучение на примерах): демонстрация примеров желаемого формата кода или тестов (стр. 75–76).
  * Negative Prompting (Негативные инструкции): указание того, чего делать НЕ надо (например, запрет глобальных переменных или лишних пакетов) (стр. 76).
  * Conditional Prompting (Условные инструкции): указание разных действий в зависимости от условий (например, анализ `package.json` и настройка покрытия для Jest или Vitest) (стр. 76).

---

### 5.8. Работа с большими кодовыми базами (Working with large codebases) (стр. 76)

* Главные мысли автора: крупные проекты требуют применения специальных стратегий ограничения контекста (стр. 76).
* Стратегии:
  * Стратегия «Фокусная линза» (ограничение работы только конкретным модулем и списком релевантных файлов) (стр. 76–77).
  * Стратегия «Проводник» (использование Claude Code для погружения нового разработчика в архитектуру и процессы незнакомого проекта) (стр. 77).
  * Стратегия «Карта зависимостей» (построение связей модуля с импортами, сервисами и таблицами БД) (стр. 77).

---

### 5.9. Многоязычные промпты (Multilingual prompts) (стр. 77)

* Главные мысли автора: Claude Code понимает русский язык, но разработка имеет свои стандарты (стр. 77).
* Рекомендации: код (переменные, функции, классы) писать на английском; комментарии и документацию можно писать на русском, если это принято в проекте; допускается свободное смешивание языков в промптах (стр. 77–78).

---

### 5.10. Создание собственных шаблонов промптов (Creating custom prompt templates) (стр. 78)

* Главные мысли автора: часто повторяющиеся типы промптов следует сохранять в виде пользовательских команд (стр. 78).
* Примеры шаблонов:
  * Шаблон для создания компонентов (`.claude/commands/component.md`):
    ```markdown
    Создай React-компонент $ARGUMENTS:
    1. Создай файл в src/components/
    2. Используй TypeScript
    3. Добавь props interface
    4. Используй наш UI Kit из src/components/ui/
    5. Добавь Storybook story
    6. Добавь unit-тест
    7. Экспортируй из src/components/index.ts
    ```
    (стр. 78).
  * Шаблон для исправления бага (`.claude/commands/fix-bug.md`): поиск файла, анализ причины, варианты решения, реализация, regression-тест, запуск тестов, коммит `fix: [описание]` (стр. 78).
  * Шаблон для code review (`.claude/commands/review.md`): проверка логики, ошибок, безопасности, производительности, тестов, документации и code style с выводом в формате `[!] Critical`, `[~] Warning`, `[i] Info`, `[+] Хорошие практики` (стр. 78–79). Использование: `> /project:review src/api/routes/payments.ts` (стр. 79).
