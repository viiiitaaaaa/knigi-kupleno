## Chapter 1. What is an AI agent? / Глава 1. Что такое ИИ-агент?

#### Главная мысль автора

Главная идея главы заключается в том, что современный ИИ-агент — это программа, которая передаёт часть своего потока управления (**control flow**) языковой модели (LLM), превращая её в «мозг», принимающий автономные решения о том, какие инструменты вызывать и когда завершать работу. Эффективность агента зависит не столько от размерности контекстного окна модели, сколько от дисциплины контекстной инженерии (**context engineering**), которая формирует рабочую память агента и защищает её от «деградации контекста» (**context rot**).

#### Ключевые формулировки автора

1. "An LLM agent is a program that hands part of its control flow to an LLM, letting the model decide what actions to take and when to stop based on its current context and goals." — *«LLM-агент — это программа, которая передаёт часть своего потока управления LLM, позволяя модели решать, какие действия предпринимать и когда останавливаться на основе текущего контекста и целей.»*
2. "To summarize, the LLM makes autonomous decisions possible, tools expand the action space, and the loop unfolds it over time." — *«Подводя итог: LLM делает возможными автономные решения, инструменты расширяют пространство действий, а цикл разворачивает его во времени.»*
3. "Context engineering is the discipline of providing the information an LLM needs to perform its tasks at the right time and in the right form." — *«Контекстная инженерия — это дисциплина предоставления информации, необходимой LLM для выполнения её задач, в нужное время и в правильной форме.»*
4. "Agent = Model + Harness" — *«Агент = Модель + Обвязка»*

##### 1.1 The age of AI agents / Эра ИИ-агентов

* **Мысли автора по порядку**: Ландшафт ИИ-агентов быстро трансформируется по трём направлениям:
  1. *Персональные ИИ-агенты* (Personal AI agents) — ChatGPT, Claude, Gemini эволюционировали из чат-ботов в помощников, анализирующих документы, ищущих информацию в сети, генерирующих изображения и исполняющих код.
  2. *Клиентские агенты* (Customer-facing agents) — действуют от имени бизнеса, имеют доступ к внутренним базам, обрабатывают транзакции и возвраты.
  3. *Специализированные агенты* (Specialized agents) — решают узкопрофильные задачи (Claude Code, Cursor, Codex CLI для работы с кодом; Deep Research для асинхронных исследований сотен источников). Все эти агенты объединяет общий фундамент — использование LLM в качестве ядра принятия решений.

##### 1.2 Understanding LLM agents / Понимание LLM-агентов

* **Мысли автора по порядку**:
  * **1.2.1 What is an LLM? / Что такое LLM?** LLM обучается предсказывать следующее слово (токен) на огромных объёмах интернет-текста, формируя способность к обобщению (**generalization**). Появление моделей рассуждения (**reasoning models**), генерирующих токены размышления (начинающиеся с <think>), позволяет решать сложные задачи.
    * **Номера рисунков**: **Figure 1.1** показывет пример способности языковой модели к обобщению (Few-shot learning с примерами перевода слов Apple, Orange на корейский и Zero-shot learning для Banana -> 바나на).
  * **1.2.2 What is an LLM agent? / Что такое LLM-агент?** *Исследовательский агент (Research agent)*: При запросе пользователя о лауреатах Нобелевской премии по физике 2024 года агент сам решает, какие источники проверить, достаточно ли данных и когда писать отчёт. *Сущность автономного потока управления*: В традиционном ПО логика зафиксирована разработчиком (if, for), а в агенте право принятия решений о следующем шаге передаётся LLM. *Формула автономии*: LLM+Tools+Loop (LLM — мозг, Инструменты — расширение пространств действий, Цикл — разворачивание во времени). *Как работает цикл агента*:
    1. LLM оценивает контекст и решает, нужен ли инструмент.
    2. Выбранный инструмент исполняется.
    3. Результат инструмента добавляется обратно в контекст LLM.
    4. LLM решает, продолжить цикл или выдать финальный отчёт.
    5. **Все цифры, примеры и истории**: История исследовательского агента (Пользователь запросил отчёт по Нобелевской премии 2024 года → Агент выполнил поиск по Нобелевской премии 2024 → установил имена лауреатов Geoffrey Hinton и John J. Hopfield → изучил научные статьи и Википедию → сгенерировал итоговый отчёт).

##### 1.3 Workflow vs. agent / Рабочий процесс против агента

* **Мысли автора по порядку**: Выделяется 7 уровней агентности (от меньшей к большей): Code, LLM call, Chain, Router, Tool call, Multistep, Tool creation. Они делятся на два подхода:
  * **1.3.1 Workflow: Developer-defined flow / Рабочий процесс: поток, определяемый разработчиком** Последовательность действий жестко зафиксирована кодом.
    * *LLM call*: одиночный вызов модели для классификации или суммаризации.
    * *Chain*: цепочка последовательных вызовов LLM, где выход одного шага становится входом для следующего.
    * *Router*: условная логика, где LLM выбирает один из преднастроенных разработчиком путей.
  * **1.3.2 Agent: LLM-directed flow / Агент: поток, направляемый LLM** Модель сама динамически определяет процесс.
    * *Tool use with a multistep loop*: комбинирование инструментов и цикла до достижения цели.
    * *Tool creation*: высший уровень автономии, когда агент сам пишет код нового инструмента для обработки специфических данных.
  * **1.3.3 Combining workflows and agents in practice / Комбинирование рабочих процессов и агентов на практике** На практике эффективны гибридные системы (агенты как узлы внутри рабочего процесса). Пример конвейера обработки документов: 1) Приём (workflow); 2) Анализ содержания (agent); 3) Проверка качества (workflow); 4) Доставка (workflow). Это снижает непредсказуемость, оптимизирует расходы и обеспечивает плавную обработку ошибок.

##### 1.4 Tasks that require agents / Задачи, требующие агентов

* **Мысли автора по порядку**:
  * **1.4.1 Tasks that require an LLM / Задачи, требующие LLM** Использованию агента предшествуют два вопроса: 1) Нужна ли здесь LLM? 2) Нужен ли именно агент или достаточно workflow? Критерии использования LLM: работа с неструктурированными данными (текст, фото, аудио) и высокое разнообразие входных данных (Input diversity).
  * **1.4.2 Conditions for using agents / Условия для использования агентов** Агенты несут издержки: выше финансовые затраты (умножение вызовов API), растёт задержка (latency) и накапливаются ошибки (error propagation). Три критерия применения агентов:
    1. *Сложность задачи* (непредсказуемое количество шагов).
    2. *Ценность задачи* (ценность решения превышает затраты на API).
    3. *Стоимость и обнаруживаемость ошибок* (ошибки не должны приводить к катастрофическим последствиям, и их можно выявить).
  * **1.4.3 GAIA: An agent gym / GAIA: спортзал для агентов** Бенчмарк GAIA (General AI Assistants), выпущенный Meta и Hugging Face в 2023 году, содержит пары «вопрос-ответ», требующие многошаговых рассуждений, поиска и вычислений. GAIA идеален для разработки, так как имеет чёткие проверяемые ответы, подходит для цикла «наблюдение-анализ-улучшение» и не требует узких доменных знаний.
* **Все цифры, примеры и истории**:
  * Пример вопроса Кипчоге (из GAIA): *"Если бы Элиуд Кипчоге мог поддерживать свой мировой рекорд в марафоне неограниченно долго, сколько времени у него ушло бы на бег от Земли до Луны?"* (требует поиска Кипчоге, поиска расстояния в перигее на Википедии и вычислений).

##### 1.5 Context engineering / Контекстная инженерия

* **Мысли автора по порядку**:
  * **1.5.1 Why agents fail / Почему агенты терпят неудачу** Причины сбоев агентов: 1) Недостаток интеллекта модели; 2) Отсутствие необходимой информации в контексте (информационный дефицит).
  * **1.5.2 From prompt engineering to context engineering / От промт-инженерии к контекстной инженерии** Промт-инженерия фокусировалась на статических системных промтах. С появлением инструментов контекст стал динамическим (добавляются результаты поиска, исполнения кода и БД).
  * **1.5.3 Bigger context isn't always better / Больший контекст не всегда лучше** Заполнение контекстного окна на сотни тысяч токенов приводит к эффекту деградации контекста (**context rot**) и феномену «Lost in the Middle» (модель теряет важные детали в середине длинного текста).
  * **1.5.4 Five context-engineering strategies / Пять стратегий контекстной инженерии** Пять ключевых стратегий: **Generate** (генерация планов/рефлексии), **Retrieve** (извлечение из внешних источников/RAG/БД), **Write** (запись в долговременную память/файлы), **Reduce** (сокращение/суммаризация контекста), **Isolate** (изоляция задач/песочницы/мультиагенты).
  * **1.5.5 From context engineering to harness engineering / От контекстной инженерии к инженерии обвязки** Всё, что поддерживает модель извне (память, безопасное исполнение кода, координация агентов, рабочее окружение), называется обвязкой (**harness**). Формула: Agent=Model+Harness.
  * **1.5.6 The journey of this book / Путешествие по этой книге** Главы 2–4 строят базовый цикл агента. Главы 5–9 последовательно добавляют элементы обвязки (RAG, память, планирование, исполнение кода, мультиагентность). Глава 10 посвящена оценке.

#### Summary / Резюме главы 1

* ИИ-агенты охватывают широкий спектр систем — от персональных помощников до узкоспециализированных инструментов разработки, имея в качестве ядра принятия решений LLM.
* Агент состоит из трёх элементов: LLM (мозг), инструменты (взаимодействие с миром) и цикл (итеративный процесс до достижения цели).
* Рабочие процессы (workflows) задаются разработчиком, а агенты (agents) направляются самой моделью. На практике они часто комбинируются.

## Chapter 2. The brain of AI agents: LLMs / Глава 2. Мозг ИИ-агентов: LLM

#### Главная мысль автора

Языковая модель является «мозгом» агента, однако из-за отсутствия состояния в API (**stateless**) разработчик обязан вручную управлять историей диалога и формированием системных промтов, стимулирующих автономные действия. Экспериментальная проверка закрытых моделей на бенчмарке GAIA доказывает, что даже самые сильные LLM без внешних инструментов способны решить не более 25% простейших задач, что математически обосновывает абсолютную необходимость вызова инструментов (**tool calling**).

#### Ключевые формулировки автора

1. "An agent's performance ultimately depends on the LLM's intelligence." — *«Производительность агента в конечном счёте зависит от интеллекта LLM.»*
2. "The key to context engineering is providing the right information at the right time in the right form." — *«Ключ к контекстной инженерии заключается в предоставлении нужной информации в нужное время и в правильной форме.»*
3. "A chatbot converses with users, whereas an agent works on their behalf." — *«Чат-бот беседует с пользователями, тогда как агент работает от их имени.»*
4. "If it's not ambiguous, don't ask; just execute." — *«Если нет двусмысленности, не спрашивайте; просто выполняйте.»*

##### 2.3 Enhancing agent intelligence: Prompt engineering / Повышение интеллекта агента: промт-инженерия

* **Мысли автора по порядку**:
  * **2.3.1 The role of system prompts / Роль системных промтов** Системный промт фиксирует правила поведения агента. Анализ публичного системного промта Anthropic Claude выделяет 4 роли:
    1. *Определение идентичности продукта* (предотвращение устаревших сведений из обучающей выборки).
    2. *Задание формата и стиля вывода* (ограничение злоупотребления списками/маркерами).
    3. *Установка поведенческих границ* (раздел refusal_handling с требованиями отказа от опасных тем, детской безопасности, биологического оружия, вредоносного кода и финансово-юридических советов).
    4. *Уточнение пределов знаний* (указание даты срезки знаний и предложение использовать веб-поиск).
  * **2.3.2 Guidelines for agent prompts / Руководство по промтам для агентов** Агент должен работать от имени пользователя.
    * *Автономность*: Главное правило: *«Если нет двусмысленности, не спрашивайте; просто выполняйте»*.
    * *Стратегическое использование инструментов*: Задание триггерных языковых паттернов для вызова инструментов и негативных инструкций (не искать общеизвестные факты и теоремы).
    * *Якорение примерами*: Передача конкретных пар «Вход — Действие — Ответ».
* **Все цифры, примеры и истории**:
  * Примеры вызова из промта: Запрос *"Какова текущая цена акций Samsung Electronics?"* → Действие [web_search: Samsung Electronics stock price]. Запрос *"Что такое теорема Пифагора?"* → Прямой ответ без поиска.

* Закрытые LLM дают практические преимущества на старте разработки благодаря стабильным API вызова функций и структурированного вывода.
