## Chapter 7. Planning and reflection for complex tasks / Глава 7. Планирование и рефлексия для сложных задач

#### Главная мысль автора

Реактивные агенты ReAct, ориентированные только на текущий шаг, ломаются при выполнении сложных многошаговых задач (теряют направление, повторяют неудачные попытки, делают поспешные выводы). Инструменты планирования (**planning**) и рефлексии (**reflection**) дают агенту «время подумать» (**time to think**), наделяя его метапознанием (**metacognition**). Планирование декомпозирует задачу до начала выполнения, а рефлексия оценивает прогресс и позволяет восстанавливаться после ошибок, формируя взаимодополняющий цикл (**complementary cycle**).

#### Ключевые формулировки автора

1. "Planning breaks complex problems into manageable tasks before execution. Reflection pauses to check progress and adjust direction when things go wrong." — *«Планирование разбивает сложные проблемы на управляемые задачи перед выполнением. Рефлексия делает паузу, чтобы проверить прогресс и скорректировать направление, когда что-то идет не так.»*
2. "Planning is time to think before acting ("What should I do? In what order should I proceed?"). Reflection is time to look back after acting ("What have I learned so far? Am I on the right track? Should I change direction?")." — *«Планирование — это время подумать перед действием («Что мне сделать? В каком порядке двигаться?»). Рефлексия — это время оглянуться назад после действия («Что я узнал к этому моменту? На правильном ли я пути? Нужно ли изменить направление?»).»*
3. "Planning adds 'what to do next' to the context, while reflection adds 'evaluation and direction so far'." — *«Планирование добавляет в контекст «что делать дальше», а рефлексия добавляет «оценку и направление на данный момент».»*
4. "Planning and reflection form a complementary cycle. Planning provides direction; reflection checks that direction and, when necessary, returns to planning." — *«Планирование и рефлексия образуют взаимодополняющий цикл. Планирование задает направление; рефлексия проверяет это направление и при необходимости возвращает к планированию.»*

##### 7.1 Giving agents time to think / Предоставление агентам времени подумать

* **Мысли автора по порядку**:
  * **7.1.1 The limitations of ReAct / Ограничения ReAct** Реактивный подход без плана похож на вождение автомобиля без GPS — на каждом перекрестке поворот выбирается только по текущему виду. В сложных задачах ReAct демонстрирует 4 типичных сбоя:
    1. *Потеря направления*: попытка сделать слишком много действий одновременно без фиксации приоритетов.
    2. *Забывание промежуточных результатов*: повторные поиски уже найденной информации.
    3. *Поспешные выводы*: попытка дать ответ при наличии лишь частичных данных.
    4. *Неспособность восстановиться после ошибок*: бесконечное повторение одного и того же заваливающегося вызова инструмента до исчерпания max_steps.
  * **7.1.2 How human experts work / Как работают человеческие эксперты** Опыт исследователей и разработчиков ПО: эксперты не пишут код сразу, а составляют спецификации/PRD (планирование), ведут пошаговую работу и сверяются со спецификацией при возникновении трудностей (рефлексия).
    * **Все цифры, примеры и истории**:
      * *Пример исследователя на задаче Кипчоге*: Эксперт декомпозирует вопрос -> находит марафонский рекорд Кипчоге -> переводит в скорость (21 км/ч) -> находит расстояние до Луны в перигее -> проверяет чеклист выполненных пунктов перед генерацией финального ответа.
      * *Пример инструментов разработки*: Инструменты Claude Code и Cursor создают план реализации перед написанием кода и сверяются с ним на каждом этапе.
      * *Цитата Anthropic*: Руководство по разработке агентов Anthropic подчёркивает, что эти практики вдохновлены ежедневной работой эффективных инженеров ПО.
  * **7.1.3 Why time to think matters / Почему время подумать имеет значение** В исследованиях LLM подтверждено, что предоставление модели «времени подумать» повышает точность вычислений (Chain-of-thought, reasoning models с генерацией мысленных токенов). В контекстной инженерии планирование и рефлексия относятся к категории **Generate** (LLM генерирует управляющий текст внутри контекста, формируя метапознание).

#### Summary / Резюме главы 7

* Планирование и рефлексия предоставляют агенту «время подумать», заменяя сиюминутные реактивные действия осознанным метапознанием.
* Инструмент планирования create_tasks декомпозирует задачу на подзадачи с отслеживанием статусов (pending, in_progress, completed).
* Инструмент reflection позволяет анализировать ошибки (ERROR ANALYSIS), проверяет прогресс (PROGRESS REVIEW), делает выверку противоречивых данных (RESULT SYNTHESIS) и проводит самопроверку перед финальным ответом (SELF CHECK).
* Флаг need_replan=True объединяет планирование и рефлексию во взаимодополняющий цикл перепланирования.
* С точки зрения контекстной инженерии обе стратегии относятся к категории **Generate**, добавляя управляющий текст в контекст для направленной работы LLM.

## Chapter 8. Empowering agents with code execution / Глава 8. Расширение возможностей агентов с помощью исполнения кода

#### Главная мысль автора

Подход с предопределёнными инструментами (**predefined tools**) имеет ограниченное пространство действий, приводит к «разрастанию инструментов» (**tool proliferation**) и снижает точность выбора функций моделью. Переход к генерации и прямому исполнению кода (подход **CodeAct**) превращает модель в полноценного исполнительного агента с компьютером. Исполнение кода должно быть строго изолировано в облачной песочнице (**E2B sandbox**). Предоставление агенту рабочего пространства (**workspace**) с файловой системой и CLI (bash_tool), а также иерархической системы навыков (**Agent Skills**) с поэтапным раскрытием токенов (**progressive disclosure**) обеспечивает максимум функциональности при минимальных затратах токенов.

#### Ключевые формулировки автора

1. "Instead of creating individual functions as tools, we'll provide an execution environment in which the LLM can write and run code directly. This is what it means to give an agent a computer." — *«Вместо создания отдельных функций в качестве инструментов, мы предоставим среду исполнения, в которой LLM сможет писать и запускать код напрямую. Вот что значит дать агенту компьютер.»*
2. "A sandbox is isolated from external systems so that code can be executed safely." — *«Песочница изолирована от внешних систем, благодаря чему код может выполняться безопасно.»*
3. "Agent skills maximizes token efficiency by progressively disclosing tool information and solves tool-portability problems through a folder-based structure." — *«Навыки агента максимизируют эффективность использования токенов за счёт поэтапного раскрытия информации об инструментах и решают проблему переносимости инструментов благодаря папочной структуре.»*

#### Summary / Резюме главы 8

* Подход с предопределёнными инструментами ограничен жестким списком функций, создает задержки при итерационных вызовах и раздувает промт при росте числа инструментов.
* Исполнение кода (подход CodeAct) расширяет возможности агента за счёт управляющего потока (**control flow**), сохранения промежуточных данных (**data flow**) и композиции инструментов (**tool composition**).
* Исполнение кода требует изоляции в облачной песочнице (E2B sandbox) для обеспечения безопасности, контроля ресурсов и сохранения состояния.
* Переносимые инструменты (sandbox_executable=True) извлекают свой исходный код и выполняются внутри песочницы, сводя 31 вызов LLM к 1 запуску кода.
* Рабочее пространство (**Workspace**) предоставит агенту файловую систему и CLI (bash_tool, upload_file).
* Навыки агента (**Agent Skills**) реализуют поэтапное раскрытие токенов (**progressive disclosure**) через файловую структуру с SKILL.md и YAML-заголовком, снижая затраты на контекст в сотни раз.
