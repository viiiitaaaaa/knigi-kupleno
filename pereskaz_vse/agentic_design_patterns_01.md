## Chapter 1. Prompt Chaining / Глава 1. Цепочки промптов

#### Главная мысль автора

Вместо того чтобы требовать от большой языковой модели (LLM) решения сложной многосоставной задачи за один монолитный шаг, следует применять стратегию «разделяй и властвуй» (divide-and-conquer), разбивая задачу на последовательность мелких управляемых подзадач, где выходные данные предыдущего промпта передаются на вход следующему.

#### Ключевые формулировки автора

1. *"Rather than expecting an LLM to solve a complex problem in a single, monolithic step, prompt chaining advocates for a divide-and-conquer strategy."* — «Вместо того чтобы ожидать от LLM решения сложной проблемы за один монолитный шаг, цепочки промптов предлагают стратегию "разделяй и властвуй".»
2. *"The output of one step acting as the input for the next is crucial. This passing of information establishes a dependency chain, hence the name..."* — «Выходные данные одного шага, выступающие в качестве входных данных для следующего, имеют решающее значение. Эта передача информации формирует цепочку зависимостей, откуда и название...»
3. *"Context Engineering is the systematic discipline of designing, constructing, and delivering a complete informational environment to an AI model prior to token generation."* — «Инженерия контекста — это систематическая дисциплина проектирования, конструирования и предоставления полной информационной среды ИИ-модели перед генерацией токенов.»

#### Prompt Chaining Pattern Overview / Обзор паттерна цепочек промптов

##### Мысли автора по порядку

* Паттерн цепочек промптов (Prompt Chaining), также называемый паттерном конвейера (Pipeline pattern), представляет собой парадигму обработки сложных задач с помощью больших языковых моделей.
* Основная идея заключается в разделении исходной сложной задачи на последовательность более простых подзадач.
* Каждая подзадача решается с помощью специально составленного промпта, а результат работы одного промпта стратегически передается в качестве входных данных в следующий промпт цепочки.
* Последовательная обработка обеспечивает модульность, ясность, простоту отладки и интерпретируемость каждого отдельного шага.
* Передача информации формирует цепочку зависимостей, позволяя модели строить выводы на базе предыдущей работы и уточнять понимание.
* Паттерн позволяет интегрировать внешние знания и инструменты на любом шаге цепочки, обращаясь к сторонним API и базам данных.
* Ограничения одиночных промптов (Single prompts): при попытке решить сложную задачу одним промптом модель сталкивается с высокими рисками игнорирования инструкций (instruction neglect), контекстного дрейфа (contextual drift), усиления ошибок (error propagation) и галлюцинаций из-за высокой когнитивной нагрузки.
* Повышение надежности через последовательную декомпозицию: сложный процесс разбивается на узкофокусированные шаги, где модели на каждом шаге может назначаться отдельная роль (например, «Аналитик рынка», «Торговый аналитик», «Эксперт-документовед»).
* Роль структурированного вывода (Structured Output): надёжность цепочки зависит от целостности передаваемых данных. Для предотвращения сбоев из-за нечеткого естественного языка используется форматирование вывода в JSON или XML.

##### Цифры, примеры и истории

* **Пример (анализ отчета о рыночных исследованиях):** Пользователь запрашивает анализ отчета, выделение трендов с цифрами и составление письма. В монолитном промпте модель часто пропускает извлечение данных или написание письма. При цепочке:
  * *Шаг 1 (Резюмирование):* Промпт к роли «Market Analyst» резюмирует ключевые выводы отчета.
  * *Шаг 2 (Идентификация трендов):* Промпт к роли «Trade Analyst» извлекает 3 главных тренда и подтверждающие цифры из резюме.
  * *Шаг 3 (Составление письма):* Промпт к роли «Expert Documentation Writer» составляет итоговое письмо маркетологам.
* **Пример структурированного JSON-вывода:** Извлечение трендов форматируется в JSON-объект:
  * Транд 1: «AI-Powered Personalization», данные: **73%** потребителей предпочитают бренды, использующие персональные данные.
  * Тренд 2: «Sustainable and Ethical Brands», данные: продажи товаров с ESG-заявлениями выросли на **28%** за последние **5 лет** по сравнению с **20%** для товаров без них.
* **Пример (извлечение данных из форм и OCR PDF):** Обработка PDF-документов включает извлечение текста, нормализацию данных (например, перевод текстового числа «one thousand and fifty» в числовую форму **1050**) и делегирование точных арифметических расчетов внешнему калькулятору.

##### Что делает пример кода (без самого кода)

* В примере кода на LangChain и LCEL демонтируется двухшаговый конвейер обработки текста.
* Инициализируется модель ChatOpenAI(temperature=0) и парсер вывода StrOutputParser().
* Первый промпт (prompt_extract) извлекает технические спецификации из текста с описанием ноутбука («3.5 GHz octa-core processor, 16GB of RAM, and a 1TB NVMe SSD»).
* Второй промпт (prompt_transform) преобразует извлечённые спецификации в JSON-объект с ключами cpu, memory и storage.

#### Practical Applications & Use Cases / Практические применения и варианты использования

##### Мысли автора по порядку

1. **Рабочие процессы обработки информации (Information Processing Workflows):** Извлечение текста из URL -> очистка и резюмирование -> извлечение сущностей (имена, даты, локации) -> поиск в локальной базе знаний -> генерация итогового отчета.
2. **Ответы на сложные запросы (Complex Query Answering):** Выделение подвопросов -> отдельное исследование каждой части -> синтез единого ответа. Использует гибридный подход: параллельный сбор данных и последовательное цепочечное резюмирование.
3. **Извлечение и трансформация данных (Data Extraction and Transformation):** Итеративное извлечение полей из счетов/форм с проверкой качества и условными повторными промптами при обнаружении пропусков или ошибок.
4. **Рабочие процессы генерации контента (Content Generation Workflows):** Идея (5 тем) -> выбор пользователем -> составление плана -> последовательное написание черновика по разделам с передачей контекста предыдущих частей -> итоговая вычитка стиля и грамматики.
5. **Разговорные агенты с состоянием (Conversational Agents with State):** Сохранение диалогового контекста путем передачи накопленной истории и сущностей в каждый новый ход диалога.
6. **Генерация и рефакторинг кода (Code Generation and Refinement):** Псевдокод/план -> черновик кода -> поиск ошибок (статический анализ / LLM) -> исправление кода -> добавление документации и тестов.
7. **Мультимодальные и многошаговые рассуждения (Multimodal and multi-step reasoning):** Анализ изображений со встроенным текстом и таблицами: извлечение текста -> сопоставление текста с метками -> интерпретация с помощью таблицы.

##### Цифры, примеры и истории

* В примере сложных запросов рассматривается вопрос: *"Каковы были основные причины краха фондового рынка 1929 года и как отреагировало правительство?"*.
* В примере генерации идей предлагается создать **5** идей тем.
* В примере извлечения данных из нормализованного текста число «one thousand and fifty» конвертируется в число **1050**.

#### Context Engineering and Prompt Engineering / Инженерия контекста и инженерия промптов

##### Мысли автора по порядку

## Chapter 2. Routing / Глава 2. Маршрутизация

#### Главная мысль автора

Линейные цепочки ограничены в адаптивных сценариях; маршрутизация вводит условную логику в операционный фреймворк агента, позволяя динамически выбирать следующий путь исполнения, инструмент или под-агент на основе анализа контекста, намерений пользователя или состояния среды.

#### Ключевые формулировки автора

1. *"Routing introduces conditional logic into an agent's operational framework, enabling a shift from a fixed execution path to a model where the agent dynamically evaluates specific criteria..."* — «Маршрутизация вводит условную логику в операционную структуру агента, позволяя перейти от фиксированного пути выполнения к модели, в которой агент динамически оценивает конкретные критерии...»
2. *"It transforms an agent from a static executor of pre-defined sequences into a dynamic system that can make decisions about the most effective method for accomplishing a task under changing conditions."* — «Она превращает агента из статического исполнителя предопределенных последовательностей в динамическую систему, способную принимать решения о наиболее эффективном методе выполнения задачи в меняющихся условиях.»

#### Routing Pattern Overview / Обзор паттерна маршрутизации

##### Мысли автора по порядку

* Реальные автономные системы должны принимать динамические решения в зависимости от входных данных или промежуточных результатов.
* Маршрутизация добавляет развилки (условную логику), смещая архитектуру от жесткого пути к адаптивной.
* **Пример маршрутизации поддержки клиентов:**
  1. Анализ запроса пользователя.
  2. Маршрутизация по намерению (intent):
    * «check order status» -> под-агент/инструмент базы заказов.
    * «product information» -> поиск по каталогу товаров.
    * «technical support» -> гайды по устранению неполадок / эскалация на человека.
    * «unclear» -> под-агент уточнения.
* **4 механизма реализации маршрутизации:**
  1. *LLM-based Routing:* LLM классифицирует запрос и выдает идентификатор категории (например, 'Order Status', 'Technical Support').
  2. *Embedding-based Routing:* Запрос преобразуется в векторный эмбеддинг и сравнивается по семантическому сходству с векторными описаниями путей.
  3. *Rule-based Routing:* Жесткие правила (if-else, ключевые слова, регулярные выражения). Быстро и детерминировано, но негибко.
  4. *Machine Learning Model-Based Routing:* Использование дискриминативной обученной модели-классификатора. Логика запечена в весах модели, генеративная LLM на этапе инференса не вызывается.
* Маршрутизация применяется на входе (классификация задачи), в середине цепочки или внутри подпрограмм для выбора инструмента.

#### Practical Applications & Use Cases / Практические применения и варианты использования

##### Мысли автора по порядку

* **Взаимодействие человека и компьютера (HCI):** Виртуальные ассистенты и ИИ-тьюторы классифицируют намерения для вызова поиска, эскалации или выбора обучающего модуля.
* **Автоматизированная обработка данных и документов:** Входящие тикеты/письма распределяются по отделам (продажи, конвертация JSON/CSV, срочная эскалация).
* **Высокоуровневый диспетчер под-агентов:** Исследовательская система распределяет подзадачи между агентами поиска, суммаризации и анализа. Кодинг-ассистент определяет язык и намерение (debug, explain, translate) перед вызовом инструмента.

#### At a Glance / Краткий обзор

##### Мысли автора по порядку

* **Что:** Линейные процессы не способны адаптироваться к разным типам входящих ситуаций.

## Chapter 3. Parallelization / Глава 3. Параллелизация

#### Главная мысль автора

Многие сложные агентные задачи содержат независимые подзадачи; параллельное выполнение вызовов LLM, инструментов или под-агентов позволяет кардинально снизить общее время задержки (latency) и повысить производительность системы.

#### Ключевые формулировки автора

1. *"Parallelization involves executing multiple components, such as LLM calls, tool usages, or even entire sub-agents, concurrently."* — «Параллелизация включает одновременное выполнение нескольких компонентов, таких как вызовы LLM, использование инструментов или даже целые под-агенты.»
2. *"By running these independent tasks at the same time rather than one after another, this pattern drastically reduces the total execution time."* — «Запуская эти независимые задачи одновременно, а не одну за другой, этот паттерн кардинально сокращает общее время выполнения.»

#### Parallelization Pattern Overview / Обзор паттерна параллелизации

##### Мысли автора по порядку

* В отличие от последовательных цепочек и маршрутизации, параллелизация выполняет независимые шаги одновременно.
* Освещается сравнение подходов при исследовании темы:
  * *Последовательный подход:* Поиск источника А -> Резюме А -> Поиск источника B -> Резюме B -> Синтез.
  * *Параллельный подход:* Одновременный поиск А и B -> Одновременное резюмирование А и B -> Последовательный синтез итогового ответа.
* Паттерн особенно эффективен при задержках ввода-вывода (I/O) и вызовах внешних API.
* Фреймворки поддерживают асинхронное исполнение: LangChain LCEL (через параллельные словари/рунаблы), LangGraph (несколько параллельных узлов из одного состояния) и Google ADK (ParallelAgent).

#### Practical Applications & Use Cases / Практические применения и варианты использования

##### Мысли автора по порядку

1. **Сбор информации и исследования (Information Gathering and Research):** Анализ компании — параллельный поиск новостей, котировок акций, упоминаний в соцсетях и данных из корпоративной БД.
2. **Обработка и анализ данных (Data Processing and Analysis):** Анализ обратной связи — одновременный тональный анализ, извлечение ключевых слов, категоризация и подсвечивание срочных проблем по пакету отзывов.
3. **Взаимодействие с несколькими API/инструментами (Multi-API or Tool Interaction):** Планировщик путешествий — параллельный запрос цен на авиабилеты, отелей, мероприятий и ресторанов.
4. **Генерация контента из нескольких компонентов (Content Generation):** Маркетинговое письмо — параллельная генерация темы, тела письма, подбор картинки и текста для кнопки призыва к действию.
5. **Валидация и проверка (Validation and Verification):** Проверка данных пользователя — одновременная проверка формата email, валидация телефона, проверка адреса по БД и фильтрация ненормативной лексики.
6. **Мультимодальная обработка (Multi-Modal Processing):** Анализ поста с текстом и фото — параллельный анализ текста и распознавание объектов на изображении.
7. **A/B тестирование и генерация вариантов (A/B Testing or Multiple Options Generation):** Одновременная генерация **3** вариантов заголовков с помощью разных промптов или моделей для выбора лучшего.

#### Hands-On Code Example (LangChain) / Практический пример кода (LangChain)

##### Мысли автора по порядку

* Параллельное исполнение в LCEL достигается путем размещения нескольких Runnable объектов в словаре (RunnableParallel).
* Установка библиотек: pip install langchain langchain-community langchain-openai.
* Автор делает важное техническое замечание: asyncio в Python обеспечивает конкурирование (concurrency), а не истинный многопроцессорный параллелизм, работая в одном потоке с циклом событий (event loop) в рамках GIL.

##### Что делает пример кода (без самого кода)

* Код параллельно обрабатывает тему *"The history of space exploration"*.
* Используется модель ChatOpenAI(model="gpt-4o-mini", temperature=0.7).
* Создаются **3** независимые цепочки:
  1. summarize_chain — краткое резюме темы.
  2. questions_chain — генерация **3** интересных вопросов по теме.
  3. terms_chain — выделение от **5 до 10** ключевых терминов через запятую.
* Блок RunnableParallel (map_chain) объединяет эти три цепочки и сохраняет исходный текст через RunnablePassthrough().
* Промпт synthesis_prompt принимает резюме, вопросы и термины, а финальная цепочка full_parallel_chain синтезирует единый структурированный ответ.
* Функция запускается асинхронно через asyncio.run() с вызовом ainvoke.

#### Hands-On Code Example (Google ADK) / Практический пример кода (Google ADK)

##### Мысли автора по порядку

* В Google ADK параллелизация реализуется с помощью класса ParallelAgent.

##### Что делает пример кода (без самого кода)

* Создаются **3** исследовательских под-агента LlmAgent с моделью gemini-2.0-flash и инструментом google_search:
  1. researcher_agent_1 — исследование возобновляемой энергетики.
  2. researcher_agent_2 — исследование электромобилей.
  3. researcher_agent_3 — исследование методов улавливания углерода.
* Каждый агент сжимает выводы до **1–2 предложений** и сохраняет их в состояние сессии через output_key.
* Класс ParallelAgent (ParallelWebResearchAgent) запускает всех трех исследователей одновременно.
* Объединяющий агент merger_agent (SynthesisAgent) считывает результаты из состояния и формирует итоговый структурированный отчет с заголовками и строгой опирой только на полученные данные.
* Вся цепочка объединяется в SequentialAgent (ResearchAndSynthesisPipeline), где сначала отрабатывает ParallelAgent, а затем merger_agent.

#### At a Glance / Краткий обзор

##### Мысли автора по порядку

* **Что:** Последовательное выполнение независимых подзадач приводит к задержкам и узким местам из-за ожидания сетевых I/O вызовов.
* **Почему:** Паттерн Parallelization запускает независимые задачи одновременно, кардинально сокращая общее время работы.
* **Правило:** Используйте параллелизацию при наличии нескольких независимых операций (запросы к нескольким API, обработка фрагментов данных, генерация частей контента).

#### Key Takeaways / Ключевые выводы
