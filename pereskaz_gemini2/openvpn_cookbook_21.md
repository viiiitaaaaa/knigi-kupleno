### Перезапуск DNS-кэша · Принудительно перезапускайте службу кэширования DNS и сбрасывайте кэш сразу после установки соединения с помощью команды регистрации DNS. · Директива `registerdns` выполняет команды `net stop dnscache`, `net start dnscache`, `ipconfig /flushdns` и `ipconfig /registerdns`. · (стр. 110)

### Работа службы без входа пользователя · Настройте запуск OpenVPN как службы Windows, чтобы соединение устанавливалось до входа пользователя в систему. · Установите в реестре `allow_service` в `1`, а в оснастке «Службы» переведите тип запуска OpenVPN Service в положение «Автоматически». · (стр. 111)

### Системный сертификат для службы · Учитывайте, что служба OpenVPN работает от учетной записи SYSTEM, поэтому используемые сертификаты должны быть установлены в локальное хранилище системы, а не пользователя. · При использовании директивы `cryptoapicert` импортированный сертификат должен быть установлен как сертификат (локальной) системы. · (стр. 111)

### Обход сетевого класса Public · Предотвратите проблему с недоступностью общих папок и принтеров на клиентах Windows, задав сетевому адаптеру правильный тип сети. · Добавьте на сервере маршрут по умолчанию с высоким метрическим коэффициентом: `push "route 0.0.0.0 0.0.0.0 vpn_gateway 300"`. · (стр. 112)

### Выбор метода добавления маршрутов · Управляйте способом добавления маршрутов в таблицы маршрутизации Windows с помощью директивы `route-method`. · Используйте параметры `ipapi` (встроенные функции), `exe` (через внешнюю программу `route.exe`) или `adaptive` (автоматический выбор с запасным вариантом). · (стр. 113)

### Проверка успешности добавления маршрутов · Всегда проверяйте лог-файл клиента, так как OpenVPN не прерывает соединение при неудачном добавлении маршрута, а графический интерфейс (GUI) все равно покажет зеленую иконку успеха. · Установите уровень детализации лога `verb 5` и ищите в конце лога строки вроде `Route addition via IPAPI succeeded`. · (стр. 113)

### Безопасность DNS-запросов · Предотвратите утечку DNS-запросов через другие сетевые адаптеры в Windows 8.1+ с помощью специального механизма фильтрации. · Добавьте в конфигурационный файл клиента директиву `block-outside-dns`. · (стр. 114)

### Ошибка множественных туннелей DNS · Соблюдайте осторожность при использовании `block-outside-dns` в OpenVPN 2.3 с несколькими одновременными туннелями. · Правила фильтрации (WFP) первого туннеля могут некорректно восстановиться при закрытии второго, полностью заблокировав весь DNS-трафик. · (стр. 114)

### Инлайн-конфигурация для мобильных устройств · Упаковывайте все сертификаты и ключи внутрь профиля мобильного клиента в виде тегов (`<ca>`, `<cert>`, `<key>`, `<tls-auth>`), чтобы упростить перенос конфигурации на Android или iOS. · Превратите `.ovpn` файл в автономный файл конфигурации, заменив ссылки на внешние файлы встроенными блоками. · (стр. 115)

### Сохранение расширения при передаче файлов · Убедитесь, что тип файла и расширение `.ovpn` остаются неизменными при передаче конфигурации через веб-сервер на мобильное устройство, иначе передавайте файл внутри архива `.zip`. · Мобильное устройство будет обрабатывать конфигурацию как обычный текст, если не распознает её как профиль OpenVPN. · (стр. 116)

### Передача информации клиента на сервер · Настройте отправку параметров с клиентского устройства на сервер для адаптации настроек под конкретные платформы. · Добавьте в конфигурацию клиента опцию `push-peer-info`, а на сервере используйте скрипт `client-connect` с проверкой переменных окружения вроде `IV_PLAT`. · (стр. 116)
