### Безопасность управления · Всегда задавать локальный IP и пароль для интерфейса управления · Указывайте `127.0.0.1` для IP интерфейса управления на сервере и защищайте его надежным паролем, так как через него можно отправить команду завершения работы (`signal SIGTERM`). · (стр. 8)

### Ошибки прав доступа · Не использовать пользователя `nobody` со скриптами ARP · Если для работы скриптов (`proxyarp-*.sh`) требуются привилегии root (`/sbin/arp`), нельзя переключаться на пользователя `nobody` / группу `nogroup`, иначе скрипты перестанут работать. (В качестве альтернативы можно настроить `sudo`). · (стр. 39)

### Контекст сети · Оценивать ограничения Proxy ARP для широковещательного трафика · Proxy ARP может не подойти для приложений, требующих полноценного общего широковещательного домена; для таких случаев лучше использовать Ethernet-мосты (bridging). · (стр. 39)

### Планирование архитектуры · Избегать мостов (bridging) без крайней необходимости · Мосты ухудшают производительность и безопасность; используйте их только как последний вариант, когда остальные методы не подходят. · (стр. 40)

### Планирование сети · Использовать протокол UDP по умолчанию · UDP обеспечивает оптимальную производительность, но при проблемах с прохождением у провайдеров конфигурацию можно легко переключить на TCP в файлах клиента и сервера. · (стр. 41)

### Проверка результата · Перманентное включение пересылки IP на Linux · Для постоянной работы IP-forwarding добавляйте `net.ipv4.ip_forward=1` в `/etc/sysctl.conf` и применяйте командой `sysctl -p`. · (стр. 41)

### Масштабируемость · Учитывать влияние широковещательного трафика в TAP-сетях · При включении `client-to-client` в TAP-режиме весь широковещательный трафик от каждого клиента пересылается остальным, что может вызвать проблемы с масштабируемостью при большом числе подключений. · (стр. 42)
