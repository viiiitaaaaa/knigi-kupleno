### Совмещение портов · Настроить OpenVPN на совместное использование TCP-порта (например, 443) с веб-сервером с помощью директивы `port-share`, чтобы обрабатывать VPN-трафик и пересылать остальной трафик на локальный порт веб-сервера. · Использовать `port 443` и `port-share localhost 8443` в конфигурации сервера. · (стр. 127)

### Обход локальной сети и DNS · Использовать параметры `bypass-dhcp` и `bypass-dns` для директив `redirect-gateway` или `redirect-private`, чтобы трафик DHCP и DNS шел напрямую, а не через VPN-туннель. · Добавить строку `push "redirect-private bypass-dhcp bypass-dns"` на сервере. · (стр. 128)

### Использование доменных имен в маршрутах · Разрешить клиентам запрашивать доменные имена (FQDN) от сервера для создания маршрутов, добавив соответствующую директиву в конфиг клиента. · Добавить `allow-pull-fqdn` в конфигурационный файл клиента. · (стр. 128)

### Фильтрация получаемых от сервера опций · Использовать директиву `pull-filter` на клиенте для управления маршрутами и адресами, передаваемыми с сервера (`accept`, `ignore`, `reject`). · Добавить строку `pull-filter ignore "dhcp-option DNS"` в конфиг клиента. · (стр. 129)

### Выделение публичных IP-адресов клиентам · Использовать топологию `subnet`, пул адресов и скрипты `client-connect`/`client-disconnect` с командами ARP для выдачи клиентам реальных IP-адресов без перерасхода адресного пространства. · Применить связку `topology subnet`, `ifconfig-pool` и скрипты с `/sbin/arp -i eth0 -Ds ... pub`. · (стр. 130)
