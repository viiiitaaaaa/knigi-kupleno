### Использование директивы `dev-node` · Указывайте имя адаптера через `dev-node` на Windows, так как схема именования TAP-адаптеров там отличается от Linux. · Пример из текста: `dev tap` и `dev-node tapbridge`. · (стр. 44)

### Фиксация MAC-адреса клиента · Задавайте уникальный MAC-адрес в конфигурационном файле клиента с помощью директивы `lladdr`, чтобы при перезапуске клиенту не выделялся новый динамический IP. · Пример из текста: `lladdr CA:C6:F8:FB:EB:3B`. · (стр. 46)

### Использование внешнего DHCP-сервера с ретрансляцией · Комбинируйте команду `dhrelay` (перечисляя TAP и Ethernet адаптеры) со скриптом proxy-arp, чтобы использовать внешний DHCP-сервер без организации моста. · Пример из текста: `[root@server]# dhrelay -i tap0 -i eth0`. · (стр. 46)

### Защита от потери шлюза по умолчанию при DHCP · Добавляйте директиву `push "route 0.0.0.0 255.255.255.255 net_gateway"`, чтобы клиент не терял прямой маршрут к OpenVPN-серверу при получении настроек от внешнего DHCP. · Пример из текста: `push "route 0.0.0.0 255.255.255.255 net_gateway"`. · (стр. 46)

### Настройка игнорирования шлюза DHCP в Linux · Добавляйте параметр `GATEWAYDEV=eth0` в конфигурационные файлы сетевых скриптов (`/etc/sysconfig/network-scripts/ifup-tap0`), чтобы скрипт `dhclient` игнорировал шлюз, приходящий от внешнего DHCP-сервера. · Пример из текста: `GATEWAYDEV=eth0`. · (стр. 46)

### Мониторинг подключений через файл статуса · Добавляйте директиву `status` в конфигурацию сервера для записи списка клиентов и таблицы маршрутизации в файл мониторинга. · Пример из текста: `status /var/log/openvpn.status`. · (стр. 47)
