### Передача максимума данных в JSON · Возвращайте результаты работы сервисов и API в виде полных JSON-документов (строк), чтобы LLM могла самостоятельно и гибко их парсить, фильтровать, сортировать и трансформировать вместо получения простых списков названий. · Пример: В версии `tmdb_v2.py` функция `get_top_movies_by_genre` возвращает отфильтрованные фильмы через `json.dumps(filtered_movies)`. · (стр. 125–127)

### Создание плагинов через декоратор · Превращайте функции в кастомные действия ИИ-ассистента с помощью простого добавления файла в специальную папку и использования специального декоратора. · Пример: В файле `file_actions.py` функция сохранения файла помечена декоратором `@agent_action`. · (стр. 138–140)

### Локальный запуск кода ИИ · Запускайте код, сгенерированный ассистентом, локально в изолированном виртуальном окружении с помощью специальных экшенов `run_code` и `run_shell_command`, что позволяет агенту автоматически устанавливать нужные модули (`pip install`) и итерировать решение. · Пример: Включение действий `run_code` и `run_shell_command` в интерфейсе Playground для запуска игры «Змейка». · (стр. 140–142)

### Изоляция контекста агентов по потокам · Разделяйте агентов по разным цепочкам сообщений (threads), чтобы изолировать их работу от лишнего шума и нерелевантных обсуждений других участников. · Пример: В коде `agentic_btree_coding_challenge.py` проверяющий агент (`verifier`) работает на отдельном потоке, в то время как хакер и судья делят общий поток. · (стр. 147–149)

### Ограничение контекста и задач агентов · Старайтесь создавать узкоспециализированных ассистентов под конкретные цели и выдавайте им минимально необходимый набор действий, чтобы избежать галлюцинаций и ошибок принятия решений. · Пример: Использование менеджера (`Manager Assistant`) с мощными правами только для администрирования, а остальных задач — строго по профилю. · (стр. 144)

### Использование файлов для передачи данных между агентами · Передавайте результаты работы между агентами через общие файлы (например, `solution.py`, `judged_solution.py`), а не только через длинные чаты, что снижает уровень «шума» и объем повторяющихся мыслей у LLM. · Пример: Хакер сохраняет код в `solution.py`, судья считывает его и пишет в `judged_solution.py`. · (стр. 147–149)

### Троттлинг запросов к LLM · Регулируйте паузы между тиками дерева поведения (например, с помощью `time.sleep()`), чтобы контролировать частоту и интенсивность запросов, отправляемых к языковой модели. · Пример: Добавление `time.sleep(20)` в цикл тиков дерева поведения в файле `agentic_btree_coding_challenge.py`. · (стр. 149)
