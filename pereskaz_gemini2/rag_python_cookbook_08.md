### Мониторинг и трассировка · Записывайте каждый запуск агента в отдельную запись (транрскт/трейс) с полными шагами выполнения и историей вызовов инструментов, используя встроенные средства SDK. · Пример из текста: Просмотр трейсов на платформе OpenAI Platform Traces, где каждый запуск логируется отдельно. (стр. 257)

### Предотвращение бесконечных циклов · Используйте встроенные в SDK средства управления и защитные барьеры (guardrails) для предотвращения зацикливания агента. · Пример из текста: Использование встроенных функций трассировки, защитных барьеров и элементов контроля для предотвращения бесконечных циклов в OpenAI Agents SDK. (стр. 257)

### Управление состоянием и контекстом · Передавайте общую историю диалога (conversation history) от модератора к каждому специализированному суб-агенту для координации их работы. · Пример из текста: Модератор передает историю разговора каждому суб-агенту при реализации паттерна многосторонних взаимодействий. (стр. 258)

### Оптимизация задержек и стоимости (экономия лимита) · Избегайте многоуровневых перенаправлений (hand-offs) между агентами там, где критична задержка, так как каждый переход требует полноценного вызова LLM и линейно увеличивает расходы. · Пример из текста: Избегайте паттерна иерархической делегации, когда критична задержка; используйте прямые вызовы функций для простых задач без диалога. (стр. 258)

### Обработка ошибок подключения и таймаутов · Увеличивайте стандартные тайм-ауты клиентских сессий при подключении к внешним серверам инструментов (например, через MCP) до 30–60 секунд и обрабатывайте сетевые сбои. · Пример из текста: `async with MCPServerStdio(params=params, client_session_timeout_seconds=30) as server:` (стр. 261, 262)

### Безопасность при работе с внешними инструментами · Учитывайте, что MCP-серверы принимают сетевые запросы, расширяют поверхность атаки и требуют реализации аутентификации, авторизации и валидации входных данных. · Пример из текста: Каждый MCP сервер расширяет вашу поверхность атаки, требуя аутентификации, авторизации и валидации входных данных в отличие от локальных вызовов функций. (стр. 264)

### Ограничение контекста и шагов (LangGraph) · Добавляйте счетчики шагов в состояние агента (state) для контроля и ограничения глубины выполнения графических рабочих процессов. · Пример из текста: `class AgentState(TypedDict): messages: Annotated[Sequence[BaseMessage], add_messages] number_of_steps: int` (стр. 251)

### Проверка результата и обработка ошибок в тулах · Обязательно оборачивайте логику пользовательских инструментов (tools) в блоки `try-except`, чтобы возвращать ошибки в виде словарей, а не обрывать работу агента. · Пример из текста: Возврат словаря с ошибкой `return {"error": str(e)}` внутри функции-инструмента получения погоды или транскрипции аудио. (стр. 266)

### Планирование и управление потоком выполнения (LangGraph) · Используйте явное описание графов состояний с узлами, рединами и условиями продолжения для отладки неожиданных решений агента. · Пример из текста: Использование условных ребер (`should_continue`), проверяющих наличие вызовов инструментов (`tool_calls`) перед завершением работы графа. (стр. 253, 254)

### Безопасность учетных данных · Храните конфиденциальные данные (ключи, доступы к базам данных) в файле `.env` с помощью библиотеки `python-dotenv` и никогда не фиксируйте их в системе контроля версий. · Пример из текста: `NEO4J_URI=neo4j://localhost:7687`, `NEO4J_USERNAME=neo4j`, `NEO4J_PASSWORD=testpassword` (стр. 265)

### Предотвращение дублирования данных · Создавайте уникальные ограничения (constraints) в графовых базах данных (например, Neo4j) перед импортом сущностей, чтобы избежать дублирования узлов при операциях слияния. · Пример из текста: `CREATE CONSTRAINT sla_id IF NOT EXISTS FOR (s:SLA) REQUIRE s.id IS UNIQUE` (стр. 265)
