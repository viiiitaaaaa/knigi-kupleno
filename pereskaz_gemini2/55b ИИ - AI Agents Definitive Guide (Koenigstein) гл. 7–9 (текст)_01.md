### Управление историей диалога (Context Janitor) · Очищайте старый контекст, оставляя системный промпт и последние $N$ сообщений, а промежуточную часть заменяйте сводкой (стр. 7).
Пример из текста: Функция `prune_history()` сокращает историю, если она превышает лимит токенов, добавляя системное сообщение с описанием удаленного участка (стр. 7).
(стр. 7)

### Предотвращение зацикливания (Circuit Breaker) · Внедряйте жесткие лимиты на стоимость сессии и количество шагов (оборотов), чтобы аварийно останавливать агента при бесконечных циклах (стр. 8).
Пример из текста: Класс `AgentSession` и функция `check_circuit_breaker()` выбрасывают исключение, если превышен бюджет (`BUDGET_CAP`) или лимит ходов (`MAX_TURNS`) (стр. 8).
(стр. 8)

### Персистентность и восстановление (Checkpointing) · Сохраняйте сериализуемое состояние сессии агента после каждого хода, чтобы возобновлять работу с места сбоя, а не начинать сначала (стр. 8–9).
Пример из текста: Функции `save_checkpoint()` и `load_checkpoint()` записывают состояние сессии (историю, счетчики, затраты) в JSON-файл для восстановления после падения процесса (стр. 8–9).
(стр. 8–9)

### Безопасность и логирование трейсов · Настраивайте правила маскирования конфиденциальных данных (PII, секреты) и логируйте 100% ошибок в продакшене, а успешные трейсы — выборочно (10–25%) (стр. 6).
Пример из текста: Правило для логов: определите правила удаления секретов перед включением трейсинга, логируйте все ошибки, но только часть успешных запусков для экономии бюджета (стр. 6).
(стр. 6)

### Обработка долгоиграющих задач · Избегайте стандартных REST POST запросов с таймаутами; используйте WebSockets или Server-Sent Events (SSE) для стриминга прогресса агента (стр. 6).
Пример из текста: Рекомендация в FastAPI-настройке использовать SSE или WebSockets вместо 30-секундных REST-таймаутов для долгих рассуждений агента (стр. 6).
(стр. 7)

### Стратегия фоллбэков (Fallback Model) для структурированного вывода · Реализуйте многоуровневую защиту (строгая схема через провайдера, валидация через Pydantic/Instructor и аварийную канонизацию), так как валидный JSON не гарантирует стабильность логики (стр. 10–16).
Пример из текста: Трехуровневая система: Tier 1 (Strict JSON Schema), Tier 2 (Instructor + Pydantic с автоповторами), Tier 3 (деградированный промпт и функция `canonicalize` для исправления чужих ключей) (стр. 10–16).
(стр. 10–16)

### Нормализация ответов модели (Normalization Maps) · Используйте словари сопоставления для приведения нестандартных текстовых меток модели к единым системным значениям, защищаясь от дрейфа моделей (стр. 11).
Пример из текста: `CATEGORY_MAP`, `PRIORETY_MAP` и `SENTIMENT_MAP` переводят разные варианты ответов модели (например, «urgent», «high») в строгие внутренние категории (стр. 11).
