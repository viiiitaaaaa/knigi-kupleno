### Контракты и валидация через Pydantic · Определяйте жесткие контракты на входе в систему и валидируйте данные с помощью Pydantic на границах системы, чтобы ошибки и несоответствия типов не распространялись дальше. · `class UserData(BaseModel): user_id: int; age: int = Field(ge=0, le=150)` (стр. 1)

### Динамические контракты (паттерн «Фабрика») · Создавайте Pydantic-модели на лету с помощью фабричных функций под актуальные системные политики, чтобы система была независима от конкретных моделей (model-agnostic). · `def build_image_prompt_model(policy_dict, mode, policy_hash): ... class ImagePrompt(BaseModel): ...` (стр. 2)

### Защита от дрейфа состояния (хэширование политик) · Защищайте систему от изменений в процессе работы (mid-run drift), фиксируя (pinning) политику на старте и создавая уникальный хэш спецификаций и схемы. · `policy_hash = hash_policy(policy_dict)` и `schema_hash = sha256_text(...)` (стр. 3)

### Семантическая обратная связь при ошибках · Возвращайте LLM понятную семантическую обратную ошибку (вместо сырых стектрейсов), чтобы агент мог скорректировать свои действия при повторной попытке. · `last_error: e.errors()[0]["msg"]` возвращает текст ошибки в структуру для агента (стр. 3)

### Отказоустойчивость через чекпоинты (Time Travel) · Используйте чекпоинтеры (например, `InMemorySaver` или `PostgresSaver`) для сохранения рабочего состояния, чтобы при сбое или повторной попытке возобновлять работу с последнего стабильного узла без перерасхода токенов на предыдущие шаги. · `memory = InMemorySaver(); app = workflow.compile(checkpointer=memory)` (стр. 4)

### Разделение циклов коррекции (Inner vs Outer Loop) · Разделяйте исправление мелких ошибок генерации внутри модели (через библиотеку Instructor в цикле запроса) и системные ошибки рабочего процесса (через граф и Pydantic на границе). · Использование `Instructor` для генерации и `LangGraph` для оркестрации (стр. 5)

### Транспорт и безопасность MCP (Model Context Protocol) · Используйте `stdio` для локальной разработки, а для продакшна выбирайте HTTP/Streamable HTTP или gRPC; для параллельных вызовов применяйте соединения на каждый вызов и режим SQLite WAL для предотвращения гонки потоков. `mcp.run(transport="stdio")` (стр. 6)

### Изоляция контекста с помощью подрагентов (Subagents) · Делегируйте ресурсоемкие операции (поиск, чтение файлов) подрагентам, чтобы изолировать контекстное окно главного агента от промежуточного «мусора» и передавать наверх только финальный результат. · Использование параметра `subagents` для изоляции контекста (стр. 9)

### Использование файлов AGENTS.md и SKILL.md · Применяйте файлы `AGENTS.md` (для описания роли, тона и стандартов качества) и `SKILL.md` (для границ возможностей и ограничений), чтобы задавать для агента воспроизводимые контракты поведения. · Создание файлов `SKILL.md` и `AGENTS.md` (стр. 9)

### Продуктовые требования для кодинга (PRP) · Предоставляйте агентам структурированную спецификацию (Product Requirement Prompt), включающую точные пути к файлам, версии библиотек, примеры кода и команды для валидации. · Использование PRP вместо одиночной инструкции для работы в кодовой базе (стр. 13)

### Политики управления инструментами и бюджетами (Governance Policy) · Ограничивайте поведение агента с помощью политик (списки разрешенных/запрещенных инструментов, запрет на совмещение обнаружения и выполнения в одном запуске) и трекеров бюджета. · `SEPARATION_POLICY = GovernancePolicy(name="Connection Separation", ...)` (стр. 14)
