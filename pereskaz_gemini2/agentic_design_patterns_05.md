### Использование специализированных кастомных агентов · Создавайте кастомные агенты как полные, самоописываемые классы, расширяющие `BaseAgent`, для реализации нестандартного не-LLM поведения. · Пример: класс `TaskExecutor`, унаследованный от `BaseAgent`, выполняющий предопределенную задачу. · (стр. 122–123)

### Использование циклического агента (LoopAgent) · Настраивайте циклические воркфлоу с помощью `LoopAgent`, задавая `max_iterations` и комбинируя шаги обработки с агентами проверки условий (`ConditionChecker`). · Пример: `StatusPoller` с `max_iterations=10`, выполняющий шаги до выполнения условия завершения. · (стр. 123–124)

### Использование последовательного конвейера (SequentialAgent) · Стройте линейные воркфлоу, где вывод одного агента сохраняется в состоянии сессии и используется следующим агентом. · Пример: конвейер `MyPipeline`, состоящий из `Step1_Fetch` (сохраняет в `data`) и `Step2_Process` (анализирует `state['data']`). · (стр. 124–125)

### Параллельное выполнение агентов (ParallelAgent) · Запускайте несколько подзадач параллельно, сохраняя результаты каждого агента в разные ключи состояния сессии. · Пример: `data_gatherer`, запускающий `weather_fetcher` и `news_fetcher` параллельно. · (стр. 125–126)

### Парадигма «Агент как инструмент» (Agent as a Tool) · Оборачивайте специализированного агента в `AgentTool`, чтобы родительский LLM-агент мог вызывать его как обычный инструмент для выполнения подзадач. · Пример: `image_tool` на базе `image_generator_agent`, вызываемый родительским `artist_agent`. · (стр. 126–128)

### Выбор правильного сервиса сессий · Используйте подходящий `SessionService` в зависимости от задач: `InMemorySessionService` для локального тестирования, `DatabaseSessionService` (SQLite, PostgreSQL) для продакшена с персистентностью или `VertexAiSessionService` для масштабируемого облака. · Пример: `session_service = DatabaseSessionService(db_url="sqlite:///./my_agent_data.db")`. · (стр. 135–136)

### Префиксы областей видимости в состоянии сессии · Организуйте ключи в `session.state` с помощью префиксов: без префикса — для сессии, `user:` — для данных пользователя во всех сессиях, `app:` — общие для приложения, `temp:` — только для текущего шага без сохранения. · Пример: `state["user:login_count"] = 1`, `state["temp:validation_needed"] = True`. · (стр. 137, 139)

### Автоматическое сохранение ответа агента через output_key · Настройте параметр `output_key` у `LlmAgent`, чтобы ранер автоматически сохранял финальный текстовый ответ агента в состояние сессии. · Пример: `greeting_agent = LlmAgent(..., output_key="last_greeting")`. · (стр. 137–138)

### Инкапсуляция изменений состояния в инструменты · Обновляйте сложные или множественные ключи состояния через `ToolContext` внутри функций-инструментов, а не напрямую в коде. · Пример: функция `log_user_login(tool_context: ToolContext)` обновляет несколько полей через `tool_context.state`. · (стр. 139–141)

### Предупреждение об ошибке: прямой модификации словаря state · Избегайте прямого изменения словаря `session.state` после получения сессии, так как это обходит механизм событий, не сохраняется сервисом сессий, вызывает проблемы с консистентностью и пропускает обновление метаданных. Всегда используйте `output_key` или `EventActions.state_delta`. · Пример: прямая модификация `session.state["key"] = "value"` запрещена. · (стр. 141)

### Выбор сервиса долговременной памяти · Используйте `InMemoryMemoryService` для тестов или `VertexAiRagMemoryService` / `VertexAiMemoryBankService` для продакшена с семантическим поиском через RAG-корпус. · Пример: инициализация `VertexAiRagMemoryService` с параметрами `rag_corpus`, `similarity_top_k=5`, `vector_distance_threshold=0.7`. · (стр. 142–143, 149)

### Настройка буфера памяти в LangChain для чат-моделей · При использовании `ConversationBufferMemory` с чат-моделями обязательно устанавливайте параметр `return_messages=True`, чтобы получать структурированный список объектов сообщений вместо простой строки. · Пример: `memory = ConversationBufferMemory(memory_key="chat_history", return_messages=True)`. · (стр. 144–146)

### Процедурная память через рефлексию (Reflection) · Реализуйте адаптацию агента, используя узел рефлексии: заставляйте LLM анализировать историю разговора и текущие инструкции, чтобы сгенерировать и сохранить улучшенные правила в хранилище. · Пример: функция `update_instructions` сохраняет новые инструкции агента через `store.put()`. · (стр. 147)
