### Пошаговая методология разработки · Перед генерацией кода опишите проект на человеческом языке, продумайте архитектуру, создайте скелет («скелет проекта»), реализуйте функции последовательно и запустите приложение для проверки результата. · Пример: Этап 1 (Описание приложения для личных финансов), Этап 2 (Запрос архитектуры), Этап 3 (Скаффолдинг), Этап 4 (Реализация), Этап 5 (Интеграция и тестирование). · (стр. 80–81)

### Послойная генерация кода · Генерируйте код послойно (от фундамента к поверхности), чтобы каждый новый слой опирался на уже созданные типы и интерфейсы предыдущих слоев. · Пример: 1. Модели данных (Prisma schema) -> 2. Repository layer -> 3. Service layer -> 4. API endpoints -> 5. Фронтенд-компоненты -> 6. Тесты. · (стр. 89)

### Разработка через тестирование (TDD) · Сначала попросите ИИ написать только тесты на основе бизнес-правил, а затем попросите реализовать код, который проходит эти тесты. · Пример: Написание тестов для модуля расчёта скидок с оговоркой «ТОЛЬКО тесты, код пока не пиши», а после их генерации — запрос на написание реализации. · (стр. 90)

### Копирование стиля существующего кода · Попросите модель проанализировать готовый модуль в проекте, чтобы создать новый в точно такой же структуре и стиле. · Пример: «Посмотри, как реализован модуль src/modules/users/. Создай аналогичный модуль src/modules/products/ с такой же структурой и стилем кода». · (стр. 90)

### Прототип в продакшен · Создайте сначала простейший прототип без базы данных и сложных зависимостей (в памяти), а затем доработайте его до продакшен-версии. · Пример: Запрос на создание простейшего чата на WebSocket в памяти, а затем запрос на его доработку до продакшена (PostgreSQL, JWT, комнаты, типизация, тесты). · (стр. 90)

### Борьба с устаревшими API и deprecated-функциями · Явно указывайте версии используемых библиотек и технологий в промпте, чтобы избежать генерации устаревшего кода. · Пример: «Используй Next.js 14 App Router (НЕ Pages Router). Используй server actions (НЕ API routes для мутаций)». · (стр. 92)

### Принцип минимализма и YAGNI · Требуйте от ИИ минимальной реализации без лишних абстракций и добавления того, о чем вы не просили. · Пример: «Минимальная реализация. Никаких лишних абстракций. YAGNI – не добавляй то, что не просил». · (стр. 92)

### Борьба со стилистическим дрейфом · Используйте файл CLAUDE.md и ссылайтесь на существующий код, чтобы стиль не «дрейфовал» в длинном диалоге. · Пример: Ссылаться на существующий код при создании новых модулей. · (стр. 92)

### Явное перечисление граничных случаев (Edge Cases) · Явно перечисляйте потенциальные граничные случаи в запросе, чтобы ИИ реализовывал не только happy path. · Пример: «Обработай edge cases: – Пустой ввод – Очень длинная строка (10000+ символов) – Спецсимволы и emoji в имени – Конкурентные запросы к тому же ресурсу – Потеря соединения с БД». · (стр. 92)

### Цикл отладки с AI · Следуйте циклу из четырёх шагов: описание проблемы, формулировка гипотезы, проверка (эксперимент для подтверждения/опровержения) и исправление корневой причины. · Пример: Анализ stack trace с помощью ИИ, который выдвигает гипотезы и проверяет их диагностическими командами. · (стр. 105)

### Сбор диагностики и диагностические скрипты · Создайте специальный диагностический скрипт для сбора версий, статуса зависимостей, тестов, состояния БД и логов перед отправкой в issue. · Пример: Создание скрипта `scripts/diagnose.sh` для автоматического сбора метрик окружения и системы. · (стр. 114)
