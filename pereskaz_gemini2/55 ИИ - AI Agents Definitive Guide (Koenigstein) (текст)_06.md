### Pydantic для валидации · Определяйте точные схемы данных с помощью Pydantic на границах системы, чтобы ловить битый JSON, неверные типы (например, строку вместо числа) и отсутствующие поля до того, как они распространятся по агентам. · `UserData(BaseModel): user_id: int` и проверка входа через `UserData(**data)` вместо сырых словарей. · (стр. 6)

### OmegaConf для динамического управления политиками · Используйте иерархическую конфигурацию YAML через OmegaConf для изменения системных настроек и режимов «на лету» без пересборки кода. · `GOVERNANCE_CONFIG = """mode: "strict" ... """` и создание `cfg: DictConfig = OmegaConf.create(...)`. · (стр. 6)

### Закрепление состояния (Pinning and Hashing) · Замораживайте и хэшируйте конфигурацию политик и схемы на старте запуска, чтобы избежать дрейфа правил посреди выполнения и обеспечить аудируемость. · Вычисление хэша через `policy_hash = hash_policy(policy_dict)` и `schema_hash = sha256_text(...)` в начале работы. · (стр. 6)

### Обратная связь для повторных попыток (Semantic Feedback) · При ошибках валидации возвращайте агенту читаемое сообщение об ошибке (а не сырой стрейк-трейс), чтобы он мог выполнить целевой повторный запрос. · Логика перехвата `ValidationError as e` и возврат `last_error: e.errors()[0]["msg"]` для повтора. · (стр. 6)

### Чекпоинты для отказоустойчивости · Компилируйте граф с сохранением состояния (например, через `InMemorySaver`), чтобы при сбое или ошибке валидации возобновлять работу с последнего стабильного узла без перерасхода токенов на уже выполненные шаги. · `memory = InMemorySaver()`, `app = workflow.compile(checkpointer=memory)` с привязкой по `thread_id`. · (стр. 6)

### Instructor для исправления схем на этапе генерации · Используйте библиотеку Instructor для привязки валидации Pydantic прямо к процессу генерации модели, чтобы исправлять ошибки структуры (пропущенные ключи) на внутренней петле без сложного ветвления графа. · Создание клиента `instructor.from_provider(...)` и передача `response_model=ImagePrompt` вместе с `max_retries`. · (стр. 6)

### Разделение циклов исправления ошибок · Различайте внутреннюю петлю (Instructor для генерации и исправления схем на лету) и внешнюю петлю (Pydantic/LangGraph для системных политик и инфраструктурных сбоев). · Разделение retry-логики на генерационную (inner) и системную (outer). · (стр. 6)

### MCP для универсального интерфейса инструментов · Используйте Model Context Protocol (MCP) как стандартный протокол («USB-C для ИИ»), чтобы подключать агентов к базам данных, файлам или API через тонкую обертку без изменения основного кода. · Создание сервера через `FastMCP("FileManager")` и декоратор `@mcp.tool()`. · (стр. 6)

### Лучшие практики работы с MCP · Выбирайте правильный транспорт (`stdio` для локальной разработки, HTTP/Streamable HTTP для веб-серверов), используйте соединения на один вызов для безопасности параллелизма и обязательно применяйте Pydantic для типизированного ввода-вывода (Typed IO). · Конфигурация клиента `MultiServerMCPClient` с `transport: "stdio"`. · (стр. 6)

### Динамическое обнаружение инструментов · Позволяйте агентам динамически искать и подтягивать нужные интеграции через семантический поиск во время выполнения (например, через Composio), вместо жесткого зашивания инструментов в код. · Вызов `composio.tools.get(user_id=..., search=use_case)` для получения инструментов в формате OpenAI. · (стр. 6)

### Глубокие агенты и предварительное планирование · Внедряйте этап явного планирования и делегирования задач изолированным подсущностям (субагентам), чтобы избежать раздувания контекста (context bloat) промежуточными артефактами. · Использование фреймворка `deepagents`, где субагенты изолируют контекст и возвращают главному агенту только финальный результат. · (стр. 6)

### Исполнительные контракты (SKILL.md и AGENTS.md) · Описывайте границы возможностей, тон, стандарты качества и рабочие процессы в виде файлов-контрактов (`SKILL.md` и `AGENTS.md`), обеспечивая воспроизводимость поведения агентов. · Использование `SKILL.md` для границ компетенций и `AGENTS.md` для роли и стандартов качества. · (стр. 6)
