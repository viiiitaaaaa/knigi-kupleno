### Управление ошибками и их обработка · Оборачивать API-вызовы в блоки try-except для перехвата исключений и возврата понятных сообщений об ошибках (строкой вместо падения), чтобы агент мог продолжить работу. · Пример: Возврат строки `"Error: Search failed - {e}"` вместо падения программы при сбое поиска. · (стр. 79–80)

### Создание инструментальных средств · Автоматизировать преобразование Python-функций в схемы инструментов с помощью модуля inspect (извлечение имени, докстринга и сигнатуры параметров для JSON Schema). · Пример: Функция `function_to_input_schema(func)` с автоматическим маппингом типов (str -> string, int -> integer) и определением обязательных параметров (`required`). · (стр. 80–82)

### Запуск и тестирование агентов · Использовать цикл управления (while True), который отправляет вопрос агенту, выполняет запрошенные им инструменты, добавляет результат в контекст и крутится до тех пор, пока модель не вернет финальный ответ без вызова инструментов. · Пример: Функция `simple_agent_loop` с проверкой `if assistant_message.tool_calls` для выполнения инструментов и отправки их результатов обратно в LLM. · (стр. 83–85)

### Стандартизация инструментов (MCP) · Применять архитектуру Model Context Protocol (MCP) с разделением на хост (мозг/LLM), клиент (мост связи) и сервер (выполнение инструментов) для стандартизации обнаружения и вызова сторонних инструментов. · Пример: Подключение официального сервера Tavily через `npx` и запуск через MCP Inspector для автоматического получения списка доступных инструментов. · (стр. 87–90)

### Работа с MCP-клиентом · Использовать MCP Python SDK (`mcp`) для программного подключения к MCP-серверам через Stdio, инициализации сессии, получения списка инструментов и их вызова. · Пример: Использование `ClientSession` и `stdio_client` с параметрами `StdioServerParameters` для выполнения поиска через MCP. · (стр. 91–93)

### Разработка собственных MCP-серверов · Превращать обычные Python-функции в MCP-серверы с помощью библиотеки FastMCP и декоратора `@mcp.tool()`, автоматически генерирующего схему из сигнатуры и докстринга. · Пример: Создание файла `tavily_mcp_server.py` с декоратором `@mcp.tool()` над функцией поиска и запуском `mcp.run(transport='stdio')`. · (стр. 94–96)

### Управление состоянием агента (Контекст) · Консолидировать все данные выполнения (историю событий, счетчик шагов, идентификаторы, состояние) в едином контейнере `ExecutionContext` вместо использования разрозненных переменных. · Пример: Использование класса `ExecutionContext` для передачи единого объекта состояния во все методы агента и инструменты. · (стр. 102–104)

### Паттерн проектирования ReAct (Рассуждение и действие) · Реализовывать итеративный цикл решения задач, в котором агент поочередно рассуждает (внутренне через LLM), вызывает инструменты для получения данных, наблюдает результаты и повторяет процесс до получения финального ответа. · Пример: Агент последовательно запрашивает рекорд Кипчоге, расстояние до Луны и считает результат через калькулятор в цикле ReAct. · (стр. 100–102)
