### Планирование · Использование итеративного подхода с LLM для проектирования ассистента вместо создания всего в одном промпте (например, пошаговое создание инструкций для агента через диалог). · Задайте LLM первый промпт для базовой идеи эксперимента, второй — для перевода шагов в инструкции, и третий — для выбора подходящей персоналистичности. · (стр. 68–69)

### Контекст · Добавление в инструкции правил (RULES) и роли/персонажа для обеспечения согласованности ответов агента и задания тона общения (например, общение в стиле известного шеф-повара или статистика). · Задайте агенту роль известного статистика Нейта Сильвера или повара Джулии Чайлд и пропишите обязательные правила вывода. · (стр. 67, 69)

### Помощники · Подключение специализированных инструментов и навыков, таких как Code Interpreter для работы с файлами и кодом, а также кастомных действий (Custom Actions) через OpenAPI-спецификации. · Включите чекбокс Code Interpreter в панели конфигурации ассистента и добавьте OpenAPI-спецификацию внешнего сервиса. · (стр. 70, 77)

### Безопасность · Осторожная публикация ассистентов с кастомными действиями или туннелями (например, через ngrok), чтобы случайно не выставить наружу приватную информацию или платные сервисы. · Не экспонируйте сервисы, которые взимают плату или дают доступ к личным данным, если планируете публичную публикацию агента. · (стр. 79)

### Экономия лимита · Добавление в инструкции правил, предупреждающих пользователей о лимитах ресурсоемких функций (генерация изображений, частый запуск кода, анализ больших файлов), чтобы избежать блокировки аккаунтов. · Добавьте правило: «При генерации изображений убедитесь, что пользователь знает: создание множества картинок подряд может временно заблокировать его аккаунт». · (стр. 86)
