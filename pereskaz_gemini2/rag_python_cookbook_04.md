### Рекурсивное разбиение текста · Используйте рекурсивный сплиттер для документов с четкой структурой абзацев, общих RAG-систем или когда формат неизвестен; он делит текст по приоритетам (абзацы, переносы строк, знаки препинания, пробелы), сохраняя смысловую связность · Разделение текста с помощью `RecursiveCharacterTextSplitter` с размером чанка 200 символов · (стр. 116–118)

### Ошибки при рекурсивном разбиении · Не используйте рекурсивное разбиение для размеченных документов (Markdown, HTML) и доменного контента, где важны смысловые границы · Риск смешать несвязанные темы (например, политику и спорт) с фиксированным размером чанков · (стр. 118)

### Документо-зависимое разбиение · Применяйте сплиттеры, понимающие синтаксис разметки (Markdown, HTML, код, LaTeX), чтобы сохранять логическую структуру, иерархию заголовоков и код без разрывов · Выбор сплиттера по расширению файла (`.py`, `.tex`, `.md` с заголовками `#`) · (стр. 119–121)

### Семантическое разбиение · Используйте семантическое разбиение на основе эмбеддингов предложений для неструктурированных текстов (транскрипты, чаты), разделяя их по смысловым порогам (например, 90-й перцентиль падения сходства) · Использование `SemanticChunker` из `langchain-experimental` · (стр. 122–124)

### Ограничения семантического разбиения · Избегайте семантического разбиения на больших корпусах документов из-за высоких затрат на эмбеддинги и в реальном времени из-за задержек · Двойное создание эмбеддингов для каждого куска увеличивает расходы · (стр. 125)

### Агентное разбиение текста · Превращайте длинный и сложный текст в атомарные независимые утверждения (пропозиции) с помощью LLM, удаляя местоимения и разрешая контекст · Паттерн `wfh/proposal-indexing` с вызовом структуры через `with_structured_output` · (стр. 125–129)

### Избегание агентного разбиения · Не используйте агентное разбиение для хорошо написанной документации, больших корпусов и конвейеров реального времени · Метод требует 2–3 вызова LLM на чанk, что в 10–20 раз дороже семантического · (стр. 129)

### Выбор метрики расстояния · Используйте косинусное сходство как стандарт для RAG-поиска, так как оно оценивает направление векторов и устойчиво к разнице в длине текста · Вычисление через скалярное произведение и норму векторов в NumPy · (стр. 127–130)

### Выбор модели эмбеддингов · Начинайте с проверенных моделей (`text-embedding-3-small` для облака или `all-MiniLM-L6-v2` для локального запуска), тестируйте на 50–100 реальных запросах и проверяйте задержку (<100 мс) и стоимость · Таблица сравнения моделей и бенчмарки MTEB · (стр. 131–132)

### Мультимодальный поиск с CLIP · Используйте модель CLIP для создания общих эмбеддингов картинок и текста, чтобы искать изображения по текстовым запросам или классифицировать их · Загрузка `CLIPModel` и `CLIPProcessor` из Hugging Face · (стр. 133–136)

### Классификация текста эмбеддингами · Обучайте классификатор (например, Random Forest) на эмбеддингах текстовых чанков для маршрутизации вопросов пользователей по темам перед поиском в векторной базе · Загрузка PDF-файлов, разбиение и генерация эмбеддингов для разметки категорий · (стр. 136–138)
