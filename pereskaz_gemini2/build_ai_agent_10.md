### Использование облачной песочницы · Создайте изолированную среду с помощью облачных сервисов (например, E2B) для безопасного выполнения кода, сохранения состояния сессии и легкого восстановления после сбоев. · Применение E2B для создания изолированного Python-окружения через `Sandbox.create()` с последующим выполнением кода. · (стр. 244)

### Управление жизненным циклом песочницы · Автоматически инициализируйте песочницу в начале выполнения задачи и уничтожайте её после завершения с помощью конструкции `try-finally`, чтобы избежать утечки ресурсов. · Инициализация `context.code_env = Sandbox.create(timeout=300)` в методе `run()` с последующим вызовом `context.code_env.kill()` в блоке `finally`. · (стр. 247-248)

### Настройка таймаута и переменных окружения · Передавайте чувствительные данные (ключи API) через словарь параметров `envs`, а продолжительность работы песочницы регулируйте параметром `timeout` и методом `set_timeout()`. · Передача `TAVILY_API_KEY` в параметре `envs` и установка таймаута песочницы на 300 секунд при создании. · (стр. 245)

### Обработка ошибок выполнения кода · Перехватывайте информацию об ошибках через свойство `execution.error` и передавайте её языковой модели для генерации исправленного кода (цикл наблюдения и повторной попытки по паттерну ReAct). · Проверка `if execution.error:` для получения имени ошибки (`error.name`) и сообщения (`error.value`). · (стр. 246)

### Автоматическая регистрация инструментов выполнения кода · Настройте фреймворк так, чтобы при включении режима песочницы (`code_execution="e2b"`) инструмент `execute_python` добавлялся автоматически без явной регистрации разработчиком. · Проверка условия `if self.code_execution == "e2b":` в методе `_setup_tools()` для добавления `execute_python`. · (стр. 247)

### Портирование пользовательских функций в песочницу (sandbox_executable) · Помечайте чистые функции флагом `sandbox_executable=True` и извлекайте их исходный код через `inspect.getsource()`, удаляя декоратор `@tool`, чтобы запускать их прямо внутри песочницы. · Создание инструмента `get_wikipedia_revisions` с флагом `sandbox_executable=True` для выполнения циклов внутри песочницы вместо множества вызовов LLM. · (стр. 251-253)

### Настройка рабочего пространства (Workspace) с CLI и файловой системой · Предоставьте агенту полный набор инструментов для работы с терминалом и файлами (`bash_tool`, `upload_file`), чтобы он мог выполнять bash-команды, устанавливать пакеты через pip и загружать локальные файлы. · Передача файлов в песочницу с помощью `upload_file` и выполнение команд через `bash_tool` (например, `sandbox.commands.run("ls -la")`). · (стр. 258-260)

### Прогрессивное раскрытие информации об инструментах (Agent Skills) · Организуйте навыки в папки со структурой `SKILL.md` (содержащим YAML front matter с именем и описанием), помещая в промпт только краткий список навыков, а подробную документацию и скрипты считывая только по мере необходимости. · Указание только имен и описаний навыков в системном промпте и вызов `cat /home/user/skills/<skill-name>/SKILL.md` через bash-инструмент при реальной потребности. · (стр. 262-267)

### Трехуровневая иерархическая структура инструментов · Разделите инструменты на три уровня для экономии контекста: базовые инструменты в промпте (ядро), устанавливаемые навыки со списками в промпте и полной документацией на файловой системе, а также код, генерируемый моделью «на лету».  · Использование `execute_python`, `bash_tool` и `upload_file` как неизменяемого первого уровня для доступа к файлам и генерации кода третьего уровня. · (стр. 268-269)
