### Экономия лимита · Использовать интеллектуальную выборку вместо проверки 100% трафика (например, оценивать только 5–10% запросов), чтобы получить статистически значимую оценку здоровья системы без лишних затрат. · При онлайн-оценке (online evaluation) рекомендуется «не нужно оценивать 100% вашего трафика, вместо этого можно использовать интеллектуальную выборку всего 5–10% взаимодействий» (стр. 213).

### Экономия лимита · Внедрить бюджет на оценку параллельно с производственным бюджетом и применять безэталонные метрики (reference-free) или выборочный контроль для дорогих проверок. · «Чтобы сохранять контроль над расходами, оценка не должна быть сплошным процессом; скорее, вы можете внедрить бюджет на оценку параллельно с производственным бюджетом» (стр. 213).

### Контекст · Использовать асинхронный конвейер оценки (асинхронные фоновые воркеры), чтобы не увеличивать задержку для пользователя при проверке ответов. · Вместо блокирующих оценок «внедрите асинхронный конвейер оценки, где система RAG доставляет ответ немедленно, а фоновый воркер регистрирует запросы для оценки "вне полосы" (out-of-band)» (стр. 212–213).
