### Авторизация через браузер · Запустить `claude` в терминале и подтвердить доступ на странице в браузере при первом запуске (способ удобен для индивидуального использования и сам обновляет токен). · `claude` (стр. 21)

### API-ключ через переменную окружения · Задать переменную `ANTHROPIC_API_KEY` в окружении, добавив её в конфигурационный файл оболочки (например, `~/.bashrc`) или используя менеджер секретов. · `export ANTHROPIC_API_KEY="sk-ant-…"` (стр. 21)

### Настройка через AWS Bedrock · Указать переменные окружения для работы с Claude через инфраструктуру Amazon Bedrock, обеспечивая единый биллинг и корпоративный compliance. · `export CLAUDE_CODE_USE_BEDROCK=1` (стр. 21-22)

### Инструкции в файле CLAUDE.md · Разместить в корне проекта файл `CLAUDE.md` с описанием архитектуры, соглашений по коду и команд, чтобы агент постоянно следовал этим правилам. · `## Соглашения по коду: Используй type hints везде...` (стр. 23)

### Проектные настройки в settings.json · Настроить разрешения команд и параметры в файле `.claude/settings.json` для управления доступом агента к инструментам. · `{"permissions": {"allow": ["Read", "Write", ...]}}` (стр. 24)

### Однократный режим (print mode) · Использовать флаг `--print` для обработки агентом одиночного запроса с последующим завершением работы (подходит для автоматизации и скриптов). · `claude –print "Объясни, что делает файл main.py"` (стр. 33-34)

### Pipe-режим для конвейеров · Передавать данные в Claude Code через стандартный ввод (pipe) для интеграции в Unix-конвейеры. · `git diff | claude –print "Проведи code review этих изменений"` (стр. 34)

### Итеративный диалог вместо монопромптов · Делать задачу не одним огромным запросом, а вести итеративный диалог: ставить задачу, проверять промежуточный результат и корректировать направление. · `> Добавь аутентификацию через JWT в наш API` (стр. 12, 34-35)

### Подтверждение опасных операций · Отвечать на запросы агента (`Y`/`n`/`always`) при попытке выполнения потенциально опасных команд или изменения файлов. · `Allow? [Y/n/always]` (стр. 11-12, 35)

### Сброс контекста через /clear · Использовать команду `/clear` при переключении на другую задачу или если агент запутался, чтобы полностью сбросить историю диалога. · `/clear` (стр. 36)

### Сжатие контекста через /compact · Вызывать команду `/compact` (или указывать фокус сжатия) для уменьшения объёма токенов и экономии средств после завершения крупного блока работы. · `/compact Сфокусируйся на работе с базой данных` (стр. 31, 36-37)

### Мониторинг сессии и стоимости · Использовать слэш-команды `/status` и `/cost` для отслеживания расхода токенов, времени и денежных затрат на текущую сессию. · `/status` и `/cost` (стр. 37)

### Выборочное чтение файлов для экономии контекста · Избегать загрузки всей кодовой базы в память; явно указывать агенту конкретные файлы или папки для анализа. · `> Проанализируй файлы в каталоге src/auth/` (стр. 14, 38, 42)
