### Иерархический выбор навыков (Hierarchical Skill Selection) · Организуйте навыки в группы с описаниями и выполняйте двухуровневый поиск (сначала по группе, затем внутри неё), чтобы повысить точность выбора навыков при большом их числе. · Текст предлагает организовывать навыки в группы (например, «Computation», «Automation», «Communication»), описывать каждую группу и выполнять поиск сначала по группе, а затем среди входящих в неё навыков. · (стр. 6)

### Использование базового парсера для параметров · Применяйте базовый парсер для проверки входных данных на соответствие типам и давайте указание языковой модели исправить паттерн при сбое проверки. · Рекомендуется использовать базовый парсер для валидации того, что введённые параметры соответствуют базовым критериям типов данных. · (стр. 7)

### Ограничение длины цепочек навыков · Задавайте максимальную длину для цепочек навыков (chains), так как ошибки имеют свойство накапливаться по мере прохождения длинной цепи. · Текст рекомендует устанавливать максимальную длину для цепочки навыков, поскольку ошибки могут суммироваться вдоль всей цепочки. · (стр. 8)

### Тюнинг параметров деревьев · Настраивайте максимальное число навыков на одно выполнение и максимальную глубину дерева при использовании древовидных топологий. · Для древовидной структуры ключевыми параметрами для настройки под конкретный сценарий являются максимальное количество навыков за выполнение и максимальная глубина дерева. · (стр. 8)

### Принцип постепенного усложнения топологий · Начинайте с простых подходов (например, с одиночного выполнения навыков или линейных цепочек) и добавляйте сложность только тогда, когда это необходимо для конкретного кейса. · В тексте отмечается принцип: «начинайте с простого и добавляйте сложность только для решения конкретных задач в вашем сценарии». · (стр. 8, 9)

### Ограничения итеративного планирования · Учитывайте, что при чисто итеративном («жадном») подходе без предварительного планирования агенты могут застревать в циклах и не продвигаться к цели. · Текст предупреждает, что просто выполняя одно действие за другим в жадном ключе, агенты иногда попадают в циклы и не могут завершить задачу. · (стр. 9)

### Использование примеров для планирования (In-Context Learning) · Выделите ключевые высокоприоритетные сценарии, создайте для них чёткие примеры планов и сохраните их в базу данных для few-shot поиска похожих примеров. · Разработчики могут вручную проектировать планы для ключевых сценариев и через эмбеддинги индексировать их в few-shot базе данных для подсказки будущим планам. · (стр. 9)

### Режим ReAct для адаптации плана · Применяйте фреймворк Reason-Act (ReAct), в котором агент чередует шаги рассуждения (reasoning) и действия (acting) для проверки достаточности результатов и адаптации плана. · Агент чередует шаги рассуждения о том, что нужно сделать, и шаги выполнения действий, проверяя, достаточны ли результаты для решения задачи. · (стр. 9)

### Оптимизация контекстного окна (Context Window) · Предоставляйте модели всю необходимую для задачи информацию, но не больше, размещая наиболее релевантный контекст ближе к концу промпта. · Подчёркивается необходимость эффективно использовать контекстное окно: выделять наиболее релевантный контекст и размещать его ближе к концу промпта, чтобы повысить вероятность его использования моделью. · (стр. 11)

### Скользящее окно контекста (Rolling Context Window) · Используйте rolling context window (FIFO), где старые взаимодействия вытесняются новыми по мере заполнения лимита токенов, как простой метод памяти. · Полная история передается в окно, а при его заполнении самые старые части удаляются и заменяются свежими по принципу first-in, first-out. · (стр. 11)

### Гибридная память на основе ключевых слов и скользящего окна · Комбинируйте поиск по ключевым словам и rolling context window, выделяя часть лимита под найденные по ключевым словам прошлые взаимодействия, а остаток заполняя свежим контекстом. · Текст предлагает гибридный подход, разделяющий контекстное окно между извлечением по ключевым словам и последними интеракциями. · (стр. 12)
