### Планирование и выбор моделей · Выбирайте наименьшую модель, которая решает задачу (используйте ультраэффективные/эффективные модели для 80% простых запросов, а флагманские/рассуждающие — только для сложных случаев), и разбивайте сложные рабочие процессы на мелкие шаги. · Для стандартного чата с контекстом из 3–4 чанков используйте быстрые эффективные модели (например, Gemini Flash или GPT-5 mini), так как более крупные модели не оправдывают возросшую задержку. · (стр. 27, 28, 43)

### Память и контекст · Контролируйте размер контекста и токенов: балансируйте гибкость и жесткость промптов (слишком свободные промпты вызывают галлюцинации, слишком жесткие — ломают обработку краевых случаев), учитывайте стоимость токенов ввода и вывода. · Промпт для закупки товаров содержит структурированные секции [Role], [Instruction], [Context], [User Question], [Output Requirements] с ограничением до 120 слов. · (стр. 24, 25, 27)

### Помощники и интеграция с API · Изолируйте зависимости с помощью виртуальных окружений и файлов `requirements_chXX.txt` для каждой главы, чтобы избежать конфликтов версий. · Используйте единый SDK OpenAI с подменой `base_url` для работы с Google Gemini, локальным Ollama и OpenAI, а для Anthropic Claude используйте собственный SDK. · (стр. 36, 33, 38, 50)

### Проверка результата и структуры · Применяйте структурированные выходы через библиотеки валидации (например, Pydantic с `BaseModel`) для принудительного соблюдения схемы JSON и типов данных на этапе инференса. · Разбор счета (Invoice) с вложенными LineItem через `client.responses.parse(..., response_format=Invoice)` для автоматической валидации типов перед передачей в БД. · (стр. 41, 42)

### Безопасность и локальные данные · Запускайте локальные открытые модели (Llama, Mistral, Qwen) через Ollama (`http://localhost:11434/v1`), когда данные слишком чувствительны для отправки во внешние API или при больших объемах вызовов. · Запуск модели `qwen3:4b` локально через тот же OpenAI SDK с `base_url="http://localhost:11434/v1"` и ключом `api_key="ollama"`. · (стр. 37, 38, 40)

### Работа с данными (загрузка) · Превращайте табличные данные в текст (строка в описание) для простых поисковых запросов или используйте подход text-to-SQL для аналитики по крупным базам данных. · Превращение строк датасета доходов в текстовое описание через функцию `create_text_description_of_row` для последующего векторного поиска. · (стр. 52, 53, 56)
