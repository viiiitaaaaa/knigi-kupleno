### Обновление файла `ipp.txt` · Учитывайте интервал обновления файла пула IP-адресов или отключайте его · При использовании параметра `duplicate-cn` опция `ifconfig-pool-persist` становится бесполезной, так как клиенту выдается несколько IP-адресов. · (стр. 123)

### Топология `net30` в `ipp.txt` · Учитывайте специфичный формат файла для топологии `net30`, где для каждого клиента записывается сеть /30 из четырёх адресов, начиная с адреса сети · Пример: `client1,10.200.0.4`. · (стр. 123)

### Использование SOCKS-прокси · Настраивайте подключение через SOCKS-прокси (например, с помощью SSH) при блокировке UDP-трафика фаерволами · `[socks-proxy]$ ssh -g -D 1080 remote-host.example.com`. · (стр. 123)

### Двойное шифрование при проксировании · Помните о снижении производительности и избыточности: туннелирование VPN (уже зашифрованного) поверх SSH-туннеля (тоже зашифрованного) приводит к двойному шифрованию. · (стр. 123)

### Подключение через HTTP-прокси · Настраивайте клиент для работы через HTTP-прокси с помощью директивы `http-proxy` и проверьте, что прокси поддерживает метод `CONNECT` · `http-proxy http-proxy-host 80` и `verb 4`. · (стр. 124)

### Опции настройки HTTP-прокси · Используйте дополнительные параметры для тонкой настройки HTTP-прокси: `http-proxy-timeout (n)`, `http-proxy-option AGENT (string)` и `http-proxy-option VERSION 1.1`. · (стр. 124)

### Обход фаерволов и DPI · Учитывайте, что OpenVPN не пытается скрыться от фаерволов; современные системы с глубоким анализом пакетов (DPI) легко детектируют и блокируют OpenVPN-трафик. · (стр. 124)

### HTTP-прокси с аутентификацией · Настраивайте аутентификацию на прокси-сервере и передавайте учетные данные клиенту через файл паролей · `http-proxy proxy.example.com 80 /etc/openvpn/cookbook/proxypass`. · (стр. 125)

### Ограничения NTLM-авторизации · При использовании NTLM-прокси учитывайте ограничения реализации в OpenVPN и используйте флаги `stdin ntlm` или `stdin ntlm2` для запроса учетных данных в командной строке. · (стр. 125)

### Настройка IP-less туннелей (`ifconfig-noexec`) · Создавайте туннели без назначения IP-адресов интерфейсу с помощью `ifconfig-noexec` и `route-noexec` для повышения безопасности и изоляции шлюзов · В скрипте `up` назначайте интерфейсу адрес `0.0.0.0` и используйте `route-up` для применения маршрутов. · (стр. 126)
