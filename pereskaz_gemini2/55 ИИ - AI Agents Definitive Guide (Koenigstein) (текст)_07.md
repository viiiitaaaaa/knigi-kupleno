### Планирование · Всегда планировать действия агента заранее (план перед действием) и разделять фазы обнаружения (discovery) и выполнения (execution), чтобы предотвратить несанкционированное лавинообразное расширение возможностей (capability escalation). · Агенты должны использовать паттерн «план перед действием» и изолировать фазы (например, разделение discovery и execution через политики). · (стр. 2)

### Проверка результата · Валидировать любые пути к файлам перед записью для предотвращения атак обхода каталога (path traversal), используя единый разрешенный корневой каталог и канонизацию путей. · Функция `work_path()` нормализует путь, проверяет его через `resolve()` и вызывает `RuntimeError`, если он ведет за пределы `WORK_DIR`. · (стр. 6)

### Безопасность · Использовать принцип «запрещено по умолчанию» (default-deny) для инструментов, бюджетирование вызовов, ограничения по времени, а также запускать генерируемый моделью код в песочницах (например, Monty с deny-by-default или контейнерах Docker/микроВМ), а не напрямую на хосте. · Внедрение центральной точки принудительного исполнения (`governed_call`), проверка аргументов, использование изолированных интерпретаторов для программного вызова инструментов (code mode). · (стр. 3, 5, 8, 9)

### Память и контекст · Использовать программный вызов инструментов (code mode / programmatic tool calling), чтобы модель писала короткие программы-оркестраторы с циклами и условиями, выполняя их в интерпретаторе без возврата каждого промежуточного результата в контекст модели, что экономит токены и снижает задержку. · Использование интерпретатора Monty для выполнения цепочки вызовов инструментов внутри песочницы с передачей результатов только в конце. · (стр. 8)

### Экономия лимита · Сокращать количество обращений к модели (round trips) за счет выполнения множества вызовов инструментов внутри одной программы в песочнице (code mode), избегая раздувания контекста промежуточными данными. · Выполнение 16 вызовов инструментов за 0 раунд-трипов модели с помощью скрипта на Monty. · (стр. 10)

### Помощники · Использовать структурированные спецификации для задач кодинга (Product Requirement Prompts — PRP), объединяющие цель PRD, точные пути к файлам, версии библиотек, паттерны кода и исполняемые шаги валидации. · PRP объединяет намерения, точные пути к файлам и тесты для верификации агентом своей работы с первой попытки. · (стр. 3)
