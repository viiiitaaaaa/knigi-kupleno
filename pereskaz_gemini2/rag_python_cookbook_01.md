### Выбор IDE и AI-помощника · Использовать правильные инструменты для разработки и работы с кодом · Для быстрого прототипирования подойдут VS Code (с расширениями Python/Jupyter) или PyCharm, для отладки крупных кодовых баз — Claude Code (командная строка), а для автодополнения кода в реальном времени — GitHub Copilot или Cursor · (стр. 6)

### Использование Jupyter Notebooks · Применять блокноты для экспериментов, но выносить рабочий код в модули · Писать код в Jupyter (`.ipynb`) для интерактивного тестирования и визуализации в памяти, но переносить переиспользуемую логику в отдельные `.py` файлы и подключать автозагрузку (`%autoreload 2`), избегая блокнотов для продакшена и командной работы из-за скрытых зависимостей и формата JSON · (стр. 8)

### Безопасное хранение секретов и API-ключей · Использовать локальные `.env` файлы и облачные хранилища секретов · Не хардкодить ключи в коде и не коммитить их в Git, добавив `.env` в `.gitignore`; для локальной разработки использовать `python-dotenv` и `os.getenv()`, а в продакшене — AWS Secrets Manager или Azure Key Vault · (стр. 10)

### Раздельная отладка RAG-пайплайна · Проверять поисковик (ретривер) до отладки генерации · Если ответы модели нерелевантные, сначала проверьте качество поиска документов (возвращает ли ретривер нужные чанки), а не меняйте промпты или параметры LLM · (стр. 17)

### Выбор библиотек и фреймворков · Избегать избыточных зависимостей на старте · Для простых RAG-систем использовать прямые вызовы API (OpenAI, Chroma) вместо тяжелых оркестраторов вроде LangChain или LlamaIndex, чтобы уменьшить дерево зависимостей и конфликты версий · (стр. 18)
