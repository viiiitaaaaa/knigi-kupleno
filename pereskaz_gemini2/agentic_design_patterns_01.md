### Цепочки промптов · Разделяйте сложные задачи на последовательность простых шагов, где вывод одного промпта передается как ввод в следующий, чтобы снизить когнитивную нагрузку на модель и избежать игнорирования инструкций. · Пример из текста: разбить задачу анализа рынка на три шага: 1) суммаризация текста, 2) выявление трендов и данных по сводке, 3) составление письма по результатам второго шага. · (стр. 24)

### Структурированный вывод для передачи данных · Используйте строгие форматы вроде JSON или XML для передачи данных между шагами, чтобы исключить двусмысленность и ошибки парсинга при передаче результатов дальше по цепочке. · Пример из текста: вывод этапа идентификации трендов упаковывается в JSON-объект с полями `trends`, `trend_name` и `supporting_data`. · (стр. 24–25)

### Назначение ролей на каждом этапе · Задавайте модели конкретную профессиональную роль для каждого отдельного шага в пайплайне, чтобы повысить точность решения узкой подзадачи. · Пример из текста: назначение ролей для цепочки: первый промпт — «Рыночный аналитик», второй — «Торговый аналитик», третий — «Эксперт по написанию документации». · (стр. 24)

### Инженерное проектирование контекста (Context Engineering) · Стратегически отбирайте, упаковывайте и очищайте только самые важные данные (удаляя лишний мусор и длинные исходные тексты) перед отправкой их в следующий шаг или инструмент, предотвращая перегрузку контекста. · Пример из текста: из длинного письма с подтверждением рейса извлекаются только номера, даты и локации для последующего вызова календаря и погоды. · (стр. 17)
